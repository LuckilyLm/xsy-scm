# XSY-SCM 前端 UI 优化规划

> 文档路径：`docs/frontend-ui-optimization-plan.md`  
> 基线仓库：`LuckilyLm/xsy-scm`  
> 基线提交：`abfb2bc688156d76d0c31c9221059636b981bb57`（`feat(ui): streamline product archive list columns`）  
> 前序 UI 提交：`1e7cdebe6f8387bb6b8695e4b19ac37f68da0d83`（`feat(ui): polish product form drawer and sku editor`）  
> 编写日期：2026-10-05  
> 适用范围：`xsy-scm-web`，重点覆盖 `src/views/business/scm/**`。SmartAdmin 系统/支撑页面只做全局一致性治理，不在本轮重做业务信息架构。

---

## 1. 背景

当前 XSY-SCM 已完成较多业务能力建设，商品、客户、供应商、采购、销售订单、库存、配送、分拣、价格、营销、财务、报表等页面已经形成完整业务链路。

目前前端主要问题已经不是“缺页面”，而是：

1. 不同模块的信息密度、间距、Drawer 宽度、按钮层级不统一。
2. 很多列表仍按照“后端有什么字段就展示什么”的方式组织，编码、创建时间、更新时间等低频信息长期占据首屏。
3. 多个列表的“操作”列过宽，部分达到 260～420px，严重挤压真正重要的业务字段。
4. 金额、数量、比例、天数等业务字段仍有使用普通文本框的情况。
5. 状态展示方式不一致：Tag、文本、disabled Input、Switch 混用。
6. Drawer / Modal 中大量表单仍使用连续长表单或 Divider 分隔，缺少明确业务分区。
7. 商品模块已经开始出现 `form-section`、`btn-secondary`、`btn-tertiary`、`btn-icon-danger` 等视觉模式，但目前仍散落在具体组件中，继续复制会形成新的样式债务。
8. 日志类、流水类页面和普通业务列表缺少差异化规则，容易错误地“一刀切”隐藏时间、编号。
9. 主数据页、业务单据页、操作工作台、财务流水页、报表页实际上需要不同的信息架构，但当前风格区分不足。

本规划的目标是把商品模块已经验证过的方向扩展为 **XSY-SCM 统一业务后台 UI 规范**，并按模块分阶段落地。

---

# 2. 总目标

最终界面应满足以下原则：

> **信息密度高，但不乱；功能很多，但一眼能看出重点。**

统一做到：

- 列表少而准。
- 表单有业务分区。
- 详情有层级。
- 状态有统一视觉。
- 金额、数量、比例、天数具有明确的输入和展示语义。
- 操作有主次。
- 危险操作被弱化并有二次确认。
- 技术字段下沉到详情。
- 日志、流水、财务类页面保留必要时间和业务编号。
- 全系统间距、按钮、Drawer、表格对齐方式一致。
- 不为了“美观”牺牲 SCM 的操作效率。

---

# 3. 非目标

本轮 UI 优化默认 **不做**：

- 不改后端接口。
- 不改 DTO / VO / Entity 字段结构。
- 不改数据库。
- 不删除现有查询能力。
- 不删除导出字段。
- 不修改权限码。
- 不改变订单、采购、库存、财务状态机。
- 不引入新的 UI 框架。
- 不把 SmartAdmin / Ant Design Vue 换掉。
- 不为了视觉统一强行把所有 Drawer 做成同一宽度。
- 不把所有操作都包装成新的业务组件。
- 不在 UI 优化任务中顺带重构无关业务代码。

> 执行中遇到的**后端字段不足**统一登记在[前端 UI 优化的后端字段缺口盘点](frontend-ui-backend-gap-inventory.md)，
> 按 §33「后端字段重构不得与其他内容同提交」单独开单、单独提交；补齐前前端只做「不渲染该段 / 不臆造数值」。

# 4. 优先级定义

## P0：立即统一

满足任一条件即为 P0：

- 影响所有页面的一致性。
- 当前页面明显影响操作效率。
- 操作列严重挤压业务信息。
- 表单输入控件与业务语义明显不匹配。
- 已经在商品页形成新规范，若不马上抽取会产生大量重复 CSS。

重点：

- SCM UI Foundation。
- 商品收尾。
- 客户。
- 供应商。
- 采购订单。
- 销售订单。
- 库存余额。

## P1：第二批

- 库存单据。
- 价格中心。
- 营销。
- 财务。
- 配送。
- 分拣。
- 商品图片中心、辅助资料等专业页面。

## P2：统一收尾

- 报表。
- 打印。
- 大屏。
- 系统/支撑/SmartAdmin 基础页的视觉一致性。
- 非核心配置页的细节统一。

# 5. XSY-SCM UI Foundation

## 5.1 样式组织

优先在现有：

```text
xsy-scm-web/src/theme/
├── index.less
├── smart-admin.less
├── color.ts
└── custom-variables.ts
```

基础上增加 SCM 业务层样式。

推荐：

```text
xsy-scm-web/src/theme/scm/
├── index.less
├── form.less
├── table.less
├── action.less
├── status.less
└── responsive.less
```

由 `src/theme/index.less` 统一引入。

不要继续在每个 Drawer 里重复：

- `.btn-secondary`
- `.btn-tertiary`
- `.btn-icon-danger`
- section card 基础样式
- table action 居中样式
- amount / quantity 基础格式

## 5.2 不要过度组件化

以下优先使用统一 CSS / class，而不是组件：

- Card 边框、圆角、padding。
- 表格操作列居中。
- 次级按钮颜色。
- 危险图标按钮颜色。
- 表单行距。
- 金额 tabular number。
- 通用 flex gap。

只有具备行为或复杂展示逻辑时才组件化，例如：

- `ScmStatusTag`
- `ScmActionMore`
- `ScmMoneyText`
- `ScmQuantityText`
- `ScmBusinessIdText`
- 复杂 Tag Picker

避免出现大量纯包装组件。

# 6. 全局视觉规范

## 6.1 页面结构

普通业务列表统一为：

```text
查询区
────────────────────────
主操作 / 批量操作                       表格设置
────────────────────────
数据表格
────────────────────────
分页
```

要求：

- 查询区和表格区不混在一起。
- 首屏主要展示“查、看、操作”。
- 高级筛选默认折叠。
- 批量按钮只有勾选后才强调可用状态。

## 6.2 Drawer 宽度分级

### S：简单 Drawer

宽度：

```text
560 ~ 640px
```

适用：

- 协议价。
- 客户类型。
- 简单字典。
- 简单配送线路配置。

### M：中型 Drawer

宽度：

```text
720 ~ 820px
```

适用：

- 供应商。
- 仓库。
- 司机/车辆。
- 简单库存业务表单。

### L：复杂 Drawer

宽度：

```text
900 ~ 960px
```

适用：

- 商品。
- 客户。
- 采购单。
- 销售订单。
- 有多行明细的复杂业务单据。

统一响应式：

```text
max-width: 96vw
```

移动端自动单列。

## 6.3 Drawer 内容分区

复杂表单不再仅依赖 `a-divider`。

统一使用轻量 Section：

```text
┌ 基础信息 ───────────────────────┐
│ ...                             │
└─────────────────────────────────┘

┌ 业务设置 ───────────────────────┐
│ ...                             │
└─────────────────────────────────┘
```

建议：

- `border: 1px solid #f0f0f0`
- `border-radius: 8px`
- `padding: 20px`
- `margin-bottom: 20px`
- 不使用明显阴影。
- 标题 15～16px / 600。
- 辅助说明 12～13px，secondary color。

## 6.4 表单间距

桌面端：

- Card padding：20px。
- Section gap：20px。
- Form item：16～20px。
- Label 到输入框沿用 Ant Design 默认节奏。
- 两列 `gutter`：16～20px。
- 不允许上下两个 label/input 贴在一起。

## 6.5 按钮层级

### Primary

用于：

- 新增。
- 保存。
- 确认收货。
- 提交关键业务动作。

表现：

- 主题绿色实心。

### Secondary

用于：

- 上传。
- 新增明细。
- 新增商品规格。
- 导入。

表现：

- 浅主题色背景。
- 主题色文字。
- 浅主题色边框。
- 允许极轻阴影：`0 1px 2px rgba(0,0,0,.04)`。

### Tertiary

用于：

- 编辑。
- 设为主图。
- 普通辅助操作。

表现：

- link 或浅灰背景小按钮。
- 不抢主操作视觉。

### Danger

用于：

- 删除。
- 作废。
- 不可逆取消。

表现：

- 红色。
- 列表中优先放到“更多”。
- 图标操作优先使用浅红底垃圾桶按钮。
- 必须二次确认。

# 7. 列表字段展示原则

不是所有“编码”和“时间”都应该隐藏。

## 7.1 默认隐藏的技术/低频信息

普通主数据列表默认隐藏：

- 商品编码。
- SKU 编码。
- 客户编码。
- 供应商编码。
- 创建时间。
- 更新时间。
- 助记码。
- 内部版本号。
- 审计字段。

但仍保留：

- 搜索。
- 高级筛选。
- 详情。
- 编辑。
- 导出。

## 7.2 必须保留的业务单据编号

以下属于业务识别信息，不应隐藏：

- 订单号。
- 采购单号。
- 收货单号。
- 退货单号。
- 退款单号。
- 出库单号。
- 调拨单号。
- 盘点单号。
- 报损报溢单号。
- 转换单号。
- 应收/应付/收款/付款/核销编号。
- 配送线路编号（可与线路名称组合展示）。

## 7.3 时间字段例外

以下页面时间属于业务核心信息，应保留：

- 操作日志。
- 库存流水。
- 财务流水。
- 收付款。
- 价格历史。
- 营销有效期。
- 配送日期。
- 计划到货。
- 期望配送。
- 审核时间（若直接关系当前业务状态）。

普通主数据的“创建时间/更新时间”默认下沉详情。

# 8. 表格统一规范

- 主文本：左对齐。
- 状态：居中。
- 单位：居中。
- 数量：右对齐。
- 金额：右对齐。
- 操作：居中。
- 操作列固定右侧时，表头和按钮共用同一中心线。
- 操作列普通场景控制在 120～160px。
- 超过 3 个动作时使用“更多”。
- 少数复杂工作台可放宽到 180px，但不得再出现 300～420px 的常驻操作列。
- 表格不要为了容纳低频字段强行设置超大的 `scroll.x`。
- 名称、分类、供应商、客户等业务文字应获得更合理宽度。
- 标签默认展示 2 个，剩余 `+N` + Tooltip。
- 空值统一使用 `—`。

---

# 9. 控件语义规范

| 数据 | 控件 |
|---|---|
| 金额 | `a-input-number` + `¥` |
| 数量 | `a-input-number` |
| 百分比 | `a-input-number` + `%` |
| 天数 | `a-input-number` + `天` |
| 整数优先级 | `a-input-number` |
| 日期 | `a-date-picker` |
| 日期时间 | `a-date-picker show-time` |
| 状态 | Select / StatusTag / Switch |
| Boolean | Switch，显示“是/否” |
| 标签 | Tag Picker |
| 客户 | CustomerSelect |
| 供应商 | SupplierSelect |
| SKU | SkuSelect |
| 员工 | EmployeeSelect |
| 仓库 | Warehouse Select |
| 备注 | Textarea |
| 业务编号 | Input，但编辑时按业务规则决定是否只读 |

不要因为 DTO 使用 string 就把金额、数量、比例全部做成普通文本输入框。

# 32. 开发纪律

AI / 开发人员执行本规划时必须遵守：

1. 先查当前页面最新代码，再修改。
2. 不按旧截图猜实现。
3. 不一次性横跨全部模块提交。
4. 每批最多围绕一个 UI 主题或一个业务模块。
5. 先建立公共规则，再批量套用。
6. 不机械复制商品页 CSS。
7. 不删除后端仍需要的字段。
8. “默认隐藏”只表示不在主列表默认展示，不等于删除能力。
9. 任何财务、流水、日志页面都要重新判断时间/编号是否为核心信息。
10. 任何状态机操作都不得因 UI 优化改变业务语义。
11. 任何数字控件替换都必须保持原 DTO 精度和提交格式。
12. 对 string-mode 金额不得因 InputNumber 改造丢失精度。
13. 视觉优化和业务重构分开提交。
14. 每次修改后至少人工验证 1920×1080。
15. P0 完成后再进入 P1，不允许全项目“铺开但都只改一半”。

# 34. 最终完成定义

本规划完成的标志不是“所有页面都加了圆角和阴影”，而是：

> 用户进入任意 XSY-SCM 模块，不需要重新学习这个页面应该怎么看、怎么找、怎么操作。

具体表现：

- 名称永远比内部编码重要。
- 状态永远容易识别。
- 金额和数量永远容易比较。
- 当前下一步动作永远容易找到。
- 详情信息不会全部挤在主列表。
- 系统字段不会抢业务字段的位置。
- 同样的数据类型使用同样的控件。
- 同样级别的按钮拥有同样视觉。
- 同样复杂度的 Drawer 拥有接近的宽度和布局。
- 商品、客户、供应商、采购、订单、库存、配送、财务看起来属于同一个系统。

# 35. 第一阶段建议立即执行清单
