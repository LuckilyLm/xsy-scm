### 券启停子阶段的确定范围

- 状态语义：券模板沿用 `DRAFT / ACTIVE / STOPPED`（V90 已建约束，本阶段不改表结构）。新建即 `DRAFT`；`DRAFT/STOPPED → ACTIVE` 为启用，`ACTIVE → STOPPED` 为停用；同状态重复启停拒绝（41327）。
- 启用不等于可发：启用只发布模板，实际发券仍须落在券自身有效期内（服务端再判窗口）。已过期的券不能再次启用。
- 权限：启停用独立权限 `scm:promotion:coupon:status`（V92 菜单 1709），不复用「券维护」，与活动侧一致——能改内容的人不必然能把它上线。
- 发券：要求 `Idempotency-Key`（缺失 → 40069）；同键同内容重放回放首次结果，不重复发券；客户归属与数据范围在服务端重新判定，越权 30005。
- 枚举收口：活动/券的 `DRAFT / ACTIVE / STOPPED` 与券实例状态改用 `ScmPromotionStatusEnum` / `ScmPromotionCouponInstanceStatusEnum`，替换营销域内残留的裸字符串字面量（`PromotionActivityService`、`PromotionDiscountService`），消除 `magic-string-domain-literal` 命中。
- 待授权验收：草稿 → 启用 → 发券链路、过期券启用被拒、并发启停版本冲突、同键重试不重复发券、越权客户发券被拒。


### 配送阶段的确定范围

- 展示内容：仓库起点、停靠点编号/客户/地址、配送先后顺序与带方向的连线。当前点间连线作为大致路线即可，不要求沿真实道路绘制，也不扩展实时路况、导航、ETA。
- 坐标缺失：保留全部停靠清单，标明缺失点并断开相邻线段；坐标齐全时能概览整条路线。地图配置/网络失败不阻断查看清单、排线或既有发车/签收操作。
- GPS 不再是本期功能或验收项：不建设实时位置、定时上报、轨迹回放，不接 GPS 终端，不要求员工小程序持续定位权限；已有代码先退场，历史表和记录保留。坐标维护及 CRS 换算继续保留，不能按 `gps` 关键字机械删除转换代码。
- 保留人工排序和既有辅助建议；地图能展示已保存的顺序即可，不能强制生成建议。草稿变更顺序后地图同步；已规划/已发车线路不因查看地图、生成或应用建议被自动改变业务状态。
- 待授权验收：地图顺序/编号/方向、缺点断线、失败降级、不同司机与调度范围、建议过期拒绝、GPS 入口不可用且旧数据不变。代码完成与现场地图验收分别记录。

### 本轮静态盘点发现的衔接缺口

- 配送已补齐：建议入口要求线路查看权，写侧显式传司机范围给锁查询，历史复用线路范围；先锁线路再锁建议。生成时冻结线路与停靠点版本、起点/各点坐标和 CRS，应用核对冻结输入；旧无版本快照允许回看但拒绝应用。历史明细从快照恢复，前端修复应用后调用不存在的 `load()` 及切换线路的旧响应覆盖。
- `PromotionController.discount/confirm` 目前使用活动查询权限；表单接收 `customerId`、`salesOrderId`、行 id 与基础金额，`PromotionDiscountService` 未从正式订单重建并核验这些输入。需改为受订单权限与范围约束的正式业务命令。
- 当前订单域未检索到优惠服务调用，前端也仅有试算/冻结 API 封装；活动页与优惠券页不等于订单优惠已经生效。发券已在本子阶段补上请求级幂等与客户范围判定（见上节）；优惠重复冻结仍是拒绝而非原结果重放，满赠当前返回零金额、未见赠品履约来源。以上剩余项作为第三阶段开发入口，不把表结构/DAO 状态方法当主链完成。
