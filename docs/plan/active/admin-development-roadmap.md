- 已完成能力不重新列成开发任务；需要回看历史实现时查 Git。
- 新能力先确认现有 ADR 是否允许；规则不足时先补决策，再写代码。
- 已应用 Flyway migration 不修改，只追加新版本。

- 外部服务、真实设备和生产渠道不能用 mock 结果代替。
- 默认不推送、不发布、不执行生产迁移；按具体任务授权执行。

## 3. ADM-01～12 的维护方式

ADM-01～12 的主干实现已经进入现有代码，不再在路线图重复保存“第几切片、当时改了哪些文件”的历史过程。后续只按以下边界维护：

- Finance / 报表继续遵守 ADR-004、ADR-006 的追加事实、跨域只读、净额与对账口径。
- 采购净需求、通知、打印、异常聚合继续遵守 ADR-007；需要扩展时在原契约上增加，不另建第二套状态。
- 地图、配送、分拣设备继续遵守 ADR-002、ADR-003、ADR-008；实时 GPS 不在当前范围。
- 营销、支付、余额继续遵守 ADR-009 与[余额支付设计](balance-payment-order-settlement-design.md)；已完成的优惠冻结、赠品、券生命周期与限时特价不再维护第二份实施计划。
- 客户商城和员工移动端遵守 ADR-010，两个产品的角色与页面范围分开设计。

## 4. 前置决策与外部条件

开始下列工作前必须先拿到对应输入：

- 充值到账链：到账时点与异常恢复策略。
- 混合退款：来源分配规则。
- 电子秤：设备协议、帧样例、稳定读数/校准规则。
- 真实支付：渠道主体、沙箱或生产凭据、回调域名与验签材料。
- 地图：目标环境服务商、Key、安全配置、配额与商用授权。
- 移动端发布：微信主体、应用标识、审核与发布条件。
