# 管理后台后续开发规划清单

更新日期：2026-10-02。
状态：规划清单；本轮仅整理文档，未启动功能开发。顺序为建议，不代表排期、业务规则或新增范围已批准。

依据：[产品功能需求基线](../../requirements/产品功能需求基线.md)、[项目状态](../../status.md)、[有效决策](../../decisions.md)及当前主线代码。

## 1. 使用方式与范围

- 本清单统一管理后台剩余工作；已完成能力不重复列入开发任务。
- “未开发”表示当前主线未找到完整页面、接口和业务链；“部分实现”表示已有基础，但目标流程尚未闭环。二者均不代表当前阶段承诺的功能存在缺陷。
- 当前 ADR 排除的能力只能作为候选项；进入实施前补充或更新对应 ADR，不以本清单覆盖现有规则。
- 需求、设计、实现、验收和生产部署分别记录；静态代码盘点不能替代运行验收。
- 以下完成标准是未来验收要求，本轮未执行测试、构建、浏览器或生产环境验证。

## 2. 建议推进顺序

| 顺序 | 工作包 | 推进方式 |
| --- | --- | --- |
| 1 | 财务 R2（ADM-01） | 先明确收入、成本、余额、到期日和报表口径，再按利润、账龄、对账分别交付；退货成本处理与 ADM-02 协调。 |
| 2 | 售后库存及客户结算联动（ADM-02～04） | 优先补退货实物回库、集团统一结算、账期/授信联动的规则，再逐项实施；不把三个领域合成一次大改。 |
| 3 | 后台操作完善（ADM-05～08） | 采购净需求、业务通知、打印模板、异常订单分析分别收口，可按已确认的小范围独立推进。 |
| 4 | 地图、配送和分拣增强（ADM-09～11） | 地图部署路线、优化目标、设备协议等前置条件明确后推进。 |
| 5 | 营销结算、协同与溯源（ADM-12～15） | 营销与支付分开交付；二维码、移动协同与溯源各自明确消费者和权限。 |
| 6 | 客户商城 / W6-2（ADM-16） | 保持当前冻结边界，满足主线与营销支付前置条件后再启动。员工仓储/配送操作端应单独定义范围，不自动等同于客户商城。 |

## 4. 不重复开发与未默认纳入

- 已有：商品 Excel/图片批量导入、采购单单张/批量打印、报损报溢驳回通知、调拨在途报表、市场价回退、预留消费、配送签收、Finance R1、采购每日清单。
- 基础市场价已参与定价；“时价”如指分时段/自动更新的额外机制，需先明确与当前市场价的差异，不直接判定为缺失。
- 多仓默认选择保持人工显式选仓；是否自动推荐仍为未决事项，不默认增加自动推断。
- 会计凭证/总账、发票税额、多币种、财务审批、采购退货等未作为本轮新增开发承诺；确需扩展时另行界定范围。
- 已确认的当前阶段排除项仍生效；候选清单不等于解除这些边界。

## 5. 交付与维护

每次只推进已明确范围的工作包：规则/ADR → 实现 → 按授权执行验证 → 更新本清单与项目状态。实现完成后记录实际证据与未覆盖项；部署记录独立维护，不把 Git 合并或本地验收当成生产上线。

需要执行验证时，重点覆盖真实跨域场景、权限/范围、重复与并发请求、失败回滚、查询/导出一致性和浏览器操作。数据库变更只追加 migration，版本与菜单编号在实施时扫描现状后确定，不在本清单预占。
