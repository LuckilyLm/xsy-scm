## 1. P0 · 阻塞项

### B-01 后端 `/scm/mall/**` 完全不存在

- **事实**：`xsy-scm-server` 内 `find -iname "*mall*"` 无结果；`grep -ril mall` 只命中
  `ScmOrderSourceEnum` 的 `MALL` 值、`SalesOrderAddForm` 与迁移脚本，即只有 `order_source = MALL` 这个枚举。
  实际业务域是 `net/lab1024/sa/admin/module/scm/**` 下的
  `common/customer/delivery/inventory/order/pricing/product/purchase/screen/supplier/warehouse`。
- **影响**：客户端无法做任何真实联调；`src/api/mall/**` 的 8 个域全部只有 mock 支撑。
- **当前缓解**：`mock/` 契约层（`VITE_APP_USE_MOCK=true` 仅 `.env.development`）顶住开发。
- **需要**：后端排期。**这是本项目当前唯一的硬阻塞。**

### B-02 商城业务错误码未冻结

- **事实**：`src/constants/error-code-const.js` 的 `MALL_ERROR_CODE` 刻意留空。
  遗留商城 v1 用过的 `40070`（购物车为空）/ `40074`（未选商品）/ `40970`（变价）
  **均已被 V2 `OrderErrorCode` 占用**，不能沿用。
- **影响**：客户端无法实现三个关键分支交互 ——
  价格已变化（`PRICE_CHANGED`）、库存不足（`STOCK_INSUFFICIENT`）、商品不可见（`SKU_NOT_VISIBLE`）。
  这三项已在 `MALL_ERROR_SEMANTIC` 里留好语义位，等码值填入即可。
- **需要**：与后端一次性对齐码段。

### B-03 微信小程序 AppID 未提供

- **影响**：无法真机预览、无法配置 request 合法域名、微信一键登录无法实测
  （`uni.login` + `wx.login` 链路只在代码层面存在）。
- **需要**：业主提供 AppID，写入 `src/manifest.json`。

### B-04 request 合法域名未提供

- **事实**：`.env.pre` / `.env.production` 的 `VITE_APP_API_URL` 仍是
  `https://pre-api.example.com` / `https://api.example.com` 占位值。
- **影响**：小程序端不走 Vite devServer，必须使用可从手机访问的 HTTPS 域名并在微信公众平台备案，
  否则真机一律请求失败。
- **需要**：业主提供三套环境（test / pre / prod）域名。

### B-05 在线支付商户号未提供

- **影响**：结算 → 支付链路无法闭环。规划 §39 第 11 项（结算）即使开发完也无法验收。
- **需要**：业主提供微信支付商户号与证书配置方式。

### B-06 商品图片 fileKey 未提供

- **影响**：全部商品图走「名称首字」占位（`product-card.vue` / `detail.vue` 的
  `imageUrl` 为空时分支）。视觉验收无法进行。
- **需要**：业主提供商品图 fileKey 或图片托管方案（含 URL 派生规则）。

### B-07 登录是否为启动硬门禁未裁决

- **事实**：当前入口是 `pages/home/index`（Tab 页），登录页按需跳转
  （令牌失效时由请求层 `reLaunch` 到 `/pages/login/login`）。
- **影响**：首页、分类、搜索、商品详情在**未登录**状态下会请求失败或拿到空数据，
  用户先看到空态再被跳登录，体验不佳。
- **需要**：产品裁决。若定为硬门禁，`App.vue` 的 `onLaunch` 里加一次令牌校验并 `reLaunch` 即可。

## 2. P1 · 契约不确定（后端落地后必须逐项核对）

### C-01 mock 契约字段是暂定的

- **依据**：`mock/fixtures.js` 的字段形状来自
  [`docs/reference/2026-09-22-遗留商城v1契约参考.md`](../reference/2026-09-22-遗留商城v1契约参考.md)

- **核对方式**：后端落地后只改 `mock/fixtures.js` 与 `mock/routes/**`，
  页面与 `src/api/mall/**` 的签名不用动（这是当初的分层目的）。
- **重点核对**：分页对象字段名（`list` / `total` / `pageNum`）、商品详情多出的
  `deliveryTip` / `nonStandardTip` / `description`、库存状态枚举三值、`priceSource` 四值。

### C-02 非标品「预计金额」的归属

- **事实**：规划 §11.2 示例里有 `预计 ¥12.20`，但 §17.1 把「非标品预计金额」定位在
  `POST /orders/preview` 的响应里，§38.6 又禁止客户端自行算价。
- **当前实现**：商品详情页**不做**预估，只展示「按实际称重结算 / 下单数量 ≠ 最终实际重量」的规则说明。
- **待裁决**：若业主要求详情页也显示预估，需**后端在详情接口返回该字段**，客户端不自行乘算。
  详见 `README.md` → 「尚未完成」。

### C-03 库存展示口径未裁决

- **事实**：当前只在 `stockStatus === 'AVAILABLE'` 时展示「可售 N」，不足 / 缺货时只显示文案。
- **待裁决**：B2B 场景下是否应展示具体可售数字（含不足时的数字）。
- **注意**：客户端把 `availableQty` 只当**交互上限**用，真正的库存校验必须在服务端事务内完成（§38.7）。

### C-04 分页上限

- **事实**：V2 `PageParam` 对 `pageSize` 有 `@Max(500)`；mock 侧 `paginate()` 已按 500 截断。
- **待核对**：真实后端超限时是报错还是静默截断。

### C-05 订单状态映射表未拿到

- **事实**：规划 §18 要求做「客户可理解状态映射」（如内部 `DRAFT` / `PENDING` → 客户侧「待确认」），
  且明确客户端**不得自行推断**。
- **影响**：订单列表 / 订单详情（§39 第 12 项）无法实现，只能等后端给映射表。

### C-06 价格指纹算法与幂等键语义

- **事实**：§17.1 要求 `POST /orders/preview` 返回 `priceFingerprint`，提交时携带同一个值；
  §17.2 要求 `Idempotency-Key` 在同一份订单内容重试时复用、内容变化后换新。
- **待核对**：指纹的生成方（服务端）与客户端需要参与的部分、幂等键的有效期与作用域。
  请求层已支持 `options.idempotencyKey`（写入 `Idempotency-Key` 头），语义待确认。

### D-06 文档中一处机制描述不准确（本次已实测修正）

**原文表述**：「uni-app 会把 `src/` 整棵树镜像进构建产物（未被引用的文件同样会被发射）。」

**实测结论（本次用探针文件验证）**：在 `src/utils/` 下放置两个**无任何模块引用**的探针文件
（一个纯导出、一个带顶层 `.map()` 副作用），生产构建产物中**两者均未出现**。
因此「镜像整棵 `src/` 树」这一表述**不成立**，未引用模块会被正常 tree-shake。

**此前观察到的 `src/mock/fixtures.js` 泄漏，更可能的真实原因**：
当时引入标识是 `@/mock`，被 uni-app 自带的 `@` → `src/` 别名（优先级高于用户 `resolve.alias`）
截获并解析到 `src/mock/index.js`，**使整条 mock 依赖链变为可达**，于是被打进产物。
换句话说，泄漏的根因是**别名解析错误**，不是「整树镜像」。

**处置**：`README.md`（「Mock 契约层」→ 两个必须知道的约束）、`AGENTS.md`（Mini Program 章节）
与技能文档 `xsy-scm-miniapp-dev`（§2.5）的措辞**已按本结论修订**；
两条实践规则**继续保留**（纵深防御，成本为零）：
① `mock/` 放在 `src/` 之外；② 引入标识用 `@mock` 而非 `@/mock`。

**教训**：这条错误表述曾连续被抄进 3 份文档（README / AGENTS / 技能），
说明「构建产物里出现了某文件」这类观察很容易被归因错误。
下次遇到类似现象，先用**最小探针**（放一个无引用的文件，看它进不进产物）验证机制，
再写结论。

### D-07 `.gitignore` 默认拒绝规则容易静默吞掉新文件（本轮已部分处置）

仓库根 `.gitignore` 用 `/tools/*` + 显式 `!` 白名单的默认拒绝策略，

## 5. R · 本轮已修正的缺陷

### V-04 无 CI / 无 git hooks

仓库没有 husky、`.git/hooks` 里也没有自定义钩子。
`lint` / `test:mock` / 双端构建全靠**手工执行**，无法阻止未验证的提交进入分支。
建议后续把验证门禁接进 CI。

## 7. 附录 A · 构建期陷阱清单（长期守住）

这些坑 lint 查不出来，改动样式层 / 请求层 / store / 页面结构后**必须跑构建**。

| 陷阱 | 症状 | 规则 |
| --- | --- | --- |
| `uni.scss` 自动注入 | 相对路径 `@import` 以**引入方目录**为基准重新解析 | `uni.scss` 内一律用 `@/` 别名 |
| 请求层依赖成环 | Vite `Circular chunk` | 请求层禁止 import Pinia store |
| `:export` | 非法 CSS 警告 | 用 `theme-color-const.js`，与 `tokens.scss` 同步 |
| 页面 vs 组件 lint 作用域 | `vue/multi-word-component-names` 误报页面 | 页面目录豁免，`src/components/**` 仍约束 |
| `@mock` vs `@/mock` | `Cannot find module .../src/mock` | uni-app 的 `@` 别名优先级更高，必须用 `@mock` |
| `getRequest` 丢参数 | 筛选 / 分页静默失效 | 必须 `(url, params) => request(url, 'GET', params)` |
| 空元素未自闭合 | `vue/html-self-closing` 报错 | 空 `view` 写成 `<view />` |
| `safe-delete` 静默改名 | `Cannot find module`，文件被改成 `<name>.DELETE.<hash>` | `mv` 改回原名；装完依赖扫一遍 `find node_modules -name "*.DELETE.*"` |

**另注意**：`npm run build` 输出的 Dart Sass `@import` / legacy JS API 弃用警告
来自 uni-app 自身的变量注入模型（`@use` 不支持全局变量注入），
**结构性不可消除，不要试图「修」它**。
