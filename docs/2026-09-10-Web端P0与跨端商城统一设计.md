# Web 端 P0 与跨端商城统一设计

> 版本：v1.0
> 日期：2026-09-10
> 依据：`docs/功能清单模块.docx`、`docs/references/sdongpo/功能参考与借鉴记录.md`、`docs/references/sdongpo/页面调查索引.md`

## 1. 背景与目标

当前项目已经完成商品、客户、订单、采购、库存等 Web 基础页面，并已完成营销、分拣、物流配送、财务报表后端域。下一阶段补齐 Web 端 P0 页面，同时解决 Web 商城与 Taro 小程序商城配置不一致的问题。

核心目标：

1. 后台只维护一套商城首页与主题配置。
2. Web 商城和小程序商城读取同一套聚合接口、使用同一套配置语义。
3. 后台修改首页板块、活动、主题后，两个客户端在同一发布版本下展示一致内容。
4. P0 优先覆盖营销商城、分拣、物流配送、财务报表和溯源查询的可用闭环。
5. 借鉴蔬东坡的双层导航、状态页签、常用筛选、列表合计、手机预览和商品快速选购，但不复制其代码、品牌、数据或未经验证的业务规则。

## 2. 参考站转化原则

参考站实际观察到：后台商城首页采用“主题设置 + 手机预览 + 配置表单”，H5 首页包含搜索、轮播、分类、活动、商品列表和底部导航；后台订单、库房、配送、财务页面均以状态页签、筛选、列表和详情联动为主。

本项目只借鉴以下信息架构：

- 配置与预览同屏，先看效果再发布。
- 常用筛选首屏展示，高级筛选折叠。
- 业务状态与付款/结算状态分开。
- 列表展示关键数量、金额、进度和关联单据。
- 商品选购保留分类、搜索、规格、起订量、数量和金额反馈。

明确不直接照搬：

- 参考站的价格优先级、抹零规则、账期规则和毛利口径。
- 未经真实设备验证的电子秤、打印机、GPS 和支付行为。
- 参考站内部数据库、接口、权限和菜单实现。

## 3. 统一商城架构

```text
                    ┌──────────────────────┐
                    │ Web 管理端             │
                    │ 首页配置 / 主题 / 活动  │
                    └──────────┬───────────┘
                               │ 发布配置
                               ▼
                    ┌──────────────────────┐
                    │ Marketing / Mall      │
                    │ 统一配置与聚合服务      │
                    └──────────┬───────────┘
                               │
               GET /api/mall/home + /theme
                    ┌──────────┴───────────┐
                    ▼                      ▼
          ┌────────────────┐     ┌────────────────┐
          │ Web 商城        │     │ Taro 小程序     │
          │ React + CSS     │     │ React + Taro    │
          └────────────────┘     └────────────────┘
```

### 3.1 配置职责

- `marketing`：管理促销活动、首页板块、优惠券等运营数据。
- `mall`：面向客户端提供聚合后的首页和主题数据；过滤未发布、未生效或已删除内容；按统一顺序返回板块。
- Web 管理端：提供配置录入、排序、上下线、预览入口。
- Web 商城与小程序：只消费 `mall` 聚合接口，不直接拼接后台管理接口。

### 3.2 P0 聚合接口

```http
GET /api/mall/home
GET /api/mall/theme
```

`GET /api/mall/home` 返回：

```ts
interface MallHomeResponse {
  theme: MallThemeConfig;
  sections: MallHomeSection[];
  categories: MallCategory[];
  promotions: MallPromotion[];
  generatedAt: string;
}
```

`MallHomeSection` 至少包含：

```ts
interface MallHomeSection {
  id: number;
  sectionType: 'BANNER' | 'FLASH_SALE' | 'NEW_ARRIVAL' | 'CATEGORY' | 'RECOMMEND' | 'CUSTOM';
  title?: string;
  sortOrder: number;
  payload?: Record<string, unknown>;
  promotionId?: number;
  categoryId?: number;
}
```

## 4. 主题协议

主题只描述外观，不创建或修改促销活动：

```ts
interface MallThemeConfig {
  themeCode: string;
  primaryColor: string;
  accentColor: string;
  pageBackground: string;
  cardRadius: number;
  cardStyle: 'FLAT' | 'SHADOW' | 'BORDER';
  productCardStyle: 'COMPACT' | 'COMFORTABLE';
  navigationStyle: 'BOTTOM' | 'TOP';
}
```

- Web：转换为 CSS Variables，例如 `--mall-primary-color`、`--mall-card-radius`。
- 小程序：转换为页面级 style 对象或 Taro 样式变量。
- 两端枚举值、默认值和降级策略一致。
- 非法颜色、超范围圆角、未知枚举由客户端回退到默认主题，不阻塞首页展示。
- 主题切换与促销生效相互独立。

## 5. 配置生命周期

P0 先采用“保存即生效”的简化模型，但必须保留后续版本化扩展空间：

- 管理端保存板块/主题配置。
- 客户端只读取 `status=ENABLED` 且处于有效时间范围的内容。
- 未启用、已过期、删除内容不进入聚合接口。
- 后续可扩展为草稿、预览、发布版本；本期不建设通用低代码拖拽装修器。
- 图片跳转使用类型化目标（商品、分类、公告、领券中心、仅展示、受控外链），不允许任意拼接小程序路由。

## 6. P0 Web 页面

### P0-1 商城与营销

- 商城首页：Banner、分类导航、活动板块、新品/推荐、商品列表、主题应用。
- 首页配置：板块列表、排序、上下线、有效期、目标类型、手机预览。
- 主题配置：颜色、背景、圆角、卡片和导航样式。
- 促销活动：抢购、满减、满赠、限时特价。
- 优惠券：模板、发放、核销状态。

### P0-2 分拣

- 商品分拣和客户订单分拣两种视角。
- 待分拣、分拣中、已完成、异常/缺货状态。
- 分拣员、送货日期、线路、供应商、阈值筛选。
- 实重录入与误差提示。
- 标品批量分拣、打印结构化数据。

### P0-3 配送

- 线路列表和规划条件。
- 线路内订单/客户视图切换。
- 司机、配送进度、订单数、订单金额。
- 轨迹追加和时间线。
- 线路发货单打印结构化数据。

### P0-4 财务与报表

- 经营数据卡片和趋势摘要。
- 销售、采购、客户订单明细。
- 已收款、待收款、应付款和收付款流水。
- 单品利润、客户利润、销售员业绩。
- 导出前明确日期、金额、成本和利润口径。

### P0-5 溯源

- 溯源码分页查询。
- 溯源详情与事件时间线。
- 客户侧扫码结果与 Web 管理查询使用同源数据。

## 8. 验收标准

### 跨端一致性

- 后台启用/停用或排序首页板块后，Web 与小程序使用同一接口返回同一顺序和状态。
- 后台切换主题后，两端主要颜色、背景、卡片圆角和商品卡片风格一致。
- 未生效活动不会在任一端展示。
- 统一接口异常时，两端均使用明确的空状态/降级主题，不渲染破碎页面。

### 业务页面

- P0 页面均有路由、权限入口、加载态、空状态、错误提示和分页。
- 实重、金额、数量等字段明确单位和口径。
- 批量操作明确显示作用范围，并在提交前二次确认。
- 打印接口先返回结构化数据，不在本期绑定打印机或生成 PDF。

### 工程质量

- 后端 `mvn -o test-compile` 通过。
- Web 执行 `tsc --noEmit` 和生产构建。
- 小程序执行 `tsc --noEmit` 和 `taro build --type weapp`。
- 新增接口的字段命名与现有 Java DTO/VO 一致。

## 9. 明确不纳入本期

- 通用低代码装修器。
- 真实电子秤设备接入和稳定判定。
- 真实打印机驱动。
- GPS 路线优化算法和地图服务接入。
- 完整总账、税务凭证和会计科目。
- AI 语音录单。
- 未经验证的参考站业务规则复制。
