## 4. 关键设计（值得继承的部分）

### 4.1 价格指纹算法（`MallCheckoutFingerprint`）

```java
// 明细按 skuId 升序，逐行拼接 skuId:quantity:unitPrice:priceSource:priceSourceId
String lines = items.stream()
    .sorted(Comparator.comparing(MallCheckoutItemResponse::skuId))
    .map(i -> i.skuId() + ":" + i.quantity() + ":" + i.unitPrice() + ":"
              + i.priceSource() + ":" + (i.priceSourceId() == null ? "" : i.priceSourceId()))
    .collect(Collectors.joining("|"));
// 前缀 customerId:addressId: 后取 SHA-256 hex
String source = customerId + ":" + addressId + ":" + lines;
```

要点：**明细必须按 skuId 排序**（否则同内容不同顺序会产生不同指纹）；
指纹把客户与地址纳入，因此改地址也会触发重新确认。

### 4.2 写单入口复用同一订单域（与 V2 裁决同构）

`MallOrderService` 直接依赖 v1 的 `SalesOrderEntity` / `SalesOrderItemEntity` /
`SalesOrderConverter`，**不建 `mall_order` 表**；订单按 `customerId` 查询归属。

这与 V2 裁决「直接写同一 `sales_order` 并标记 `MALL`，不建 `mall_order` 或同步表」**完全同构**，
是该裁决的正面验证。

### 4.3 地址快照独立成表

`mall_order_address`（V30）按 `order_id` 唯一，存 `receiver_name` / `phone` / `region` /
`detail_address` + `customer_id`。V2 已有等价物 `order_address_snapshot`（V13 建、V42 加经纬度），
**V2 直接用它，不新建表**。

### 4.4 订单来源

V30 把 `sales_order` 来源 CHECK 改为 `IN ('NORMAL','SUPPLEMENT','MALL')`。
V2 的 V13 已经是 `IN ('ADMIN','MALL','SUPPLEMENT')`——**已含 MALL，本期不必改 CHECK**。

## 5. 冲突清单（照搬会踩的坑）

| # | 项 | v1 做法 | V2 现状 | 处置 |
| --- | --- | --- | --- | --- |
| C-1 | 错误码 `40070` | 购物车为空 | 🔴 已被 `OrderErrorCode.ORDER_IDEMPOTENCY_KEY_INVALID` 占用 | 重排码段 |
| C-2 | 错误码 `40074` | 未选下单商品 | 🔴 已被 `ORDER_DELETE_STATE_INVALID` 占用 | 重排码段 |
| C-3 | 错误码 `40970` | 商品价格已变化 | 🔴 已被 `ORDER_RETURN_ORDER_NOT_CONFIRMED` 占用 | 重排码段 |
| C-4 | 分页参数 | `page` / `pageSize` | V2 `PageParam` 用 `pageNum` / `pageSize`，`@Max(500)` | 客户端服从 `pageNum` |
| C-5 | 地址字段 | 仅 `region VARCHAR(200)` | V40 要求省市区六列 + `longitude/latitude/geom_crs` | 按 V40 形态建 |
| C-6 | 购物车归属 | `customer_id` | 需求要求「集团客户多采购员独立采购」 | 建议改 `account_id` |
| C-7 | 认证 | Spring Security + `MallAuthenticationFilter` + 自研令牌 + `mall_customer_session` 表 | Sa-Token 多 `userType`，不建会话表 | 整体重做，不移植 |
| C-8 | 账号 | `username` + `password_hash` | 微信 openid 优先 + 手机号兜底 | 字段重构 |
| C-9 | 首页装修 | `MallHomeResponse` / `MallHomeSection` / `MallThemeConfig` 通用装修器 | 本期不做通用装修器 | 客户端不建复杂模型 |

V2 scm 域实测已占用码段：`40000–40090`、`40410–40499`、`40910–40999`、`41000–41109`。
未占用且 v1 商城码可用：`40170–40172`、`40370–40372`、`40470–40473`、`50170`。

## 6. v1 表 DDL 摘要（V29）

供字段形状参考。v1 已具备 V2 同样风格的约束习惯：partial unique index + `WHERE deleted = FALSE`、
`version` 乐观锁、审计列、**不建外键**。

```text
mall_customer_account   customer_id / username / password_hash / contact_name / contact_phone
                        / wechat_openid / status(ENABLED|DISABLED) / last_login_at / version / deleted
                        + uk(LOWER(username)) WHERE deleted=FALSE
                        + uk(wechat_openid) WHERE deleted=FALSE AND wechat_openid IS NOT NULL
                        + idx(customer_id) WHERE deleted=FALSE

mall_customer_session   account_id / customer_id / token_hash / user_agent / expires_at / revoked_at
                        + uk(token_hash) WHERE revoked_at IS NULL        ← V2 不建此表

mall_customer_address   customer_id / receiver_name / phone / region / detail_address / is_default
                        / status / version / deleted
                        + uk(customer_id) WHERE deleted=FALSE AND is_default=TRUE
                        + idx(customer_id, id) WHERE deleted=FALSE        ← V2 需加地理六列

mall_cart_item          customer_id / sku_id / quantity NUMERIC(18,4) / version / deleted
                        + ck(quantity > 0)
                        + uk(customer_id, sku_id) WHERE deleted=FALSE     ← V2 建议改 account_id

mall_order_address      order_id / customer_id / receiver_name / phone / region / detail_address
                        + uk(order_id)                                    ← V2 用 order_address_snapshot
```
