- **阶段 B：订单履约与真实决策**——SDP-03/04/05、SDP-11/14/15/18/19/23。集中建设客户/商品双分拣、异常、排线工作台、损耗/毛利/绩效视图。每个展示均能钻到正式订单行与库存事实。
- **阶段 C：客户运营和财务协作**——SDP-06/07/08、SDP-13/16/20/21/22。实现首页装修、更多营销、客户集团和供应商协作，不能让集团合并突破客户账/授信的隔离。
- **阶段 D：更深行业能力**——SDP-17/24/26，完成加工/库位/包装码、员工移动端；特定硬件/供应商协作与智能语音按真实设备及平台测试推进。

**所有阶段共同完成定义**：产品交互 + 领域业务规则（确认后写入 `docs/decisions.md`）+ 必要时新增 Flyway + 后端接口/后台/客户端 + 数据范围与审计 + 业务事实/金额/单位快照 + PostgreSQL 集成测试 + 前端契约及构建 + H5/微信或设备的单独现场验收。没有真实外部条件则标记 **INCOMPLETE**，不能拿 mock 或静态代码声称上线。当前 QUALITY-01 的浏览器 E2E 仍因测试 API 启动前置而未执行，跟新增路线图并行解决。

**地图与车辆明确排除边界（2026-10-17 用户裁决）**：保留仓库/客户/司机/停靠点静态点位、配送区域、路线规划、线路地图、已确定站点顺序及打印；**不实现车辆实时 GPS 位置、位置推送、电子围栏追车、车辆实时轨迹/回放或地图车载实时监控**。已存在的历史轨迹表不擅删，新的“线路轨迹”只指按既有站点规划生成的展示路线，不代表 GPS 实测行驶轨迹。参考系统的车辆视频若用于实时追车也排除；其它独立安防需求不在这次授权范围。

### 第一优先：商品中心与客户价格（SDP-01 / SDP-02）

**SDP-01 商品搜索与客户商品档案**（在现有 `product` + `customer` + `mall` 中增强，不新增平行主档）：

1. 商品候选搜索统一支持名称、商品编码、规格编码、条码；对**别名/助记码**先做字段与索引影响评估，禁止直接假定后端已具备。客户别名是客户对 SKU 的映射，不得修改全局商品名称；后台与客户端显示优先级必须一致。
2. SKU 条码、销售单位、起订量/步进及库存记账单位继续复用既有配置，商品销售表现从正式订单/报表聚合查得，不从当前分页表格求和；客户不可售 SKU 不出现在商城和客户下单建议里。
3. 批量上下架沿用现有 `ProductBatchService` 的权限、版本、结果明细；图片按现有 `ProductImageCenterService`，不迁入逆向图库。
4. **验收**：精确编码与模糊别名可定位同一 SKU；同名别名不越客户范围；下架、仓库无货、不可见和起订量拦截端到端一致；批量操作逐行审计及重复提交无副作用。

**SDP-02 协议价公式与调价预览**（`pricing`）：

1. 当前 `AgreementPriceEntity` 只有 `customerId/skuId/unitPrice/effectiveFrom/effectiveTo`；参考系统提到的无公式、加固定金额、成本加价率、销售加价率只是**参考端的前端字段推断**。先确认基准价选取时点、是否含税、精度四舍五入、最低价和有效区间，再设计公式。
2. 后端统一算价并显示**试算明细**（基准价来源、公式、参数、输出价、失效条件），不在 Vue/uni-app 重复计算。保存使用乐观锁，保留变化前后快照。已确认订单永远使用冻结行价格；“批量刷价”默认只作**候选影响预览**，绝不静默更新历史订单与对账单。
3. **验收**：价格优先级（具体客户→客户类型→通用）与重叠日期、并发改价、无成本数据、退款历史单独测试；时间边界按 Asia/Shanghai 口径明确；4 位小数不经 JS 浮点求价。
4. **业务待裁决**：参考资料所说的四种公式是否全部启用、公式基准价、采购成本缺失时禁用还是报错、是否允许对尚未确认订单做受控重算。

### 第二优先：分拣、配送与经营报表（SDP-03 / SDP-04 / SDP-05）

**SDP-03 分拣作业增强**（`sorting` / `inventory` / `print`）：

1. 按**发货日期 + 指定仓库**组织工作台，展示“按商品汇总”与“按客户明细”两种**只读聚合视角**，最终写入只对正式分拣任务行执行命令，不能把汇总 SKU 行当成可改库存事实。
2. 对需要重复称重/多框分拣的行，设计“分次记录”并显示总接受量、已分拣/待分拣、装车状态、差异阈值与原因；允许与现有电子秤事件绑定，但**原始读数不等于已接受量**。现有分拣任务行版本、授权仓库、指派人和补偿流程必须保留。
3. 标签打印预览保持 GET 只读，登记打印次数保持单独幂等写接口；打印失败不自动视为拣货失败。绩效只读投影从经确认的分拣事实生成，明确不同单位不能相加。
4. **验收**：同 SKU 多客户/多单位、分次称重、短少/超拣、取消重开、并发两员工录入、重复打印、跨仓隔离，使用真实 PG 定向集成测试。

**SDP-04 排线与配送作业台**（`delivery`）：

1. 在现有 `DeliveryPlanProposalService` 上增加列表/地图两视图的人工比较、配送区域和候选订单的来源说明；优先沿用 GCJ-02 坐标及当前距离矩阵服务，不照搬参考系统地图供应商配置。
2. 区分“建议→人工应用→分拣/装车→发车→签收”，司机只能操作被授权线路；变更配送地址必须检查订单绑定的配送仓和已冻结的配送事实。
3. **验收**：同仓单线、跨仓拒绝、站点重排、状态/版本冲突、重复应用建议、发车前与发车后变更约束。

**SDP-05 经营与损耗洞察**（`report` / `inventory` / `finance`）：

1. 从已有 `InventoryReportService`、`PurchaseReportService`、`ScmFinanceProfitService` 组装“采购价波动 / 预估毛利 / 实际结算毛利 / 库房损耗 / 退货损耗”口径卡片，不制造新的资金或成本账本。
2. 报表必须返回服务端总计、成本缺失标志、单位、时间字段和权限范围；期初+入库−出库±盘盈亏→期末按**同仓同 SKU 同记账单位**核对，报表不得跨单位求和。
3. **验收**：金额总计与原始流水逐行可对账；正常缺失成本不显示 `0`；退款/退货不重复冲减；多仓和业务员权限下钻正确。

### 第三优先：商城运营、采购协作与通用配置（SDP-06 / SDP-07 / SDP-08）

**SDP-06 商城首页装修**（`mall` + 客户 uni-app）：推荐先做有限的 schema 化组件，而非直接复制整套拖拽编辑器。

- 首批组件：轮播图、快捷入口、推荐商品、活动专题、公告。配置包含 `type`、`schemaVersion`、`sortOrder`、目标客户范围、开始/结束时间、状态、商品 SKU 关联；服务端校验 URL 类型、外链白名单与客户可见性。
- 版本必须区分**草稿 / 已发布**，发布时原子切换版本、保留回滚记录；前台同一版本读取、授权过滤商品，库存与价格仍**实时基于已选配送仓**查询，不随装修快照冻结。
- 后台新建配置页；客户端首页只做白名单渲染。不按参考的 `sessionStorage` 改路由伪造“多租户灰度”，统一使用服务端权限与发布版本。
- **验收**：H5 与 mp-weixin 同配置、未发布不泄漏、错链/已下架/客户无权商品安全降级、发布冲突与回滚一致、无效内容不影响既有下单。

**SDP-07 采购询价与供应商协作**（`purchase` / `supplier`）：现有 `PurchaseDemandCalculationBatchService` 已冻结净需求解释快照，新增询价/报价只能在此基础上生成，不能直接修改采购单状态。供应商链接要有独立授权、短有效期、每个询价版本、重复报价幂等和报价比较；价格转为采购单必须经人工确认与角色授权。

**SDP-08 服务端驱动的高级筛选与导出列**（共用能力）：借鉴 `SearchConfig` / `customExportColumn` 思路，但用 XSY 自己的白名单字段配置。查询条件、导出列与导出数据都必须接受后端同一仓库/客户/成本数据权限；不得让用户通过增加字段名绕开查询范围。先在商品、订单与采购报表三个页面试点。

### 长期项与明确不采纳

- **SDP-09 食品追溯**：先建企业主体、批次、检测报告、附件关联、SKU/批次映射、公开字段审批与二维码查询；地区平台上报作为外部适配器（同步状态、失败重试、凭据托管）。未取得平台正式授权与接口文档时不开发真实上报。
- **SDP-10 ERP/企微对接**：需求确定以后独立集成层做单据映射、出站事件、重试、失败对账；禁止跨域直写已记账单据，也不接入参考包里的密钥。

## GATE-02：库存、履约与退货黄金链

1. 准备配送仓 A、B，客户绑定仓和区县映射规则，SKU（商品规格）销售单位为箱、库存记账单位为 kg，明确 1 箱 = 10 kg。A 有 100 kg、B 无库存。
2. 商城地址/选仓、商品目录、购物车、结算预览和下单始终只使用当前合法配送仓；绑定仓优先于区县配置，缺仓、库存不足和不合法仓库必须拒绝。
3. 商城下单并确认 3 箱：订单行冻结销售单位与换算关系，库存预留 30 kg；分拣实际发 2 箱，发车出库 20 kg，剩余预留释放。仓库和配送线路必须一致。
4. 分两次退货各 1 箱：每次返库 10 kg；退货申请和批准量按箱计算，库存余额和成本按 kg 计算。超额退货不成立、坏件不返库，仍须跟踪原出库成本。
5. 补并发测试及失败路径：无仓、仓库停用、仓库范围越权、换算因子缺失/错误、四位数量精度溢出、重复幂等请求、历史无换算订单与旧退货。
6. 同步验证迁移 V137 中两个记账字段的空值兼容与收货接口读模型。

验收：所有相关 Spring/DAO 真实 PostgreSQL 集成测试通过，销售、预留、分拣、库存 SALES_OUT / SALES_RETURN_IN 流水和退货明细量对账，不能出现多扣或多返。
