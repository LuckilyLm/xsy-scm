# XSY-SCM 下一阶段开发计划（2026-10-28 现场确认版）

> 更新：2026-10-28。范围以 [产品功能需求基线](requirements/产品功能需求基线.md)、[负责人确认口径](requirements/2026-09-09-负责人确认口径.md)、[2026-10-28 客户现场确认](requirements/2026-10-28-客户现场确认.md) 和 [当前决策](decisions.md) 为准。代码现状与验证证据见 [项目状态](status.md)。
>
> 本计划不再按 13 模块、44 条描述逐条铺开，而是按“现场一天能不能跑通”组织：先补会阻断接单→采购→分拣→配送→结算的缺口，再处理扩展能力。蔬东坡只作常规操作参考，不自动扩展其产品范围。

## 一、目标与范围规则

**目标：一家生鲜配送公司用当前系统完成一个完整作业日，且账、货、单能对上。**

- 已有能力先复用：订单/采购/库存/分拣/财务/打印/商城已有服务与页面，不重造模块或第二套台账。
- 只补真实作业中缺失或会阻断操作的环节；技术正确性、权限、幂等、库存与资金守恒仍是底线。
- 原始需求未明确的审批层级、阈值、全自动流程，优先采用人工确认的最简路径；涉及扣账、授权外部人员、对外公开数据等边界必须先裁定。
- 证据分级：有接口或页面＝“已有源码”；隔离环境流程跑通＝“已联调”；真实岗位操作通过＝“已业务验收”。不以代码量或迁移版本号推算完成度。
- 暂停按 Flyway 版本号排功能；新迁移只服务已确认的 P0 缺口，不改已应用迁移。

## 二、现场作业主链

| 时点 | 现场动作 | 系统对应 |
| --- | --- | --- |
| 14:00 | 采购当天及次日用量，通常多买两天 | 采购汇总/采购单；允许采购量大于已分配需求 |
| 白天 | 按客户公司整单录单 | 销售订单（一客户一单、多行商品） |
| 20:00 | 打印全部客户分拣单/送货单，开始分拣 | 客户分拣单、客户送货单批量打印 |
| 20:00—24:00 | 追单/加单，形成第二批采购 | 加单、二次生成采购需求 |
| 分拣中 | 电子秤称重，秤端确认实际数量 | 秤端工作台 → 实称量回写订单 |
| 次日 | 司机到仓库取货、配送、签收，按实发量结算 | 线路发货、签收、应收、核销/抹零；无配送点、不分仓 |

## 四、批次

### P0 第一批（本轮实施）

按“先能跑一天、再对账”排序：

1. **文档**：现场确认、决策编号、本计划、文档入口。
2. **订单整单录入 + 整单粘贴**：版式列补齐、整单粘贴预览、抽取可复用商品匹配器。
3. **客户分拣单/送货单 + 批量打印 + 采购汇总单**：两种客户级单据、按配送日期/线路批量打印、采购汇总打印。
4. **电子秤授权页与现场核对**：设备/班次页面、单位优先市斤、称重后重印送货单。
5. **负库存 + 损耗报表**：仓库开关、数据库守卫、销售出库放行、月末负库存估算。
6. **采购价 7 天后置 + 采购锁单**：待定价、补价/改价审计、自动回填、人工/自动锁单。
7. **财务自动 FIFO 核销 + 抹零**：自动分配、预览、`WAIVER` 与反向、对账单。

迁移从 V186 起，一个迁移只做一件事，不改已应用迁移。实际落位：

| 版本 | 内容 |
| --- | --- |
| V186 / V187 | 仓库负库存开关 / 余额触发器守卫 |
| V188 | 电子秤设备与班次授权菜单（损耗报表沿用 `scm:report:inventory:query`，未单独建权限） |
| V189 | 客户分拣单 / 客户送货单打印类型与默认模板 |
| V190 / V191 / V192 / V193 | 采购价窗口 / 价格调整审计 / 采购锁单 / 补价与锁单权限 |
| V194 / V195 / V196 / V197 | 抹零表 / 核销来源 `WAIVER` 与财务日志类型 / 抹零权限 / 抹零单号序列 |

执行顺序与每个动作的边界见 `docs/decisions.md` 的 D-1028 系列。

### P0 第二批（2026-10-28 起，先做已裁决项）

已完成：

- **独立退货单（不关联原单）**：按 D-1028-15 实施——客户 + 商品明细建单、最近成交价优先取价、回指定仓库不绑批次与原出库行、审批生成客户级红字并按客户先进先出抵减最早未结应收。迁移 V202–V204。
- **过账特殊单据**：按 D-1028-16 实施——隐藏式财务虚拟单据（登记/修改/作废 + 操作日志 + 列表导出），不生成应收应付、不参与核销；对账单可选择包含过账行，选中时只增加「过账金额」列，不改余额口径。迁移 V207–V209。

待排：

- 财务费用、客户月利润、采购确认/价差与负库存留存已交付源码，验证与迁移仍待执行，见 `docs/status.md` 最新基线。
- 检测报告手机端采集：先验证现有上传/扫码在真实市场报告上的可用性。
- 电子秤 kg→斤显式换算：仅在现场秤不能切市斤时启用。
- 客户类型价与时价深化：现场确认目前只有协议价、几乎不用时价，保留既有解析能力，不做新界面与验收。

### 现场验收（不替代代码验收）

- 电子秤：真实读重、去皮/置零、断网续传、完成、打印、班次过期。
- 打印：A4/针式纸张、分页、签字栏、批量 50+ 单。
- 检测报告：市场灰色纸质报告拍照/转 PDF 后上传，客户扫码可读。
- 负库存：开启仓库后真实销售出库、月末报表与实物盘点口径一致。

## 五、验收与证据

- 每个 P0 项至少具备：后端定向测试或 IT、前端构建/类型检查；E2E 覆盖主链新增分支。
- E2E 自建客户/商品/仓库/订单，不依赖种子数据。
- 统一入口 `tools/verify.ps1 -Scope backend|frontend|e2e|all`；云存储 E2E 显式设置 `XSY_FILE_STORAGE_MODE=cloud`。
- 未执行的测试、未到场的硬件验收必须在 `docs/status.md` 写明“未执行/未验收”，不能以本地通过代替现场通过。
- 真实验收记录写岗位、数据、步骤、结果和问题；只记录“页面存在”不算业务验收。

## 六、暂缓与例外

- 暂缓：复杂审批引擎、自动询价策略、复杂排线、ERP 同步、多企业平台、语音代理、高级增长归因、EPCIS/召回工作台、消费者溯源门户。
- 不删除正常工作的既有代码；冻结扩展不等于破坏历史流水和数据库结构。
- 例外：演示中发现权限越界、库存/金额错账、重复入账或数据泄露，必须立即修复，这属于现有功能质量，不算扩业务。

## 七、下一轮指令

> 按 P0 第一批顺序实施，先文档后代码；每完成一项更新 `docs/status.md` 的证据块。优先复用现有订单、打印、库存、采购、财务服务，不新建平行模型。任何需要改变已确认口径的现场新事实，先补 `docs/decisions.md` 再改代码。未经明确要求不推送、不部署、不操作生产库。
