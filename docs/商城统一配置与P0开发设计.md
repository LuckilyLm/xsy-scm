# 商城统一配置与 P0 开发设计

日期：2026-09-11
状态：已确认，进入实现

## 1. 背景与目标

根据 `docs/功能清单模块.docx`，商城需要支持定制首页、促销活动、新品推荐、分类下单、购物车、再来一单和不同风格主题。参考 `D:/Browser Download/xsy-scm/docs/references/sdongpo` 的只读调查，后台商城装修采用“配置表单 + 手机预览 + 主题设置”的信息组织方式。

本方案的核心目标是：后台只维护一份商城配置，Web 商城和 Taro 小程序商城均从同一套聚合接口读取，避免两端首页、活动、主题和商品展示规则分叉。

## 2. 产品边界

### 本阶段纳入

- 首页 Banner、公告、分类导航、推荐商品、新品/活动板块的统一读取。
- 首页板块排序、启用/停用、生效时间和跳转目标。
- 有效促销活动的统一读取。
- 商城主题配置统一读取：主色、强调色、背景色、卡片圆角、卡片风格、导航风格、商品卡片密度。
- Web 商城首页和小程序首页使用同一数据模型渲染。
- 后台营销配置接口继续承担配置写入；商城聚合接口只返回当前已发布/已生效内容。

### 本阶段不纳入

- 通用低代码拖拽装修器。
- 任意自定义脚本或任意路由拼接。
- Web 与小程序分别维护主题配置。
- 支付、地图路线算法、电子秤和打印机驱动。
- 参考站的节庆模板素材和业务规则直接复制。

## 3. 总体架构

```text
后台运营配置
  ├─ /api/marketing/home-sections
  ├─ /api/marketing/promotions
  └─ /api/marketing/theme（后续可扩展为独立配置管理）
          ↓
     MallHomeService
          ↓
  GET /api/mall/home
          ↓
  ┌─────────────────┬─────────────────┐
  │ Web React 商城   │ Taro 小程序商城  │
  │ CSS Variables    │ 小程序样式映射   │
  └─────────────────┴─────────────────┘
```

聚合接口负责统一板块排序、有效期、活动状态和主题默认值。两端只负责展示和交互，不复制业务判断。

## 4. 统一接口契约

### `GET /api/mall/home`

响应包含：

```ts
interface MallHomeResponse {
  store: { name: string; logoUrl?: string; notice?: string };
  theme: MallThemeConfig;
  sections: MallHomeSection[];
  categories: MallCategory[];
  promotions: MallPromotion[];
}
```

### 主题配置

```ts
interface MallThemeConfig {
  themeCode: string;
  primaryColor: string;
  accentColor: string;
  pageBackground: string;
  cardRadius: number;
  cardStyle: 'flat' | 'shadow' | 'border';
  navigationStyle: 'bottom' | 'top';
  productCardStyle: 'compact' | 'comfortable';
}
```

主题字段使用白名单值。Web 映射为 CSS Variables，小程序映射为页面样式对象或 CSS 变量；禁止任一端自行覆盖业务配置。

### 首页板块

板块至少支持：`BANNER`、`FLASH_SALE`、`NEW_ARRIVAL`、`CATEGORY`、`RECOMMEND`、`CUSTOM`。每个板块包含 `sectionType`、`title`、`sortOrder`、`payload`、`startAt`、`endAt` 和可选的类型化跳转目标。

跳转目标使用白名单枚举：商品、分类、领券中心、公告、仅展示。后台不直接保存任意小程序路径。

## 5. 配置发布规则

- 后台配置可以保存草稿；只有状态为启用且当前时间在生效区间内的板块/活动才进入 `/api/mall/home`。
- 主题外观与促销价格分离，切换主题不得创建或修改促销活动。
- 未配置主题时返回稳定默认主题，保证两端始终可渲染。
- 空板块、失效活动和无效商品引用由聚合层过滤，两端显示空状态而不是错误卡片。
- 聚合接口不返回后台内部字段，不把删除标记、版本号和操作人暴露给商城。

## 6. Web 与小程序一致性规则

1. 两端必须调用同一个 `/api/mall/home` 接口。
2. 两端使用同名字段，不在前端做 snake_case/camelCase 的业务重命名。
3. 两端按 `sections.sortOrder` 渲染首页顺序。
4. 颜色、圆角、卡片风格由 `theme` 驱动。
5. 活动价格、客户价格、库存和可售卖状态仍由服务端决定。
6. Web 和小程序允许有平台差异：Web 使用鼠标/键盘交互，小程序使用触控交互，但内容、顺序和主题语义保持一致。

## 7. P0 开发顺序

### P0-1 统一商城配置

- 后端 `MallHomeService` 和 `/api/mall/home`。
- Web 商城首页、主题映射和路由。
- 小程序首页改为聚合接口驱动。
- 后台营销配置数据与商城聚合结果联调。

### P0-2 分拣

- 任务列表、详情、实重确认、异常差异和打印。

### P0-3 配送

- 线路列表、订单分配、线路详情、轨迹和发货单。

### P0-4 财务报表

- 经营看板、销售/采购明细、应收应付、利润报表和导出。

## 8. 验收标准

- 后端编译通过，`/api/mall/home` 能返回默认主题和配置板块。
- 后台新增/调整启用板块后，Web 与小程序下一次请求读取到相同板块顺序和主题字段。
- 停用或过期板块不出现在商城聚合响应中。
- Web 类型检查和构建通过；小程序类型检查和构建通过。
- 无新增、编辑、删除参考站数据；参考站仅用于页面观察。
- 现有商城登录、客户价格和下单幂等逻辑不被破坏。
