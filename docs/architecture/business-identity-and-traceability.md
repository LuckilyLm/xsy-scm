# 业务身份与追溯架构

更新：2026-11-03，Codex。本文解释当前身份分层与引用关系；规则以 [有效决策](../decisions.md) 为准，实施和验收边界只维护在 [项目状态](../status.md)。

## 身份分层

| 标识 | 用途 | 约束 |
| --- | --- | --- |
| 数据库 ID | 关联实体与源单明细 | 接口中的大整数保持字符串；名称和展示单号不能替代 ID |
| 业务单据号 | 订单、采购、库存、分拣、配送、财务单据 | 新号由 `ScmDocumentNumbers.next()` 生成 `XSY` + 雪花 ID，历史单号保留 |
| 内部主数据码 | 客户、供应商、仓库、商品/规格、分类、标签 | 后端发号，编辑不重编；不因名称、价格或供应商变化改变身份 |
| 外部真实标识 | 条码/GTIN、供应商货号、车牌、税号、来源批号 | 来源方提供，独立校验；内部流水码不宣称为 GS1 标识 |
| 语义配置键 | 计量单位、权限、字典、结算方式等 | 含业务标准语义，不用无意义流水号替代；客户类型已下线 |
| 批次 ID / 批次号 | 同一收货来源的一批商品 | L1 来源维度，一个批次可包含多个包装 |
| `unit_code` | 贴在单个包装实物上的身份 | L2，一码一批，全局唯一、永不复用；不等于公开访问凭据 |
| `public_token` | 包装码公开扫码凭据 | 不用可推算的 `unit_code` 授予公开访问，返回字段按白名单脱敏 |
| `eventKey` / `operationId` | 本机称重事实与请求幂等 | 原号重试，不作为平台正式包装身份 |

内部码默认不作为用户界面展示负担；单据号、追溯码、设备编码和真实外部业务键按用途展示。商品与商品规格在技术字段中仍保留 `spu` / `sku`，界面使用中文术语。

## 单据与事实引用

- 历史单据冻结当时的名称、计量单位、报价、结算主体及必要业务快照，不用当前主档覆盖旧事实。
- 后续动作关联正式来源 ID 和明细 ID，不按同名单据或字符串编号猜测来源。软删除和主档改名不能抹去业务事实。
- 库存流水是追加事实；财务更正追加反向记录。打印记录冻结内容，打印、扫码和补打本身不产生库存或财务动作。
- 供应商货号保留大小写与前导零，仅去首尾空白；它不是商品规格身份，也不用于存储供应商批号。

## L1 批次与 L2 包装

L1 主要由 `xsy_trace_lot`、收货行批次关联、`xsy_inventory_lot_balance` 及批次流水构成；L2 由 `xsy_trace_unit`、`xsy_trace_event`、分拣绑定与更正解绑事实构成。相关基础来自 V151～V158，后续 V173～V177 扩展重量、公开令牌、检测报告与标签能力。

一个包装码只属于一个批次；同批可以有多个包装。包装码绑定分拣任务行，表达当时承诺的客户/订单归属，不直接证明已发车或签收。有效绑定总量不得超过实拣量。

绑错时通过更正申请、他人审批和追加解绑事实处理，保留原记录；原订单行正式出库后不再改绑。作废保留原码且永不复用。数据库锁、唯一性与触发器共同保护并发绑定。

批次级出库只能说明一批货出现在某张出库单，不能倒推其中某一包装已经离场。当前模型不能被宣传为逐包装出库/退回、拆包混批谱系、EPCIS 或复杂召回的完整闭环。

## 秤端与正式标签

- Windows 秤端先将每筐事实、待同步命令及打印选择在 SQLite 原子保存，重试保持原事件键和操作号。
- 每筐经设备 `/measurements` 受理，商品集合完成经 `/items/{taskItemId}/complete` 校验有序事件集合；平台按每筐事实求和，不接受客户端合计替代。
- 本地记录号凭条与正式包装标签分开。正式标签人工选来源批次，请求平台发码后使用返回的包装码、批次和公开链接；本地不自行生成正式 `unit_code`。
- 原始设备读数、人工净重与最终接受的实发量分开。设备稳定不等于员工接受，打印驱动受理不等于物理出纸；手工来源与平台字段映射仍须联调核对。

本地接口和交接边界见 [秤端 README](../../xsy-scale-agent/README.md) 与 [交接清单](../../xsy-scale-agent/FIRST-GENERATION-HANDOFF.md)。

## 公开查询与报告

公开扫码只返回批准的脱敏字段，按令牌/IP 限流并追加查询审计。员工查看仍受角色与仓库范围约束，员工接口不替代公开入口。

批次检测报告保留草稿、发布、撤回和有效期规则；简化市场报告照片库是另一入口，无需批次或发布，上传时间不冒充检测时间。当前新文件统一公开：报告接口可以隐藏撤回/过期附件，已公开对象 URL 本身不具备撤销保密能力；存量私有对象继续按原授权访问。

## 变更边界

保留历史身份、事件与冻结快照，不为整理码制重写旧单据。新的跨全历史唯一约束、外部码映射或逐包装物流规则，需要先核查存量数据和确认范围，再通过新 Flyway 迁移实施；不修改已应用迁移，不为未来目标预建平行账本。
