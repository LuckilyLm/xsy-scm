## 2. `v2/` 工作区结构

```text
v2/
├─ xsy-scm-v2-server/          # Maven 多模块（sa-parent → sa-base + sa-admin）
│  ├─ pom.xml
│  ├─ sa-base/                 # 框架层：common / config / support 模块
│  └─ sa-admin/                # 应用层：module/system/* + module/business/*（SCM 将落在此）
├─ xsy-scm-v2-web/             # Vue3 + TypeScript 管理后台基线（Vite）
├─ tools/                      # 一次性转换/生成脚本（可复现，不参与构建）
└─ .runtime/                   # 本地运行产物（logs / upload / token 等，已 gitignore）
```

`tools/` 内容：

| 脚本 | 作用 |
| --- | --- |
| `pg_convert_mapper_xml.py` | 批量将 mapper XML 的 MySQL 函数改为 PG（`INSTR`→`STRPOS(...) > 0`、`DATE_FORMAT`→`CAST(... AS DATE)`），默认 dry-run，`--apply` 落盘 |
| `pg_seed_convert.py` | 解析 MySQL INSERT 并重发为 PG INSERT（V3 菜单/字典种子使用） |
| `gen_v3_migration.py` | 生成 V3（含 ERP Demo 菜单 47/48/78/79 排除、Argon2 口令哈希、CRLF 归一化） |
| `gen_v5_migration.py` | 从上游 DDL 解析列名与类型，生成 V5 的 23 张表 DDL + 少量系统种子 |
| `Sm4Encrypt.java` | 镜像 `ApiEncryptServiceSmImpl`，生成登录用 SM4 密文（用于端到端验证） |

## 3. Java 21 与依赖版本（Q2）

### 3.1 编译结果

```text
mvn -B -DskipTests compile → BUILD SUCCESS
javac [debug target 21]  sa-base 359 files / sa-admin 177 files
```

**结论：升级到 Java 21 不需要调整 Spring Boot / MyBatis-Plus 或任何其他依赖版本**，因此按 Q2 无需提交版本升级报告。

`pom.xml` 改动仅为：`<name>`/`<description>` 改为 xsy-scm-v2、`<java.version>` 17→21、compiler `source/target` 17→21、移除 `mysql-connector-j` 的 dependencyManagement 条目。

### 3.2 依赖替换（仅驱动与迁移工具）

`sa-base/pom.xml`：`mysql-connector-j` → `org.postgresql:postgresql` + `flyway-core` + `flyway-database-postgresql`。

### 3.3 端口调整（环境事实，非架构变更）

本机 Windows 动态端口范围为 **1024–15000**：

```text
netsh int ipv4 show dynamicport tcp
  启动端口 : 1024
  端口数   : 13977
```

因此上游默认的 `1024`、以及常见的 `8080`/`8081` 均落在临时端口区间，实测 bind 报
`EACCES` / `Port 1024 was already in use`（占用者 `svchost`）。处理：

- 后端 **dev** profile 默认端口改为 **18080**，可通过 `XSY_V2_SERVER_PORT` 覆盖；`pre/test/prod` 保留各自上游值。
- 前端 Vite dev server 默认端口改为 **18081**，可通过 `VITE_DEV_PORT` 覆盖。
- 已写入 `CLAUDE.md`。

### 3.4 其他启动期修复（上游基线固有缺陷）

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| `Profile '@profiles.active@' must start and end with a letter or digit` | 上游根 pom **未继承 `spring-boot-starter-parent`**，`maven-resources-plugin` 无 `@` 分隔符，profile 占位符未替换 | 根 pom 显式声明 `maven-resources-plugin`（`<delimiter>@</delimiter>` + `useDefaultDelimiters`），并固定版本 3.3.1 以便离线构建 |
| 日志目录出现 `sa-admin` 而非项目名 | `dev/application.yaml` 中 `${project.name}` 被 Maven 内置属性解析为模块 artifactId | 改为字面量 `xsy-scm-v2-admin`；`pre/prod` 同步修正 |

### 5.1 转换规则（V1 头部为事实源）

```text
bigint AUTO_INCREMENT  -> BIGINT  GENERATED BY DEFAULT AS IDENTITY
int AUTO_INCREMENT     -> INTEGER GENERATED BY DEFAULT AS IDENTITY
tinyint(1) 0/1         -> BOOLEAN
tinyint 其他 / unsigned -> SMALLINT
int                    -> INTEGER
datetime / datetime(n) -> TIMESTAMP
date                   -> DATE
text / longtext        -> TEXT
json                   -> JSONB
ENGINE/CHARSET/COLLATE/ROW_FORMAT/USING BTREE/显示宽度 -> 移除
ON UPDATE CURRENT_TIMESTAMP -> 移除（MyBatis-Plus 默认 NOT_NULL 字段策略 + DB 默认值兜底）
显式主键插入后 -> setval(pg_get_serial_sequence(...), (MAX+1), false)
```

### 5.2 系统表清单（`xsy_v2` 共 43 张 = 42 业务表 + `flyway_schema_history`）

**覆盖了全部 36 个 `@TableName` 实体 + 上游 44 张表中除 `t_category` / `t_goods` 外的全部表**。
`t_category` / `t_goods` 是上游演示业务表（V2 无对应实体、菜单树无引用），不迁移。

**种子数据策略**：只迁移真正的系统参考数据。上游演示内容（`t_change_log` 11 行、`t_data_tracer` 10 行、`t_notice` 12 行、`t_message` 4 行、`t_oa_*`、帮助文档正文）**不迁移** —— V2 是干净基线，不是 demo 副本。

### 5.3 有意保留的差异（非机械复制）

1. `t_serial_number_record`：上游仅有非唯一索引 `uk_generator(serial_number_id, record_date)`，但 `SerialNumberBaseService.saveRecord()` 的语义是「先 update，影响行数为 0 才 insert」，该组合是事实上的自然唯一键 → V2 提升为 **UNIQUE 约束**，防止并发写入重复日计数行。
2. `t_reload_result`：上游无索引，唯一查询是 `where tag = ?` → 补 `idx_t_reload_result_tag`。
3. `t_operate_log`：上游无索引 → 补 `create_time` 与 `(operate_user_id, operate_user_type)` 索引。
4. `t_config.config_key`：上游无唯一约束 → V3 补 `uk_t_config_key UNIQUE (config_key)`。
5. `t_menu` / `t_role_menu`：`role_menu` 补 `(role_id, menu_id)` 唯一约束。

## 7. 登录 / RBAC 验证结果（Q4 / Q5 / Q6）

### 7.1 登录链路

```text
GET  /login/getCaptcha        → code=0，返回 captchaUuid + captchaText（非 prod 明文）+ base64 图片
POST /login                   → code=0，返回 employeeId/loginName/actualName/departmentName/
                                administratorFlag/token/menuList

GET  /login/logout            → 待验证（不影响 W0 验收）
```

- Token：Sa-Token `Authorization: Bearer <token>`，`simple-uuid`，30 天，状态存 Redis。

| `nullStaysNull` | `null` 序列化为 JSON `null`，**不是** `0` |
| `zeroIsZeroString` | `0` 序列化为 `"0.0000"` |
| `nullAndZeroAreDistinguishable` | 两者结果不同（`null` vs `"0.0000"`） |
| `scaleAndRounding` | 4 位小数、`HALF_UP` |
| `usingDoesNotAffectNull` | `@JsonSerialize(using=...)` **不作用于 null** |
| `nullsUsingLosesNull` | 只有 `nullsUsing=...` 才会把 null 变成 0 —— 因此**禁止**对 SCM 字段使用 `BigDecimalNullZeroSerializer` |
| `scmPackageMustNotUseNullZeroSerializer` | 类路径扫描 `net.lab1024.sa.admin.module.scm`，断言**无任何类/字段**使用 `BigDecimalNullZeroSerializer` |

**重要发现（已写入序列化器 Javadoc）**：Jackson 的 `@JsonSerialize(using = X)` 不作用于 null；只有 `nullsUsing = X` 才作用于 null。因此 `BigDecimalNullZeroSerializer` 的危险面**仅**在 `nullsUsing` 场景，V2 通过扫描测试把该风险固化为门禁。

SCM 对外契约保持不变：**数量与金额统一为 4 位小数字符串**，`null` / `UNPRICED` 与 `0` 元严格区分。

7. **迁移纪律**：Flyway 只追加；新增表/字段一律走 `V6+` 迁移，不修改已应用的 V1–V5。
8. **不修改 legacy**：`xsy-scm-server` / `xsy-scm-web` / `xsy-scm-miniapp` 只读，仅作业务与 UI 参考；禁止机械 React→Vue 翻译。
