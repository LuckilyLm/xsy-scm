### 2.2 分层职责（对齐 SmartAdmin ERP 范式）

| 层 | 职责 | 不做什么 |
|---|---|---|
| Controller | 权限注解、参数校验、调用 Service、返回 `ResponseDTO` | 不写业务规则 |
| Service | 事务边界、聚合编排、调用 Manager/DAO | 不拼 SQL |
| Manager | 单条业务规则（校验器、差量同步） | 不控制事务 |
| DAO | 数据访问（`BaseMapper` + XML） | 不含业务判断 |

### 2.3 数据模型（SPU 聚合根）

```
product_category (自引用树, level 1..3)
        ▲ category_id
product_spu  ──1:N──▶ product_sku      (交易实体, 恰好 1 个 is_default)
             ──1:N──▶ product_image    (图集, 至多 1 个 is_primary)
```

SPU 是聚合根；SKU 与图片是聚合内实体。**跨域只引用 SKU**（后续波次的订单/采购/库存/称重均以 SKU 为维度），图片与分类不被跨域引用。

## 3. Migration 设计

### 3.1 命名与数量约束

- 只允许**两个**迁移文件：`V6__scm_product.sql`（全部 DDL + 分类种子）、`V7__scm_product_permissions.sql`（菜单与权限种子）。不允许每表一个迁移。
- 表名沿用 legacy 词汇（`product_category` / `product_spu` / `product_sku`），新增 `product_image`。schema 为 `xsy_v2`，与 legacy `public` schema 完全隔离，无命名冲突。
- Flyway 是唯一 schema 演进机制；已应用的迁移不可修改。

## 4. 后端设计

### 4.1 API 契约（SmartAdmin 风格，统一 `/scm/product`）

| 方法 | 路径 | 请求体 | 响应 | 权限 |
|---|---|---|---|---|
| POST | `/scm/product/query` | `ProductSpuQueryForm`（继承 `PageParam`） | `ResponseDTO<PageResult<ProductSpuVO>>` | `scm:product:query` |
| GET | `/scm/product/detail/{spuId}` | — | `ResponseDTO<ProductSpuDetailVO>` | `scm:product:query` |
| POST | `/scm/product/add` | `ProductSpuAddForm` | `ResponseDTO<Long>` | `scm:product:add` |
| POST | `/scm/product/update` | `ProductSpuUpdateForm` | `ResponseDTO<String>` | `scm:product:update` |
| POST | `/scm/product/updateStatus` | `ProductStatusForm` | `ResponseDTO<String>` | `scm:product:status` |
| POST | `/scm/product/delete` | `ProductDeleteForm` | `ResponseDTO<String>` | `scm:product:delete` |
| POST | `/scm/product/category/tree` | `{}` | `ResponseDTO<List<ProductCategoryTreeVO>>` | `scm:product:category:query` |
| GET | `/scm/product/category/{categoryId}` | — | `ResponseDTO<ProductCategoryVO>` | `scm:product:category:query` |
| POST | `/scm/product/category/add` | `ProductCategoryAddForm` | `ResponseDTO<Long>` | `scm:product:category:add` |
| POST | `/scm/product/category/update` | `ProductCategoryUpdateForm` | `ResponseDTO<String>` | `scm:product:category:update` |
| POST | `/scm/product/category/delete` | `ProductCategoryDeleteForm` | `ResponseDTO<String>` | `scm:product:category:delete` |

设计要点：
- 查询用 POST + 表单体，与 SmartAdmin ERP 一致，便于 `PageParam` 的 `sortItemList` 传递。
- **删除与改状态都通过 body 传 `{id, version}`**，统一乐观锁入口（修正 legacy D11）。
- 分类树的树查询在 SmartAdmin 中是 POST（`/category/tree`），保持一致。
- 所有写接口加 `@OperateLog`。

### 4.2 关键 VO 字段

`ProductSpuVO`（列表行）：`spuId, version, spuCode, name, alias, categoryId, categoryName, categoryPath, status, skuCount, defaultSku(ProductSkuVO), minMarketPrice, maxMarketPrice, primaryImageUrl, updatedAt, skuList(List<ProductSkuVO>)`。

`ProductSpuDetailVO`：`spuId, version, spuCode, name, alias, categoryId, categoryPath, description, status, images(List<ProductImageVO>), skuList(List<ProductSkuVO>), createdAt, updatedAt`。

`ProductSkuVO`：`skuId, version, skuCode, barcode, specName, specValues(Map<String,String>), saleUnit, productType, marketPrice(String), status, defaultFlag, sortOrder`。

`ProductImageVO`：`imageId, version, fileKey, fileUrl, fileName, fileSize, primaryFlag, sortOrder`。

**定点数契约**：`marketPrice` / `minMarketPrice` / `maxMarketPrice` 一律为 **4 位小数字符串**，由 `ScmFixedScale4Serializer`（`setScale(4, HALF_UP)`）序列化，`null` 保持 `null`，与 `0.0000` 严格区分（修正 legacy D2）。

### 4.3 业务不变量 → 实现映射

| # | 不变量 | V2 实现 |
|---|---|---|
| P1 | SPU ≥ 1 SKU | `ProductAggregateValidator.validateSpu`：`skuList` 空 → 40020 |
| P2 | 恰好 1 个默认 SKU | 同校验器：`count(defaultFlag) != 1` → 40021 |
| P3 | 默认 SKU DB 兜底唯一 | `uk_product_sku_default_active` partial unique |
| P4 | 分类最多三级 | `ProductCategoryService.resolveLevel`（父级 +1，> 3 → 40010） |
| P5 | 只能挂已启用三级分类 | `requireSelectableCategory`（level != 3 或 status != ENABLED → 40011） |
| P6 | 分类有子/有商品禁删 | `countActiveChildren` → 40910；`countActiveProducts` → 40911 |
| P7 | 停用分类下不可加子分类 | `resolveLevel` 校验父级 status → 40011 |
| P8 | SKU 差量同步 | `ProductSkuChangeSet.between(existing, requested)` → insert/update/remove 三组 |
| P9 | 保留已存在 SKU 的 id/version | `updated` 组走 `updateById`，id/version 来自请求 |
| P10 | 禁止 delete-and-recreate | 只有 `removedIds` 走软删；不在请求中的已存在行才进 `removedIds` |
| P11 | SKU 不属于该 SPU 则拒绝 | `between` 中未命中 `existing` 的 id → 40920 |
| P12 | 默认切换 = 先清空后置位 | 事务内顺序：`clearDefault(spuId)` → 更新 `updated` 组 → 插入 `inserted` 组 → 软删 `removedIds` |
| P13 | 至少保留 1 个 SKU | 前端禁用 + 后端 40020 双保险 |
| P14 | 删默认 SKU 后首个剩余成为默认 | 前端 `removeSku` 规则；后端由 P2 校验兜底 |
| P15 | 新增自动带 1 个默认 SKU | 前端 `createEmptyProductForm`；后端不假设 |
| P16 | SKU 编码大小写不敏感去重 | `normalizeCode = trim().toUpperCase()` |
| P17 | 条码非空才去重 | `trimToNull` 后判空 |
| P18 | 规格组合归一化去重 | key/value 均 trim + 小写，`TreeMap` 排序后比较 |
| P19 | 市场价 ≥ 0 | `@DecimalMin("0.0000")` + 校验器 + DB CHECK |
| P20 | 搜索覆盖 SPU 编码/名称/别名 + SKU 编码/条码 | `ProductSpuDao.xml`：`ILIKE` + `EXISTS` 子查询 |
| P21 | 列表不 N+1 | 分页取 SPU → 批量取 SKU/图片/分类 → 内存分组 |
| P22 | 详情返回 JSONB 规格 | `ProductSkuEntity.specValues` 用 `JsonbStringMapTypeHandler` |
| P23 | 删除后编码可复用 | 全部唯一索引带 `WHERE deleted = FALSE` |
| P24 | SPU/SKU 各自乐观锁 | 两者均 `@Version`；冲突 → 40921 |
| P25 | 审计字段为真实操作人 | `ScmOperator.current()` 写入 created_by/updated_by（修正 D1） |
| P26 | 图片至多一张主图 | `uk_product_image_primary_active` + 校验器 |

### 4.4 乐观锁与软删除的实现前提（**必须修的 V2 基线缺口**）

审计确认 V2 基线当前**缺少两项 MyBatis-Plus 能力**，不补则 P24/P23 无法成立：

| 缺口 | 现状 | 处置 |
|---|---|---|
| **G1 无 `OptimisticLockerInnerInterceptor`** | `MybatisPlusConfig` 只注册了 `PaginationInnerInterceptor(POSTGRE_SQL)`，全仓无 `OptimisticLocker` 引用 → `@Version` 完全无效，`updateById` 不会带 `WHERE version = ?`，也不会自增 | 在 `sa-base/.../config/MybatisPlusConfig.java` 增加 `OptimisticLockerInnerInterceptor` 并 `addInnerInterceptor` |
| **G2 无逻辑删除配置** | 全仓无 `@TableLogic`、无 `mybatis-plus.global-config.db-config` 配置 | 在每个 SCM 实体上用 `@TableLogic(value = "false", delval = "true")` 显式声明（自包含，不改全局配置，避免影响 SmartAdmin 既有 `deleted_flag` 手工软删约定） |

其它需要同步修正的基线缺口：

| 缺口 | 现状 | 处置 |
|---|---|---|
| **G3 test profile 无 Flyway** | `sa-base/src/main/resources/test/sa-base.yaml` 无 `spring.flyway` 段 → PG 集成测试不会应用 V6/V7 | 为 test profile 补 `spring.flyway`（与 dev 同参数），使 IT 自洽 |
| **G4 sa-admin test 配置未对齐** | `sa-admin/src/main/resources/test/application.yaml` 仍是上游默认（`project.name: sa-admin`、`port: 11024`） | 对齐为 V2 命名与端口（18082，避免与 dev 18080 冲突） |

### 4.5 错误码与 40921 语义

`ProductErrorCode` 枚举（`code / msg / level`）：完整保留 legacy 的 40010/40011/40020–40025/40410/40420/40910/40911/40920，以及 **40921**（`"数据已被其他操作修改，请刷新后重试"`）。

`ScmBusinessException extends BusinessException` 携带 `ScmErrorCode`；`ScmExceptionHandler` 用 `@Order(Ordered.HIGHEST_PRECEDENCE)` 保证优先于 `GlobalExceptionHandler` 的 `BusinessException` 分支。

**HTTP 状态约定（与 legacy 的差异，需确认）**：SmartAdmin 统一以 HTTP 200 + `ResponseDTO` 信封表达业务错误（`GlobalExceptionHandler` 不设 `@ResponseStatus`），且 V2 前端 `lib/axios.ts` 的**响应错误分支只显示通用文案**（"网络发生错误"），只有 **2xx 响应体里的 `code`/`msg`** 才会展示为业务提示。因此：

- 版本冲突返回 **HTTP 200 + `{code: 40921, msg: "数据已被其他操作修改，请刷新后重试"}`**，前端能正确提示。
- 即**保留 40921 的语义与码值**，但**不沿用 legacy 的 HTTP 409 状态码**（沿用会退化为通用网络错误提示）。
- 若要求同时保留 HTTP 409，则需要改动共享的 `lib/axios.ts` 错误分支，会影响全部模块——**默认不做**，列为待确认项。

### 4.6 事务与并发顺序（修正 legacy D4）

`ProductSpuService.update` 事务内固定顺序：

1. `validator.validateSpu(form)`（P1/P2/P16–P19/P26）
2. `categoryService.requireSelectableCategory(categoryId)`（P5）
3. 读取当前 SPU（含 `deleted` 判定）→ 40420
4. `form.version` 为空 → 40921
5. 读取现有 SKU（`deleted = FALSE`，按 `sort_order, id`）→ `ProductSkuChangeSet.between`（P8/P11）
6. 读取现有图片 → `ProductImageChangeSet.between`
7. `spuDao.updateById(spu)`（带 `@Version`）≠ 1 → 40921
8. `skuDao.clearDefault(spuId)`（P12 第一步）
9. 逐条 `updateById(updated)`（各带 `@Version`）≠ 1 → 40921
10. 逐条 `insert(inserted)`
11. `deleteByIds(removedIds)`（软删）
12. 图片：`updateById` / `insert` / `deleteByIds` 同法
13. `@OperateLog` 由 AOP 记录

任一步失败整体回滚。

### 4.7 查询实现要点

`ProductSpuDao.xml` 的 `queryPage`：
- 基础条件：`p.deleted = FALSE`
- `keyword`：`p.spu_code / p.name / p.alias ILIKE`，或 `EXISTS(product_sku s WHERE s.spu_id = p.id AND s.deleted = FALSE AND (s.sku_code / s.barcode ILIKE))`
- `categoryId`：**含子分类**（选一级/二级也能筛出三级商品）——用 `p.category_id = ? OR p.category_id IN (子分类 id)`，子分类 id 由 `ProductCategoryService` 在内存解析后传入；这是对 legacy「只匹配精确 category_id」的**行为增强**，需在验收报告标注
- `status` / `skuStatus` / `productType`：`EXISTS` 子查询
- 排序：默认 `p.updated_at DESC, p.id DESC`，支持 `PageParam.sortItemList` 白名单（`spu_code`/`name`/`updated_at`/`status`）
- 批量补充：`skuDao.selectActiveBySpuIds`、`imageDao.selectActiveBySpuIds`、分类 map 一次性载入（P21）
