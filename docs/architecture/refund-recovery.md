# 退款派发、查单与财务完成

## 持久化边界

退款申请与冻结分摊先在业务事务中提交。`xsy_payment_refund.refund_no` 是持久化的渠道幂等号，重试、进程重启和渠道查单均沿用它。受理接口返回 `PROCESSING`，不把受理成功解释为资金已退回。处理中退款按申请额占用可退本金，成功后改按渠道实退额计算，避免异步窗口内再次占用同一本金。

`PaymentRefundRecoveryJob` 只读取已提交的退款记录。`PaymentRefundRecoveryService` 禁止外层事务，先在短事务内取得恢复租约并追加 STARTED 审计，再在事务外向渠道查单；只有渠道明确返回不存在时，才用原退款号幂等派发。查询异常不等于不存在，不另建退款号。

渠道结果通过 `PaymentRefundService.applyOutcome` 落库。落账失败不会删除已提交的本地退款意图，后续恢复先按原号查询渠道。生产渠道实现必须支持按商户退款号查单、同号幂等及有界的网络超时；目前仓库只有 Mock 实现，真实渠道仍需接入与验收。

## 财务与余额

- 回调、主动查单与钱包返还统一在订单锁内推进。退款分摊先锁订单，再按固定顺序锁退款，不先独占单张退款后争抢订单锁。
- 分摊执行沿用「部分来源成功、失败来源可重试」的既有口径。余额返还与在线退款准备分别在外层订单事务内使用 JDBC 保存点；子服务抛出异常时只回滚该来源的写入，再由外层将分摊行记为 `FAILED`。这不新开连接、不提前释放订单锁。外层其他数据库操作失败时仍整笔回滚，不伪造部分成功。该保存点行为的 PostgreSQL 用例已写入源码，尚未运行。
- 最后一笔来源成功后，`RefundFundingCompletionService` 自动登记唯一 `ORDER_REFUND` Finance 付款，无需再点击执行。Finance 重新读取渠道实退或钱包 CREDIT 验证成功事实、客户与金额；系统派生不依赖员工会话，人工付款仍执行原权限与范围规则。
- 实退金额与申请额或冻结分摊不一致时，保留渠道事实，不把分摊标为成功，也不自动补退、冲账或覆盖历史成功金额。矛盾结果留审计并通知原发起人，由有权人员核对渠道与财务事实。
- 纯余额退款沿用已确认的自动返还规则：订单退款完成时，同事务追加原钱包 CREDIT。显式余额接口保留为恢复入口。混合资金或已有分摊计划的订单不从该路径猜测返还份额。
- 旧钱包、旧渠道及人工退款与新分摊路径双向互斥。旧记录未保存逐来源分配，已有旧路径退款的订单不能直接切到新分摊路径；历史事实不自动迁移或重新分配。

## 恢复与操作入口

V125 增加恢复租约、重试时间与追加审计表，不修改历史迁移。V125 把外键内联进了恢复日志的列定义，成为全库唯一一个外键；V127 移除该约束（表、索引与追加审计触发器保持不变），引用完整性继续由服务层守卫承担，见[底座规则](smartadmin-foundation.md)。

- `scm.payment.refund-recovery.enabled` 默认 `true`；默认每 30 秒扫描最多 50 条到期退款。
- 每条记录使用 10 分钟租约，重试间隔逐步增长，最大 1 小时。进程中断后租约到期可继续恢复；渠道幂等仍是重复出款的最终保护。
- 渠道明确失败、金额不一致或连续未完成会向原发起员工发送去重站内信。失败退款不自动再次派发；有权人员通过资金分摊执行入口重试失败来源，仍复用原退款编号。
- `POST /scm/payment/refund/recover`：输入 `refundId` 与必填 `reason`，复用退款创建权限，并检查订单及客户范围；立即查单/恢复，受租约约束，不允许输入或覆盖金额。
- `GET /scm/payment/refund/{refundId}/recovery-log`：复用退款查询权限及数据范围，返回最近 100 条恢复审计。
- 退款查询额外返回渠道实退额、恢复次数、结果、说明和下次恢复时间。界面之外也可通过上述 API 审计人工恢复。

## 当前验证边界

V125 与 V127 已在新建隔离库执行：空库从零应用 V1～V127（127/127 success、全库 0 外键），`xsy_v2_it` 从 V126 增量应用 V127。本设计的 13 个 PG 集成用例（`PaymentRefundRecoveryPgIT`，含外键移除后追加审计与不可改写仍生效的回归）在隔离库全绿，结果见[项目状态](../status.md)。

仍未覆盖：真实支付渠道联调（渠道为本地模拟实现）；渠道侧对账与人工核销的实际操作流程。历史上的 2026-10-12 22:45 复审记录中的 29 个单测属于当时工作区，不覆盖持久化派发、恢复任务与自动入账这部分修改。
