# SCM 管理后台 UI 规范

状态：当前长期规则。
适用范围：`xsy-scm-web/src/views/business/scm/**`。SmartAdmin 系统页只在共享主题层遵守通用规则，不机械套用 SCM 业务页面结构。

本文件只保存已经落地、需要长期维持的 UI 约束。阶段性审计、逐页映射和“当时还有哪些页面没改”不在这里维护。

## 1. 基础资产

共享样式与能力优先放在：

- `src/theme/scm/`：表格、详情、表单、响应式、状态、Drawer 宽度等主题规则。
- `src/components/business/scm/`：具有明确复用价值的 SCM 组件。
- 页面只组合业务语义；不要重新声明已有的通用按钮、数字、状态、复合单元或 Drawer 宽度样式。

不为了“组件化”把一两行模板包装成新组件；只有行为、样式和约束需要跨页面共同维护时才抽公共组件。

## 2. 列表信息层级

- 首屏优先业务名称、状态、核心数量/金额和当前动作。桌面宽表中，名称、编码、联系人、电话等可独立比较的属性应分列；低频编码可通过 TableOperator 隐藏或重新显示。
- `.scm-cell-stack` 仅用于窄屏合并字段或明确的主次信息，不用它替代桌面端可独立阅读的列：
  - 主行：14px / 中等字重 / 主文字色。
  - 副行：12px / secondary 色。
  - 主行可点击时使用 `.scm-cell-link`，默认保持主文字色，hover/focus 才呈现品牌链接反馈。
- 复合单元的两行必须共享左轴；不要把主行居中、副行左对齐。联系人电话等数字标识使用 tabular-nums。
- 表头统一居中；内容按语义对齐：普通文本左、金额/数量右、状态/单位/操作中。
- 普通业务列表不长期占用“创建时间/更新时间/内部 id”大列；日志、流水和审计页面按业务需要保留时间与编号。

## 3. 金额、数量与标识

只使用三类公共数字样式：

| class | 用途 |
| --- | --- |
| `.scm-money` | 金额、单价、成本、应收应付、收付款 |
| `.scm-quantity` | 数量、库存、件数、比例、统计计数 |
| `.scm-mono` | 单据号、编码、外部流水号等需要逐位抄录/比对的标识 |

判断顺序是“钱 → 量/比例 → 标识 → 普通文本”，不是“长得像数字就用 mono”。

禁止在业务页面重新定义 `.num`；金额和数量使用比例字体 + tabular-nums，标识才使用真正的等宽字体。

## 4. 操作列

- 操作列显式居中，常规宽度控制在约 120～160px；契约测试当前上限为 180px。
- 当前状态下的**下一步业务动作**应优先常驻，不机械把所有写动作都塞进“更多”。
- 详情等高频只读入口可常驻；低频、危险或不属于当前下一步的动作放入 `ScmActionMore`。
- 一组完全平级的入口可以用语义化菜单名（如“下钻”），不要为了形式硬选两个做主动作。
- 权限裁剪在生成 action 时完成；收纳菜单不能让原本无权限的动作重新出现。
- 危险动作仍由调用方负责确认，菜单组件只负责展示与派发。

## 5. Drawer 宽度

所有 SCM `<a-drawer>` 通过 `scmDrawerWidth()` 取值，不在页面硬编码宽度，也不写 `min(NNNpx, 96vw)`。视口兜底统一由 `theme/scm/responsive.less` 提供。

| 等级 | 宽度 | 用途 |
| --- | ---: | --- |
| `s` | 600 | 简单配置、简单维护、单列只读详情 |
| `m` | 780 | 中型主数据、常规编辑表单 |
| `l` | 940 | 复杂业务编辑表单 |
| `xl` | 1120 | 复杂详情、内嵌宽表、多明细业务 |
| `workspace` | 1440 | 受限工作台，横向空间本身就是业务内容 |

`workspace` 不是普通第五档，只允许以下四类：

1. 分拣 / 称重工作台；
2. 报表下钻；
3. 超宽业务数据阅读；
4. 多面板业务工作台。

复杂业务详情（多 Tab 工作台，如配送线路详情）改用独立页面承载，不再占用本档；本档不新增用例，存量用例随页面化逐步移除。

当前白名单由 `test/scm-drawer-width-contract.test.mjs` 直接钉住。新增 `workspace` 用例必须同时说明属于哪一类并更新契约；普通表单、配置页和普通详情不得用扩大宽度掩盖信息架构问题。

## 6. 表单与详情

- 复杂表单按业务 Section 分区，Footer 右对齐，保存为主动作，取消为普通动作。
- 危险动作不与保存按钮放在同一主操作区。
- 数量、金额、比例等输入使用与业务语义匹配的数字控件，并在输入附近展示单位。
- 多 Tab 的复杂业务详情使用独立页面（列表以 `?tab=` 深链进入），不得用 Drawer 模拟页面；Drawer 只承载创建 / 编辑表单与轻量查看。
- 详情页正文按 `.scm-detail-header / .scm-summary / .scm-detail-card / .scm-field-list` 组织；单条记录的基础信息用 label / value，不用表格。少量行（≤3）的明细 Tab 用轻量卡片列表，行数多才切表格；空态说明下一步动作，禁用按钮旁写明原因。
- 系统内部编码（客户 / 供应商 / 仓库等）由服务端生成：表单不提供输入框，创建时显示「保存后由系统自动生成」，编辑时只读展示。
- 详情页优先采用“身份头部 → 核心摘要 → 业务分区 / 明细 → 日志 → 系统信息”的层级。
- 只读 360 详情可把身份头部放在 Tabs 上方，使用户切换上下文时仍知道自己在看哪个对象。
- 详情页不得为了“看起来完整”伪造销售额、应收、库存或配送状态；后端没有正式字段时登记到[后端字段缺口](../plan/active/frontend-ui-backend-gap-inventory.md)。

## 7. 状态与响应式

- 状态使用统一色语义并同时显示文本，不只靠颜色表达。
- 768px 等窄屏下表单退回单列；Drawer / Modal 最大宽度统一受 96vw 约束。
- 不通过隐藏溢出把操作按钮“裁掉”；真正解决列宽和动作层级。

## 8. 文案与信息层级

**默认不解释。只有「不告诉用户就可能操作错误」的信息才进入主界面。**

> 不要为了证明系统设计严谨，而让 UI 替代码写设计文档。
> 代码注释、ADR、测试负责解释「为什么」；业务 UI 负责告诉用户「现在能做什么」。

源码注释的同类规则见[源码注释规范](code-comment-guidelines.md)：UI 文案不该把设计推导给用户看，源码注释不该把开发过程给开发者看。

### 8.1 判定规则

| 情况 | 处理 |
| --- | --- |
| 数据库、事务、字段、真值来源、前后端精度、DTO、枚举名、错误码 | UI 删除 |
| 用户看控件本身就知道怎么操作 | 删除说明 |
| 对正常状态进行解释（「只读」「不可编辑」） | 删除 |
| 「这是只读页面」「这里用于……」自我介绍 | 删除 |
| 示例值（`如 UOM-KG`） | 改用 `placeholder`，不再额外占一行 `help` |
| 不影响当前操作结果的业务背景 | 删除，或收进帮助文档 |
| 报表统计口径 | 默认不解释；确需解释且不告知会改变用户决策时才用 `report-note`（见 §8.3） |
| 禁用按钮的原因 | `Tooltip` 保留 |
| 当前数据异常、缺失、权限不足 | Warning 保留 |
| 操作不可逆、会清空/覆盖数据 | 改为**操作时确认**，不长期挂 Alert |
| 导入文件格式、大小等操作必需规则 | 保留，压缩到 1～2 行 |
| API/网络/校验失败 | Error Alert 保留 |
| 成功结果 | Toast / Result 保留 |

**新增常驻 `info alert` 或表单 `help` 需在 PR 说明理由**（说明「不告知会导致什么操作错误」）；新增常驻解释性文案要同时更新 `test/scm-ui-copy-contract.test.mjs` 的基线，棘轮只降不升。

### 8.2 术语与形态黑名单

UI 可见文案（渲染文本节点，以及 `message` / `description` / `help` / `placeholder` / `label` / `title` / `extra` / `empty-text` 属性值）中禁止出现：

- 模块名与阶段代号：`Finance`、`R0` / `R1` / `R2`、`§` 计划章节号；
- 违反用词规则的术语：`SPU` / `SKU` / `品规` / `货品` / `单品`（见 [AGENTS.md](../../AGENTS.md) 用词规则）；
- 字段名：`path`、`parent_id`、`seller_id`、`fileKey`、`occurred_at`、`createTime`；
- 枚举名：`PURCHASE_IN`、`SALES_OUT`、`DIRECT`、`WAREHOUSE_CONFIRM`；
- 错误码：`40989`、`40995`；
- 实现词：`数据库`、`事务`、`幂等`、`真值`、`精度`、`后端`、`前端`、`服务端`、`客户端`、`VO`。

**不算违规、测试会放过**：Vue 组件标签名（`<FinanceDetailDrawer>`）、SVG 属性（`<path d="…">`）、`v-for :key` 里的技术标识（`:key="image.fileKey"`）、源码注释与 `<script>`。

### 8.3 报表口径说明

**报表默认不解释口径**：统计口径既不常驻正文，也不做成指标卡的 `ⓘ`。报表页里多数「口径」写的是程序怎么算出来的（SQL、枚举名、字段名、推导链），属于 §8.2 黑名单；剩下的是「这个数字是什么意思」，那应该先把指标名改到自解释，而不是补一句说明。

| 情况 | 处理 |
| --- | --- |
| 指标名本身 | 指标名自解释；要靠 Tooltip 才能读懂，先改指标名 |
| 数据缺失、成本不完整、权限受限 | Warning 保留（见 §8.1），只在真的发生时出现 |
| 确需解释，且不告知会改变用户决策 | 才用 `report-note`：Popover 最多 3 条、每条 ≤ 40 字；长文用 `sections` 分组（指标定义 / 统计时点 / 统计范围 / 特殊情况） |

`test/scm-ui-copy-contract.test.mjs` 钉住报表模块的 `report-note` 与 `hint` 归零；要新增必须先在 PR 说明「不告知会导致什么操作错误」。
