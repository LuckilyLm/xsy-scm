## 6. 冻结与边界

- V1–V12：与 PostgreSQL Closure 清单 **12/12 一致**，未修改。
- V13/V14：已由 Flyway 应用，冻结于 [w4-applied-migrations.sha256](./w4-applied-migrations.sha256)。后续只追加新 migration。
- Product / Customer / Pricing、sa-base、系统域、C 上游参考、小程序：源码零修改。客户引用保护实现在订单域适配器中。
- 没有 W5 采购实现、库存实现、支付渠道、会计凭证、业务员 DataScope 或新的履约状态。

实现说明：实际增加 8 份 XML（地址 DAO 也有独立 XML）；详情以 Drawer 复用列表上下文，四个列表路由由 SmartAdmin 菜单生成，router core 零修改；实际数量更新同时推进聚合版本；幂等 key 作用域包含操作者。

## 7. 已知限制与运行环境

1. 日志 append-only 由应用入口/DAO 保证，未新增 DB trigger；不声称能阻止管理员直连数据库修改。符合本设计不加触发器的边界。
2. 当前 W1 的 SKU market_price 非空，实际可售 SKU 通常可解析市场价。OrderUnpricedIT 通过 spy 注入 W3 的正式 UNPRICED 响应，在真实 PG 上验证 NULL 存储、同空 CHECK、序列化及提交拒绝；未修改 Product/Pricing 来造数据。
3. 一个订单一个创建时地址；无真实库存/支付/履约。全零退款金额按既有 Target Design 拒绝批准，未扩展零金额退款语义。
4. 幂等记录/业务日志本波次不做 TTL/归档；数据权限留后续独立能力。测试使用隔离名称的本地业务夹具，临时登录账号已清理，已确认单据保留作验收记录。
5. 本机 PostgreSQL、后端 18080、前端 18081 保持运行以供检查；未改服务配置。构建的既有大 chunk 提示、Flyway 对 PG18 的版本提示未触发依赖升级。
