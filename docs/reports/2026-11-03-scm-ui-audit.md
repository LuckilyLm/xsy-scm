## 二、问题与修复

### P0：撤销类确认框没有等待用户选择，撤销会直接执行

**问题**

`Modal.confirm` 在 Ant Design Vue 中返回 `{destroy, update}` 销毁句柄，不是 Promise。原代码使用：

```ts
await Modal.confirm({...});
await revokeApi(id);
```

`await` 一个非 Promise 会立即继续，确认框还显示在屏幕上时撤销请求已经发出。用户点“取消”也无法阻止。

受影响位置：

- `xsy-scm-web/src/views/business/scm/customer/components/customer-promotion-modal.vue`：撤销推广码
- `xsy-scm-web/src/views/business/scm/purchase/components/purchase-share-modal.vue`：撤销采购分享链接
- `xsy-scm-web/src/views/business/scm/product/components/product-form-drawer.vue`：关闭前“放弃未保存修改”判断同样会立即放行，导致抽屉直接关闭

**修复**

在 `scm-unsaved-guard.ts` 中增加统一的 Promise 包装：

```ts
export function confirmDialog(options: ModalFuncProps): Promise<boolean> {
  return new Promise((resolve) => {
    Modal.confirm({
      ...options,
      onOk: () => resolve(true),
      onCancel: () => resolve(false),
    });
  });
}
```

三处调用改为等待真实选择：

```ts
const confirmed = await confirmDialog({...});
if (!confirmed) return;
```

**结果**

- 点“取消/继续编辑”不会执行撤销，也不会关闭抽屉。
- 点“确认撤销/放弃修改”才继续原操作。

### P1：表单抽屉关闭时静默丢失未保存修改

**问题**

以下抽屉在点遮罩、X、取消或关闭时直接把 `visible` 置为 `false`，没有未保存修改判断：

- 客户新建/编辑
- 供应商新建/编辑
- 客户协议价、客户分组价
- 配送线路新建/编辑
- 采购单、采购收货单
- 销售订单（含路由离开）
- 报损报溢、规格转换、出库、盘点、调拨
- 红字应付登记、核销登记
- 商品编辑（原有判断因 P0 的 Promise 问题失效）

**修复**

新增共享守卫：

- `xsy-scm-web/src/views/business/scm/common/scm-unsaved.ts`：纯函数快照与变更判断，可单测
- `xsy-scm-web/src/views/business/scm/common/scm-unsaved-guard.ts`：基线捕获、清空、脏检查、确认弹窗

行为约定：

1. 抽屉打开并加载完成后捕获表单基线；加载失败或尚未加载时不拦截。
2. 只有内容真正变化才提示“放弃未保存的修改？”。
3. 保存中禁止关闭，避免请求与界面状态错位。
4. 销售订单额外拦截路由离开：取消则留在当前页，避免切菜单后修改被丢弃。
5. 选择“继续编辑”后抽屉保持打开，表单内容不丢失。

### P2：全局头部设置按钮缺少可访问名称

**问题**

`header-user-space` 与 `top-menu` 的设置按钮只有图标，没有文本、`title` 或 `aria-label`，屏幕阅读器无法识别。

**修复**

为两处按钮增加 `title="设置"` 与 `aria-label="设置"`。

### P1（第二轮补充）：编辑旧单据时只显示数字主键

**问题**

订单、采购单和库存类单据的明细行直接绑定 `skuId` 给 `SkuSelect`。`SkuSelect` 首屏只加载 50 个规格，编辑历史单据时，若原规格不在首屏，下拉框会把数字 ID 直接显示出来，用户无法确认选的是哪个商品。

受影响文件：

- `order/components/order-item-editable-table.vue`
- `purchase/components/purchase-order-item-editable-table.vue`
- `inventory/inventory-stocktake-list.vue`
- `inventory/inventory-loss-gain-list.vue`
- `inventory/inventory-outbound-list.vue`
- `inventory/inventory-transfer-list.vue`
- `inventory/inventory-conversion-list.vue`（源/目标两个规格）

**修复**

给 `SkuSelect` 传入 `selected-options` 快照，用详情接口返回的商品名和规格名回显：

```ts
function selectedSkuOptions(record) {
  if (record.skuId == null || !record.productName) return [];
  const spec = Object.values(record.specValues ?? {}).join('/') || record.skuName || '默认规格';
  return [{skuId: record.skuId, productName: record.productName, specName: spec}];
}
```

库存单据同时补充“记账单位”列，并在新选规格时回填单位，避免数量看错单位。

### P1（第二轮补充）：详情加载失败后保存会退化成新增

**问题**

客户、供应商表单用 `form.customerId` / `form.supplierId` 判断新增还是编辑。详情接口失败时表单被重置为空，字段也为空，用户再点保存会走新增接口，生成一条空白的重复档案。

**修复**

把编辑目标从表单字段中独立出来：

- 新增 `editingId` 和 `loadFailed`，打开编辑时立即记录 ID。
- 详情失败后禁用保存按钮并提示“详情加载失败，请重新打开后再保存”。
- 提交时按 `editingId != null` 选择更新接口，绝不再退化成新增。
- 增加请求序号，快速切换编辑对象时旧详情不覆盖新对象。

### P1（第二轮补充）：高级筛选仍要求用户输入主键

**问题**

报表高级筛选对 `customerId`、`sellerId`、`categoryId`、`supplierId`、`purchaserId`、`warehouseId` 使用普通文本框，占位提示为“输入正整数编号”，与“页面不显示主键”的规则冲突。

**修复**

`components/business/scm/advanced-filter/index.vue` 按字段 key 渲染对应选择器：

- 客户 → `CustomerSelect`
- 销售员/采购员 → `EmployeeSelect`
- 商品分类 → `ProductCategoryTreeSelect`
- 供应商 → `SupplierSelect`
- 仓库 → `WarehouseSelect`

条件值仍在内部保存为 ID 字符串，界面只显示名称；用户不再需要知道编号。

### P1（第二轮补充）：库存表单校验失败后直接中断提交

**问题**

库存报损报溢、转换、出库、盘点、调拨、预警阈值 6 个页面的 `onSubmit` 直接 `await formRef.validate()`。校验失败时异常被抛出，但页面没有任何提示，用户只看到“保存没反应”。

**修复**

统一改为：

```ts
try {
  await formRef.value?.validate();
} catch (err) {
  notifyFormInvalid(err, formRef.value);
  return;
}
```

校验失败时滚动到第一个错误字段并给出 toast。

### P1（第二轮补充）：打印模板切换单据类型后保留旧字段

**问题**

打印模板弹窗修改“单据类型”只重新加载字段目录，没有清空已勾选的表头字段和明细列。保存时旧类型字段会被提交，后端拒绝或生成错误模板。

**修复**

- 切换类型时清空 `form.model.headerFields` 和 `form.model.columns`。
- 字段目录加载增加请求序号，快速切换时旧响应不会覆盖新类型。
- 单据类型加载失败时显示独立错误提示和重试按钮，并禁用“新建模板”。
- 字段目录未加载成功时禁止保存。
- 弹窗取消/关闭增加未保存确认。

### P1（第二轮补充）：弹窗关闭静默丢弃录入内容

**问题**

- 客户月毛利“登记客户月成本与费用”“批量登记”两个弹窗关闭即清空，批量登记可能刚录入几十行。
- 追溯检测报告编辑点“取消”直接退出，草稿内容丢失。
- 营销活动、优惠券、打印模板的编辑弹窗同样取消即放弃。

**修复**

统一接入 `createUnsavedGuard`，打开时捕获基线，关闭时只有内容变化才提示“放弃未保存的修改？”。销售订单原有的路由离开守卫保持不变。

### P1（第二轮补充）：仓库授权切换员工存在竞态

**问题**

员工仓库授权弹窗切换员工时，两个请求可能乱序返回；旧员工的授权会覆盖新员工，随后保存会把错误授权写进当前员工。

**修复**

- 授权加载增加请求序号，只接受最后一次请求的结果。
- 加载期间禁用保存按钮，并在 `save()` 中再次拦截。
- 关闭/切换视图时使未完成请求失效。

### P1（第二轮补充）：配送打印范围与筛选不一致

**问题**

按客户打印时，用户先勾选客户再修改“打印状态/订单状态”筛选，已勾选的客户仍在提交范围内，导致打印了已经筛掉的对象。

**修复**

筛选条件或打印模式变化时清空勾选，提交范围始终与当前可见范围一致。

### P2（第二轮补充）：其他一致性修复

- **商城弹窗设置**：商品规格、分类、活动、外链、图片说明修改后未标记 dirty，离开页面不会提示保存。已补 `@update:value` / `@change`。
- **电子秤注册**：新建时沿用上一台设备的仓库，容易把新秤绑错仓库。已重置 `warehouseId`。
- **付款登记**：切换往来对象后保留上一个对象已选的付款方式。已重置为银行转账。
- **商城账号禁用**：禁用后客户无法登录下单，原操作无确认。已补确认框，显示手机号。
- **活动/优惠券停用**：停用立即生效且不可逆，原操作无确认。已补带名称的确认框。
- **追溯公开页**：状态横幅、加载提示、在新窗口打开的报告文件缺少可访问名称。已补 `role="status"`、`aria-live`、`aria-busy`、`sr-only` 文本和文件链接 `aria-label`。
