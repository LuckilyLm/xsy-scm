# 首衡智能电子秤与 XSY-SCM 分拣平台对接开发交接文档

> - 版本：v0.1（2026-10-15）；性质：**双方联调契约草案 / 对外开发交接**。
> - 设备端负责人：负责首衡 Win10 秤端采集、适配、打印与离线缓存的同事。
> - XSY 端负责人：负责业务后端、权限、设备绑定、数据落库及分拣工作台的同事。
> - 标注 **【现有】** 的接口已在本地源码核对；标注 **【拟新增】** 的 URL、字段、响应和状态尚未实现。实施前两位负责人须确认接口版本。
> 业务不变量以仓库根目录 `AGENTS.md`、`docs/decisions.md` 为准；本文只集中维护**跨系统集成契约**，不另复制业务规则。

## 1. 一句话目标

**一套系统、两个运行端：** 首衡电子秤上的 **Windows 10 采集/打印程序（Agent）** 负责获取真实重量和物理打印；**XSY-SCM** 负责账号权限、订单与商品规格、分拣任务、人工确认、业务记录、打印任务调度与管理。双方通过版本化 HTTPS API 交互，不另外建设第二套订单、财务或库存系统。

最终工作方式：员工在秤端或 XSY 工作台选择**分拣任务 → 客户订单 → 非标品商品规格** → 实体秤实时展示净重 → 点击“采集当前重量”生成**一次**待确认读数 → 操作员确认分拣结果 → 如需打印则接收标签任务并打印 → 回传状态；断网可缓存**已冻结且授权的设备事件**，恢复后按原 ID 补传，不自动确认分拣或重复打印。

### 3.1 主仓库及当前状态

- 仓库：`https://github.com/LuckilyLm/xsy-scm.git`。
- 本地工作区：`D:\Browser Download\xsy-scm`，当前在 `main`。电子秤工作台与非标品确认源码已本地提交为 `b2b39db3`；远程可克隆版本以推送后实际包含该提交的 Git SHA 为准。
- 正式后端：`xsy-scm-server/sa-admin/`（Spring Boot / Java / PostgreSQL）。

- 旧客户小程序已归档于 Git 历史；新设备程序应使用独立工程。

### 3.2 推荐分工与仓库权限

**优先方案：** 同事在**独立的设备采集程序仓库**（拟名 `xsy-scale-agent`；创建须经仓库负责人同意）开发 Windows Agent，XSY 仓库保留正式业务模型与接口。给设备端同事 XSY 主仓库的**只读权限**用于查 DTO/接口、按 PR 提交必要的协议改动；不要将主仓库管理员权限、生产数据库密码、设备密钥一并交付。

若暂时只使用一个仓库，可在主仓库新增 `xsy-scale-agent/` **独立目录**，由同事基于**最新已经推送的**主干新建 `feat/sohe-scale-integration` 分支，使用 PR 合并；不要在未同步的本地 `main` 上交叉直接写代码。个人 GitHub 仓库的协作者权限不一定支持目录级只读，请根据真实 GitHub 权限配置审慎授予。

交接前由仓库负责人决定何时推送本地提交及授予仓库访问权限；本地提交不代表远程协作者已经能克隆该版本。

```bash

cd xsy-scm
git fetch origin
git checkout -b feat/sohe-scale-integration origin/main
# 不要把 .env、真实设备密钥、生产 Token、设备序列号关联用户信息提交到 Git
```

## 4. 推荐总体架构与通信方向

```text
首衡 TCS-150A 称重仪表 ──RS232 / 厂家本地 HTTP──▶ Win10 秤端 Agent
                                             │
                                        本地触摸屏 UI
                                     （订单/商品/实时重量）
                                             │
                         [出站 HTTPS + 设备凭证 + 本地持久队列]
                                             ▼
                                      XSY-SCM 服务端
                     ┌───────────────────┼────────────────────┐
                     ▼                   ▼                    ▼
              设备绑定/健康状态     分拣设备事件/人工确认    打印任务/回执
                     │                   │                    │
                     └───────────────────┼────────────────────┘
                                         ▼
                                  XSY 订单/分拣正式事实
```

**推荐连接方向：** Windows 秤端主动**出站**访问 XSY HTTPS。XSY 云服务器**不直接**访问私有局域网 Windows、COM 端口或 `localhost:33582`；打印任务采用 Agent 定时领取或经已鉴权连接通知。这样不要求现场暴露内网端口，也便于工厂 NAT、弱网和离线恢复。

可以复用 XSY 已有 Web 工作台；但如果它部署在 HTTPS 网站、要从浏览器读取 Windows 本机 HTTP，涉及浏览器的混合内容、私有网络访问、CORS 与本机端口安全限制。**不要假定浏览器能直接访问 `http://localhost:33582`**。更稳妥的交付是 Agent 自带本地触摸屏操作界面（可嵌入受信任 WebView），或明确测试安全的本地桥接方式；两者都必须由 XSY 后端执行业务认证。

## 5. 【现有】XSY 可复用接口（员工会话与权限体系）

> 下列均来自当前本地 Controller/DTO 源码核对；**不是设备专用开放 API**。设备程序不得直接携带员工 Cookies/CSRF 凭证冒充设备身份，设备接口需新增隔离层并复用领域服务。

| 方法 | 路径 | 含义 | 权限 |
| --- | --- | --- | --- |
| GET | `/scm/sorting/tasks` | 分拣任务分页 | `scm:sorting:task:query` |
| GET | `/scm/sorting/tasks/{id}` | 分拣任务及明细，含订单号、客户、商品规格、销售单位、版本 | `scm:sorting:task:query` |
| POST | `/scm/sorting/scale/report` | 设备读数事实入库，待人工确认 | `scm:sorting:scale:report` |
| GET | `/scm/sorting/scale/tasks/{taskId}` | 按任务查看最近称重事件（最多 200 条） | `scm:sorting:scale:query` |
| POST | `/scm/sorting/scale/{id}/accept` | 人工确认称重并复用分拣录入命令 | `scm:sorting:scale:accept` |
| POST | `/scm/sorting/scale/{id}/reject` | 人工驳回 | `scm:sorting:scale:accept` |
| GET | `/scm/print/SORTING_TICKET/{businessId}/preview` | 小票只读预览 | 业务对象查看范围 |
| POST | `/scm/print/SORTING_TICKET/{businessId}/print` | 生成**冻结的打印记录与版面**（带 `Idempotency-Key`） | 业务对象权限 |
| GET | `/scm/print/record/{recordId}/reprint` | 历史冻结快照重印数据 | 打印记录与业务权限 |

**重要：** 现有 `/scm/print/.../print` 成功只说明服务器创建打印记录，**不说明 Windows 队列已接单，更不能证明纸已打出**；物理打印任务与执行结果需要新接口和新状态。

现有 `SortingScaleReportForm` 字段：`eventKey`（≤160）、`taskId`、`taskItemId`、`deviceCode`（≤64）、`rawReading`（非负，最多 4 位小数）、`unit`（≤32）、`stableFlag`、`capturedAt`（带时区）；服务端记录 `receivedAt`。同一事件键重复上报时返回旧事件并标注 `duplicated`；同键换订单/重量/设备等应拒绝。

员工确认请求：`{ "version": 0, "result": "NORMAL", "reason": null }`；非标品允许 `NORMAL / SHORT / OUT_OF_STOCK / OVER`，非正常结果必须说明原因；最终数量来自原始读数，不能由确认请求偷偷改写。**这部分非标品能力已在本地提交 `b2b39db3`，尚未执行测试或发布验收。**

现有分拣只写任务行 `sortedQuantity`，不直接改销售订单实发量、库存或财务。仓库范围与受指派员工范围必须交叉校验。设备上报权与操作员确认权应分离。


## 6. 【拟新增】双方统一接口契约 v1（评审草案）

> 注意：`/scm/device/scale/v1/**` 目前**没有对应 Controller**，只作为双方待签字的接口草案。不得将表格复制进 Agent 后认为接口已上线。开发落地后须生成可供双方引用的 OpenAPI，标记精确版本及发布环境。

### 6.1 通用规则

| 维度 | 建议契约 |
| --- | --- |
| 协议 | Agent 主动出站 HTTPS + JSON；服务端不主动连接局域网 COM 口或打印机 |
| 身份 | 设备短效凭证与员工身份分离；绑定仓库、工作台及设备编号 |
| 时间 | RFC3339 带时区，例如 `2026-10-15T16:00:00+08:00`；服务端另记接收时间 |
| 主键 | JS 端超过安全整数范围的业务 ID 用字符串交互；双方确认 Java JSON 序列化策略 |
| 重量 | 十进制**字符串**（例如 `"2.3500"`），不得用浮点小数直接计算业务数量 |
| 单位 | 严格枚举与映射；单位不明必须报错，不能默认按 kg |
| 幂等 | 业务事件 `eventKey` 全局唯一且持久化，同事件重试**请求内容必须相同** |
| 应答 | HTTP 状态码与应用业务码各有明确语义，网络超时表示“结果未知”，不是失败事实 |
| 版本 | Agent 携带 `agentVersion`、`protocolVersion`，不兼容时服务端明确拒绝 |
| 追踪 | 每次请求带 `X-Request-Id`，不可代替业务幂等键 |
| 超时 | 连接/读超时配置化，网络 5xx/429 指数退避且加随机抖动 |
| 禁止 | 无条件自动确认分拣、越权下载他仓订单、后端直接连电子秤 COM、公开本地无鉴权设备端口 |

### 6.2 【拟新增】设备注册、配对、解绑、心跳

绑定步骤：

1. XSY 授权管理员在设备管理中创建设备，分配 `deviceCode`、`warehouseId`、`stationCode`、设备状态（待激活）。
2. 服务端生成一次性、短有效期配对码；设备 Windows 端安装 Agent 后由操作员输入/扫描配对码。
3. Agent 提交安装 ID、Agent/协议版本和本地设备公钥（若采用密钥对方案）；服务端完成激活，返回受限的设备凭证和设备配置。
4. 定期心跳报告软件、读取状态、最后成功采集时间、打印机状态、离线队列深度；管理员可以撤销/轮换凭证与解绑。
5. 解绑之后不得再领新任务/打印任务；历史称重事实和审计记录**保留**。

| 方法 | 【拟新增】URL | 发起方 | 作用 |
| --- | --- | --- | --- |
| POST | `/scm/device/scale/v1/bindings` | 已授权 XSY 员工 | 创建待激活绑定、配对码 |
| POST | `/scm/device/scale/v1/agents/activate` | Agent | 使用配对码换取受限设备身份 |
| POST | `/scm/device/scale/v1/agents/heartbeat` | Agent | 心跳/设备健康/队列统计 |
| GET | `/scm/device/scale/v1/agents/config` | Agent | 读取绑定仓库、授权范围、允许打印机、兼容版本 |
| POST | `/scm/device/scale/v1/bindings/{id}/revoke` | 已授权 XSY 员工 | 撤销设备绑定及凭证 |

**待拍板的认证方案：** 短效 Bearer Token + 设备身份轮换或设备签名/mTLS；不允许在 Agent 明文配置文件中放员工密码，也不允许设备 Token 具备订单确认、财务、库存等权限。多租户和仓库变更后必须重新核对授权，不得仅信任请求体的 `warehouseId`。

### 6.3 【拟新增】秤端领取工作任务/订单

原则：XSY 是**订单与商品规格的唯一数据源**。秤端只能领取其绑定仓、被授权工作站/操作员范围内的当前分拣任务，不能通过猜测订单号读取其他客户。不要把客户地址、金额等与称重无关的数据同步到本机。

| 方法 | 【拟新增】URL | 说明 |
| --- | --- | --- |
| GET | `/scm/device/scale/v1/jobs?cursor=...&limit=...` | 设备授权范围内待称重任务增量分页 |
| GET | `/scm/device/scale/v1/jobs/{jobId}` | 任务明细/订单/商品规格/单位/版本 |
| POST | `/scm/device/scale/v1/jobs/{jobId}/claim` | 设备工作会话领取；同一任务的并发控制 |
| POST | `/scm/device/scale/v1/jobs/{jobId}/release` | 退出作业、释放租约 |

建议只提供：`taskId`、`taskNo`、`taskVersion`、`taskItemId`、`taskItemVersion`、`salesOrderId`、`orderNo`、`skuId`、`skuCode`、`productName`、`specName`、`saleUnit`、`plannedQuantity`、`sortedQuantity`、`productType`、`warehouseId`、`assignee`、`jobVersion`、`expiresAt`。具体字段和是否同步明细由后端最小授权 DTO 决定。

操作员在秤端可先选订单，再选商品规格；**采集读数时应冻结选中的 taskItemId 与 jobVersion**，切换订单以后，旧读数不得自动“跟随”新选择的商品。

此处 `jobId` 与“工作会话”都是新的协议概念，**不是**现有 `sorting_task` 的数据库 ID；映射关系需要明确，禁止同事自造一套与 XSY 相冲突的任务状态机。

### 6.4 【拟新增】采集重量上传

连续串口帧/HTTP 定时取重用于**本地实时显示**；仅当操作员“采集当前重量”时才冻结为一次设备事实并请求上报。不得每收到一帧就调用现有 `report` 产生数据库记录。

建议接口：`POST /scm/device/scale/v1/measurements`

请求样例（**草案，不是现有 Controller DTO**）：

```json
{
  "protocolVersion": "1",
  "eventKey": "SOHE-ST01:20261015-session01:f4f24c47-6a44-4a2a-aacc-8f3bc8fe9901",
  "deviceCode": "SOHE-ST01",
  "stationCode": "SORT-ST01",
  "sessionId": "20261015-session01",
  "taskId": "80001",
  "taskItemId": "81002",
  "taskItemVersion": 3,
  "rawValue": "2.350",
  "rawUnit": "kg",
  "netWeight": "2.3500",
  "businessUnit": "kg",
  "weightKind": "NET",
  "stableFlag": true,
  "stabilitySource": "DEVICE",
  "capturedAt": "2026-10-15T16:08:23+08:00",
  "agentVersion": "0.1.0"
}
```

字段解释：

- `rawValue/rawUnit` 是设备原始值和原始单位；`netWeight/businessUnit` 是严格换算后的数值与业务计量单位；**需保存转换依据**，不能只留覆盖后的重量。
- `weightKind` 是 `NET`/`GROSS`。对非标品分拣原则上只允许有效净重；毛重不得在未去皮情况下直接入库。
- `stableFlag/stabilitySource` 表达稳定结论及来源，如 `DEVICE`、`MANUAL_CONFIRMED`；HTTP 接口没有硬件稳定标记时，**不得伪称设备稳定**。仅比较多次采样接近不能当作计量器具的硬件稳定标志。
- `taskItemVersion` 用于防止用户切换任务、明细重开/覆盖时采集到的过时上下文。
- `eventKey` 在本地 SQLite 等持久队列生成一次即固定；重试不要重新生成。
- `deviceCode` 必须与设备凭证绑定，服务端**不得**只相信这个传入字段。
- `capturedAt` 可能离线发生，不允许未同步设备时钟的明显未来时间直接进入正式分拣。

服务端建议响应（**拟新增协议**）：

```json
{
  "code": "OK",
  "data": {
    "measurementId": "920001",
    "eventKey": "SOHE-ST01:20261015-session01:f4f24c47-6a44-4a2a-aacc-8f3bc8fe9901",
    "status": "PENDING",
    "duplicated": false,
    "accepted": false,
    "receivedAt": "2026-10-15T16:08:25+08:00"
  }
}
```

其中 `accepted=false` 表示**仅已接收/持久化，尚未人工确认分拣**。重试同键同内容应返回同一 `measurementId`、`duplicated=true`；同键不同内容返回明确的 `EVENT_KEY_CONFLICT`。若服务端无法确认首次请求是否已成功，Agent 应先查事件结果或以同键重试，不得生造另一笔。

> 对接现有代码时可以在新设备边界层进行鉴权、映射和校验后复用 `SortingScaleEventService.report`，但不要直接把现有员工权限接口暴露给匿名设备；现有 DTO 不包含 `weightKind`、原始单位/换算依据、设备会话等字段，需要确认是否追加字段和 Flyway 新版本。

### 6.5 【拟新增】事件状态查询与人工确认

| 方法 | 【拟新增】URL | 操作身份 |
| --- | --- | --- |
| GET | `/scm/device/scale/v1/measurements/{eventKey}` | 已绑定设备，仅查**自己**的上报状态 |
| POST | `/scm/sorting/scale/{id}/accept` | **现有员工端接口**，需员工会话+权限 |
| POST | `/scm/sorting/scale/{id}/reject` | **现有员工端接口**，需员工会话+权限 |

状态机：`PENDING → ACCEPTED` 或 `PENDING → REJECTED`，终态不可覆盖。Agent 的 `MEASUREMENT_UPLOADED` **不等于** `SORTING_ACCEPTED`。如果要在秤端完成“人工接受”，须明确员工认证与操作归属：可通过正规员工登录会话调现有业务操作；或者由后端新增“设备会话 + 员工二次确认”的专用业务接口，不能仅凭设备凭证代替人工签名。

允许现场“离线缓存并补传”的边界：断网时**不能声称云端已接受**；恢复后上传仍必须重新验证任务状态/授权/明细版本。如果原任务已完成、取消、改派、重开或客户权限变化，应进入异常队列人工裁定，不要强制覆盖。

## 7. 【拟新增】打印任务下发、领取与执行回执

### 7.1 必须区分四件事

1. **生成打印内容**：XSY 模板引擎生成排版数据。
2. **创建打印任务**：XSY 为某个业务事实冻结将要打印的模板、内容、数量与目标设备。
3. **Windows 打印执行**：Agent 将任务交给 Windows 打印机驱动/打印队列，得到操作系统响应。
4. **物理打印结果**：标签是否真实出纸、是否完成、是否卡纸。**Windows 队列“已接受”不自动等于物理出纸成功**；若驱动不提供可信完成反馈，应记录为“已提交打印机，物理完成未知”。

现有 XSY `/scm/print/{documentType}/{businessId}/print` 只生成正式冻结记录和版面快照，不具备面向远端 Windows Agent 的打印任务队列与打印机完成回执协议，**不能直接拿现有 printRecord 代替打印执行状态**。

**建议打印职责：** XSY 决定“打印什么、给谁、打几张、哪张模板”；Windows Agent 负责“能否打印、选择哪个已绑定物理打印机、把任务送到打印队列、回报队列或设备可证实的结果”。

### 7.2 【拟新增】打印 API 清单

| 方法 | URL（草案） | 发起方 | 业务含义 |
| --- | --- | --- | --- |
| POST | `/scm/device/scale/v1/print-jobs` | 已登录的授权员工/XSY 服务端 | 创建冻结打印任务并选目标设备 |
| GET | `/scm/device/scale/v1/print-jobs/pull?cursor=...` | Agent | 分页拉取已授权待执行的标签任务 |
| POST | `/scm/device/scale/v1/print-jobs/{id}/claim` | Agent | 领取任务（含限时租约、尝试 ID） |
| POST | `/scm/device/scale/v1/print-jobs/{id}/ack` | Agent | 回传实际执行状态与依据 |
| GET | `/scm/device/scale/v1/print-jobs/{id}` | 授权员工/对应设备 | 查看当前任务、尝试和历史 |
| POST | `/scm/device/scale/v1/print-jobs/{id}/retry` | 授权员工 | 对未知/失败任务**显式授权**重打，生成新的尝试 |
| POST | `/scm/device/scale/v1/print-jobs/{id}/cancel` | 授权员工 | 取消尚未物理提交的任务；已出纸无法撤销 |

首轮可以采用 **5～10 秒的任务领取间隔（配置项）**，避免要求服务端主动连接车间内网；后续需要低延迟时再用 WebSocket/SSE 作为领取通知，不改变数据契约。

### 7.3 建议任务报文

样例是**待评审结构，非现有实现**：

```json
{
  "printJobId": "990001",
  "printAttemptId": "990001-1",
  "printRecordId": "880091",
  "documentType": "SORTING_TICKET",
  "businessId": "80001",
  "orderNo": "SO20261015001",
  "deviceCode": "SOHE-ST01",
  "printerCode": "LABEL-01",
  "templateId": "1101",
  "templateVersion": 3,
  "snapshotChecksum": "sha256:REPLACE_WITH_ACTUAL_HASH",
  "copies": 1,
  "format": "PDF",
  "contentUrl": "/scm/device/scale/v1/print-jobs/990001/content",
  "expiresAt": "2026-10-15T16:35:00+08:00"
}
```

**版面格式待选择：**

- **首选 A：** XSY 通过现有模板生成打印内容，确定输出为 PDF/标准图像，Agent 按固定纸张/尺寸打印。需验证 Windows 打印机驱动对分页、缩放、热敏纸张的适配。
- **备选 B：** XSY 生成受控 TSPL/ZPL 等标签指令，Agent 原样下发。只有设备打印机支持该语言时才能选择，不要把供应商示例的协议能力等同于当前标签机能力。
- 打印机型号、驱动、纸张规格、打印 DPI、标签尺寸、二维码/条码格式、撕纸检测、份数上限都要现场确认。未知时**不要**把 `format` 强行锁定为 PDF 或 TSPL。

必须冻结业务版本与内容校验：**同一 `printJobId` 的每一次领取都得到相同打印内容；业务订单变更不能静默改变历史任务版面**。重新打印需要创建**明确的重印尝试**，不修改已完成历史内容。

### 7.4 打印状态机与回执契约

推荐拆成“任务状态”和“打印尝试状态”；同一任务可多次尝试，但每次尝试最多提交一次物理打印操作。

| 状态（草案） | 含义 | 客户端 UI |
| --- | --- | --- |
| `QUEUED` | 服务端任务已创建，未被设备领取 | 待下发 |
| `CLAIMED` | Agent 已领任务，租约生效 | 已领取 |
| `SUBMITTED_TO_SPOOLER` | Windows 打印后台/驱动接收请求 | 已提交打印机，出纸待确认 |
| `CONFIRMED_PRINTED` | **有可信硬件/驱动反馈或人工核验**确认完成 | 已打印 |
| `FAILED` | 明确错误（缺纸、脱机、驱动报错等） | 打印失败 |
| `UNKNOWN` | Windows 已接单，但无可靠物理完成结论、断电/进程崩溃 | 结果待核查 |
| `CANCELLED` | 未打印前取消 | 已取消 |

回执样例（草案）：

```json
{
  "printJobId": "990001",
  "printAttemptId": "990001-1",
  "deviceCode": "SOHE-ST01",
  "printerCode": "LABEL-01",
  "status": "SUBMITTED_TO_SPOOLER",
  "windowsSpoolerJobId": "142",
  "observedAt": "2026-10-15T16:12:33+08:00",
  "feedbackSource": "WINDOWS_SPOOLER",
  "errorCode": null,
  "errorMessage": null
}
```

状态转换必须校验：当前尝试/租约、绑定设备、报告时间、合法状态序列；拒绝旧尝试的晚到回执覆盖新状态。Agent 重发相同回执应幂等，重复 `ack` 不创建第二次打印。

**重试特别约束：**
- API 请求超时且可能已经向 Windows 发送成功 → **不能自动再次提交物理打印**，先查本地打印尝试记录与 spooler 状态。
- 崩溃发生在“写本地数据库 → 发给驱动 → 回写本地数据库”的中间区间，存在天然的物理副作用不确定性。必须将其标记为 `UNKNOWN` 并交人工核验，不能承诺对不可查询硬件实现严格 exactly-once。
- `FAILED` 只有经现场确认“肯定未出纸”且满足重试策略时才自动重试；其他情况需人工确认重印，记录重印人、原因、次数。
- 服务端收款、订单状态、库存、配送发车不随打印状态改变；打印失败不能偷偷重新触发业务事实。

### 7.5 标签内容及来源

首个演示标签建议包含：订单号、客户简称（仅授权所需）、商品名称、规格、净重/单位、称重时间、设备编号、操作员工号、追溯二维码（按内部业务 ID 生成，不含敏感客户数据）。可打印字段按 XSY 模板权限控制，设备端不随意拼接客户金额、地址等字段。

如果同一商品一单称重多筐/多批，应明确“单行累计重量”与“单筐标签”的关系，**不要为了打印多张标签就重复覆盖订单行重量**；需要新的称重批次/容器号才有清晰追溯。首轮如尚未裁决，可限制一次选择只确认一次完整重量。

## 8. 断网、本地缓存、数据重传与恢复

### 8.1 秤端必须持久化的内容

使用本机 SQLite 等持久化存储，建议至少区分：

| 本地数据 | 最少字段 |
| --- | --- |
| `device_config` | 设备安装 ID、绑定服务端、协议版本、凭证存储引用、绑定仓库与工作台 |
| `work_context` | 领取的任务和明细 ID/版本、员工会话引用、任务租约过期时间 |
| `measurement_outbox` | 事件键、原始重量/单位、转换记录、稳定来源、任务上下文、采集时间、请求摘要、上传状态、最近响应 |
| `print_inbox` | printJobId、printAttemptId、内容校验、目标打印机、领取租约、执行阶段、Windows 作业 ID、错误 |
| `callback_outbox` | 未上传的状态回执、错误、尝试次数、下次重试时间 |
| `agent_log` | 本地连接状态、操作记录、端口异常和更新时间（有轮转与数据保留策略） |

服务端正式数据库另保留设备绑定、设备在线心跳、称重事件、打印作业及打印尝试/回执。**本地缓存只是待同步数据与现场排障证据，不是第二套订单/库存/财务权威库。**

### 8.2 重传时机与处理规则

1. 在线状态生成 `eventKey` → 将称重采集快照及业务上下文先持久化到 outbox → 上传。
2. 成功返回后存储服务端 `measurementId`、服务端接收时间与状态；不能把“已上传”显示成“已人工接受”。
3. 无网络或超时保留同一事件与字节等价业务载荷；恢复后相同 `eventKey`、相同载荷重传。
4. 如果 409 语义冲突（旧任务已取消、明细版本过时、设备解绑、订单已转派），停止自动重试，进入人工异常清单。
5. 设备时钟漂移：不可自行修改历史 `capturedAt` 规避后端校验。记录时钟同步偏差，人工处理无法确认的过期事实。
6. 本地队列上限、磁盘满、日志轮转、凭证过期、设备更换，均需有可见告警和安全降级。

### 8.3 状态对账

- Agent 上报最后同步游标、失败事件数、最近服务器确认事件 ID；服务器不能只依靠在线心跳推断“没有遗漏”。
- 定期对账：设备端有事件、服务端没有 → 原键补传；服务端已有、Agent 未收到响应 → 同键查/重发；状态变化以服务端为准。
- **已取消任务的旧读数**不能因为设备晚到就覆盖新任务。需要对 `taskItemId`、任务状态、员工/仓权限、工作会话及当前版本重新校验。
- 多台秤同时针对同一订单明细提交读数时，应以服务端行版本、幂等键和正式分拣确认事务守住一致性；不要仅靠设备端禁用按钮。

## 9. 厂家设备适配实现边界

### 9.1 RS232：厂家文章 2 的已知参数

- 9600 波特、8 数据位、无校验、1 停止位、无流控、ASCII。
- 连续输出固定 13 字节，CR LF `0D 0A` 结尾。
- 第一字节：稳定 `s/S`、不稳定 `w/W`；**文档文本与十六进制样例有大小写差异，实机核对后定最终解析规则**。
- 第二字节：净重 `n/N` 或毛重 `g/G`；重量字符串 7 字节，单位 2 字节（`kg`、`g`、`sj`）。
- `T`（0x54）去皮，`Z`（0x5A）置零；发送一个 ASCII 字节，不追加换行。
- 断包/粘包按 `LF` 边界组帧，校验帧长、CR LF、合法单位和数值；错误数据不得进入正式业务。
- 厂家示例允许未知单位按 kg 处理，XSY **不允许**此行为；必须拒绝未知单位并告警。
- `g` → kg 除 1000，`sj`（市斤）→ kg 除 2；对商品销售单位与公斤的换算要由 XSY 正式单位规则许可。

### 9.2 厂家本地 HTTP 秤重辅助（能运行时优先评估）

厂家公开附件显示可以调用：

| 方法 | 本机 API | 意义 |
| --- | --- | --- |
| GET | `http://127.0.0.1:33582/api/Weight` | 当前净重、皮重 |
| GET | `http://127.0.0.1:33582/api/zero` | 置零 |
| GET | `http://127.0.0.1:33582/api/setTare` | 设置皮重 |
| GET | `http://127.0.0.1:33582/api/clearTare` | 清皮 |
| POST | `/api/setDecimal?value=...` 等 | 管理仪表参数，**普通分拣员不得调用** |

重量返回示例：`{"netWeight":"12.345","tareWeight":"2.000","Code":1}`。

**限制：** 这套返回数据未明确包含硬件稳定标志、业务任务 ID 或订单信息；成功调用 `/api/Weight` ≠ 稳定确认。首衡文档中还有内置 AD、RS485 和蓝牙版本，不能用其他型号的能力直接推断 `SH2100-T15` 的具体配置。

对于 Windows 10 设备，优先由 Agent 在本机访问 `127.0.0.1`，不推荐从远程浏览器跨域调用该未经确认鉴权的本机服务。Agent 可抽象为 `WeightProvider`，实现 `LocalHttpProvider`、`SoheRs232Provider`；用设备配置选一种实现，避免同一物理秤被两个程序同时占用串口。

### 9.3 可确认设备重量后，才联动 XSY

必须具备：采集时间、稳定/不稳定、净毛重、单位、正负值、串口/服务异常、去皮/置零操作结果。对于 `/api/Weight` 不具备的稳定来源，先询问厂家是否有专门接口；若无法获得，必须定义“人工采集确认”的独立业务验收标准，不能写死 `stableFlag=true`。

### 9.4 打印机

先在 Win10 现场记录：打印机具体品牌与型号、Windows 驱动名称、是否 USB/网口、纸张尺寸、分辨率、是否支持 TSPL/ZPL、队列/缺纸反馈、字符编码、裁刀或剥离配置。厂家提供的打印指令示例与实际打印机驱动**不是同义词**。先能打印固定测试标签，再对接动态冻结任务，最后验证断电/缺纸和重复打印。


## 10. 建议新增数据库对象与权限（仅设计，不执行迁移）

请后端负责人与 DBA 基于当前 Flyway 最新版本另起新迁移，不直接修改已应用的 `V89__scm_sorting_scale_and_filters.sql`、已有电子秤事件表及已发布版表结构。

| 【拟新增】实体 | 建议关键字段 | 目的 |
| --- | --- | --- |
| `scale_device` | 设备 ID、deviceCode（唯一）、型号、仓库、工作站、绑定状态、证书/凭证引用、协议、版本 | 设备资产及绑定事实 |
| `scale_device_session` | 设备 ID、员工 ID、工作会话、任务 ID、租约、有效期、结束原因 | 将设备与当班操作人员、工作任务绑定 |
| `scale_measurement_receipt` 或扩展现有事件 | 事件键、设备、任务明细、原始净毛重、单位、换算依据、稳定来源、服务端时间、来源摘要 | 无损记录采集事实 |
| `scale_print_job` | 目标设备、业务事实及版面快照引用、目标打印机、状态、创建人/时间 | 打印任务 |
| `scale_print_attempt` | 任务 ID、尝试 ID、租约、状态、spooler ID、错误、回执来源与时间 | 物理打印尝试与不确定性 |
| `scale_device_heartbeat` 或最近心跳投影 | 最后在线时间、协议/Agent 版本、告警、未同步计数 | 运维可观测性 |

数据库唯一约束建议：`deviceCode` 唯一、业务 `eventKey` 唯一、`(printJobId,printAttemptId)` 唯一；根据现有原则**不新增数据库外键**，跨对象关联由领域服务验证；业务状态仅通过可控命令迁移。绝不把 Agent 本地 SQLite 当作 XSY 的正式业务数据库。

权限建议新增并经权限目录评审：`scm:device:scale:manage`、`scm:device:scale:query`、`scm:device:scale:bind`、`scm:device:scale:print:retry`。已有 `scm:sorting:scale:report/query/accept` 以及打印权限继续复用，不让普通设备管理员获得财务权限。

管理员解除绑定、将设备更换仓库、打印任务跨设备重新分配等操作必须记录原值、新值、操作员与时间。设备权限按仓库、工作站、任务指派和员工角色交集判定。

## 11. 完整联调流程与案例

### 场景 A：非标品正常称重

1. XSY 员工管理端创建/维护分拣任务，指派对应仓库及人员。
2. 秤端 Agent 激活完成且在线；操作员登录（如设计需员工身份）。
3. 领取当前可见任务，选择客户订单 `SO20261015001`，选择商品“生菜”规格，单位 `kg`，计划量 `5.0000`。
4. 放上商品，屏幕显示设备实时值；未稳定、毛重、单位未知、负数、低于计量使用范围时禁止正常采集。
5. 有效净重稳定为 `4.8500 kg`，操作员点击“采集重量”，生成唯一 `eventKey` 并本地持久化。
6. Agent 经设备认证上传；服务端核实设备仓库、任务与明细、时间和幂等 → 返回 `PENDING`。
7. 操作员看到计划量 5.0000 kg 与实重 4.8500 kg，选择 `SHORT`，填写“复核后实重短少 0.1500 kg”。
8. 服务端使用人工授权确认，经原有 `SortingTaskService.enter` 原子地写入实分量与结果；设备事件变为 `ACCEPTED`。
9. 只有完成此业务确认后才允许根据需要生成标签打印任务；打印的内容要反映已确认事实。
10. 系统可按仓库/任务/商品/设备/员工/订单追溯此次称重及其打印回执。

### 场景 B：接口上传超时

- Agent 已发送固定 `eventKey`，HTTP 超时不知道是否保存。**不得重建事件键**，按同键查询/同键重复提交。
- 若服务器已有此事件，返回原始记录并标记重复；显示“已同步、待人工确认”，而不是再生成一条。
- 若服务器响应“已被处理/订单已取消/明细版本过时”，移入待处理异常队列，禁止静默改变订单。

### 场景 C：打印回执丢失

- 服务端已经下发打印任务，Agent 向 Windows spooler 提交成功，但打印状态回传时断网。
- Agent 本地保留 `printAttemptId`、spooler ID、提交时间和最后已知状态；恢复后先回传历史尝试，不直接重复发纸。
- 若无法确认是否已经实际出纸，任务显示 `UNKNOWN`，由授权员工现场核验后再选择重印；重印形成新的 attempt 记录，不覆盖历史。

### 场景 D：离线期间改派/取消订单

- 秤端只缓存已领取任务上下文和冻结的采集事实，不允许假定旧任务仍有效。
- 恢复联网时服务端因任务取消、重开、改派、员工失权而拒绝正式确认。保留原始记录供追踪，交人工处理，不得重绑其他订单“消化”旧重量。

### 场景 E：多台秤同时处理同一商品

- 两台设备可以提交不同的测量事件，但**不能同时无锁覆盖同一个正式分拣明细**。
- 由服务端按版本、任务归属、当前状态和事务做最终仲裁；冲突时要求前端刷新并人工选择当前有效读数。

## 12. 现场联调准备与验收清单

### 12.1 对方要提供的设备侧材料

- [ ] 实机 Windows 10 完整版本（x64/x86）、硬件配置与是否可安装/开机自启第三方程序。
- [ ] `SH2100-T15 / TCS-150A / Y15XP` 实际物理连接示意、设备管理器串口列表、仪表是否由系统内程序独占。
- [ ] 能否安装与运行“悬浮电子秤/称重辅助”；`http://127.0.0.1:33582/api/Weight` 的实机返回结果（不包含密钥）。
- [ ] RS232 实机原始 13 字节稳定/不稳定、净重/毛重、零点/去皮样例，各至少一组。
- [ ] 实机型号与协议映射：外置连续输出、内置 AD 轮询或厂家本地 HTTP，三选一或注明切换关系。
- [ ] 标签打印机品牌型号、驱动、纸张规格、打印方向、测试页/出纸结果、错误状态来源。
- [ ] 现场网络：DNS、固定 IP（如有）、是否可访问 XSY HTTPS、代理/防火墙策略、断网场景。
- [ ] 秤的计量检定证明、最小称量限制以及实际业务单位/精度要求。
- [ ] 本机时间同步方式、停机/关机程序、磁盘空间、操作员账号与远程维护授权。

### 12.2 接口功能验收

- [ ] 设备能绑定、查询自己的配置、撤销后立即失效；设备凭证不能查看其他仓库。
- [ ] 秤端可以显示授权分拣任务、订单与商品规格，切换订单时旧重量不会串到新订单。
- [ ] 正常、跳动、不稳定、毛重、负数、零值、未知单位、超范围、明显未来时钟都能按规则处理。
- [ ] 连续读数不会把每帧都落业务数据库；每次操作员“采集”只生成一个稳定事件键。
- [ ] 同键重传返回原事实；同键不同请求必报冲突；不同键抢同一任务行只能按业务版本处理。
- [ ] 未经人工接受，正式分拣数量**不发生变化**；非标品正常/短少/超出/缺货与原因正确。
- [ ] 打印内容和正式分拣事实一致，打印任务可领取、状态可追踪，物理打印失败/未知不显示“已出纸”。
- [ ] 同一打印任务请求重试不重复提交物理打印；人工重印留操作人与原因。
- [ ] 断网缓存、多小时断连、Windows 程序意外退出、磁盘满、服务端 5xx 与设备解绑都有明确结果。
- [ ] 接入后不直接修改销售订单原始数量、库存流水、财务应收与配送资格。
- [ ] 保留设备事件、处理人与物理打印尝试的完整追溯；运营数据与排障日志可区分。
- [ ] 通过一次完整现场黄金链：**选择订单 → 商品 → 稳定净重 → 设备事件 → 人工确认 → 标签出纸 → 回执 → 后台可查**。

## 13. 需要双方负责人首先确认的事项

| 编号 | 待确认问题 | 推荐决定/处理 |
| --- | --- | --- |

| D02 | 秤端是独立 Win10 程序还是浏览器打开现有 XSY？ | 推荐独立小型 Windows Agent + 触摸屏 UI，复用 XSY 后端；若浏览器需确认本地安全桥接 |

| D05 | HTTP 重量是否带稳定状态、净毛重来源？ | 现有 HTTP 文档尚无硬件稳定状态；需厂家答复或独立人工确认规则 |
