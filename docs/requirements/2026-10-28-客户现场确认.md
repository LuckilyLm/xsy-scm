# 2026-10-28 客户现场确认

> 本文只记录 2026-10-28 现场沟通的事实、纸面单据样式和未决事项，作为需求证据。
> 生效规则以 [当前决策](../decisions.md) 的「2026-10-28 客户现场确认」为准；实现状态见 [项目状态](../status.md)。

## 一、现场作业时间线

| 时间 | 动作 |
| --- | --- |
| 约 14:00 | 采购当天及次日用量，通常多买两天 |
| 当天白天 | 客户下单；后台按客户公司整单录单 |
| 20:00 左右 | 打印当天全部客户的分拣单和送货单，开始分拣、派送 |
| 20:00—24:00 | 偶有客户追单/加单，形成当晚第二批采购需求 |
| 次日早上 8:00 前 | 完成全部订单打印与出车准备 |

现场明确：采购后直接送到分拣/配送环节，**不做采购入库操作**；系统不能要求先入库再出库才能开单。

## 二、纸面单据样式（照片核对）

### 1. 客户分拣单（10/28）

- 一张纸一个收货单位（雨金、鑫阳、北田所、交口、北田各一张）。
- 表头：收货单位、日期。
- 列：`序号 / 商品名称 / 单位 / 规格 / 实数量 / 销售单价 / 备注`。
- 实数量列现场手写修正，销售单价为空，无金额、无合计。
- 分拣单不出价格，避免分拣员和客户提前看到金额。

### 2. 客户送货单（10/27）

- 表头：`鲜蔬源(西安)供应链服务有限公司 送货单`、收货单位、日期。
- 列：`序号 / 商品名称 / 单位 / 品牌 / 规格 / 实数量 / 销售单价 / 销售金额 / 备注`。
- 末行合计金额；页脚销售方、收货方签字。
- 品牌列在系统中没有稳定快照，本轮不实现；如需品牌，另立商品/订单行字段需求。

### 3. 检测报告

- 大型市场方统一出具灰色纸质检测报告，常规采购不附带。
- 现场需要拍照或转 PDF/Excel 后上传，客户扫码可查看电子版。
- 系统已有批次级检测报告、PDF/图片、发布与公开扫码；本轮只做现场验证，手机端采集放到下一批。

## 三、电子秤基础信息（现场照片与说明）

- 秤体：首衡 `SHOUHENG` 电子台秤 `TCS-150A`，最大称量 150 kg，检定分度值 `e=d=50g`，最小称量 1 kg，准确度等级 III，出厂编号 61013004。
- 显示终端：`SH2100-T15` 物联网智能称重显示器，**内置 Windows 10**，触摸屏可直接操作，带 Windows 打印机并已打印测试页。
- 结论：现有 `xsy-scale-agent`（.NET Windows 代理）可以直接装在这台秤的内置 Windows 上，不需要另配 Windows 主机；打印也走同一台机器。
- 手册地址：`http://39.106.125.188:8080/docs/windows/article/13`。
- 仍待现场确认：称重协议（SOHE RS232/AD/HTTP）、COM 口/波特率、秤输出单位是 kg 还是市斤。秤的最小分度 50g，若输出 kg，换算成斤为 ×2。

## 四、仓库口径

- 客户目前**没有独立仓库流程**：采购后直接送到仓库，不做出入库动作。
- **仓库和分拣是同一个地方**，就是本地唯一的 **鲜蔬源仓库**；采购商品堆放在仓库，分拣也在仓库内完成。
- **没有配送点**：分拣完成后由专门的司机到仓库取货运输，所以全局只有一个仓库，不是“一仓多点”。
- 系统按单仓运行：订单、分拣、出库、库存都落在这一个仓库，不要求用户先选仓；负库存开关对这个仓库默认开启。

## 五、现场确认的业务口径

1. **订单按客户公司整单录入**：一张客户送货单对应一张销售订单，下面多行商品；不按商品逐行建单，也不要求一个商品一张订单。
2. **分拣实称量是唯一实发口径**：分拣时实际发货通常多于订单量（秤不准、习惯多给），按实称量结算；订单量和实发量的差异不要求事先申请。
3. **电子秤直接录数**：称重后在秤端屏幕确认实际数量，不再手写实数量；后台不重复录入同一笔实称量。
4. **20:00 批量打印**：一次打印当天全部客户，不按 10 单分批；分拣单无价格，送货单有价格、实数量和签字栏。
5. **加单**：20:00—24:00 的追单进入当晚第二批采购需求，仍按客户整单录入。
6. **采购单位**：以斤为主，也有调味品、肉；同一商品可有多个规格，采购单位与销售单位可能不同。
7. **不做采购入库**：采购收货/入库动作在当前现场流程中不存在，库存允许出现负数并以月末损耗估算收口。
8. **检测报告**：由市场方提供，采购员拍照/转 PDF 上传，客户扫码查看。
9. **定价按客户分组**：同一商品对不同客户价格不同，例如西红柿采购价 1.5 元/斤，对一批客户 2.0 元、对另一批 2.2 元；这种差异按**协议价**处理，协议价按**客户分组**维护——
   - 每个分组至少一个客户，组内客户执行同一价格；
   - 同一商品的不同规格对组内客户也是**同一个价格**（不按规格分别定价）；
   - 实际给某个客户下单时，可以在订单行**手动改价**，改价需原因；
   - 分组与客户是个人/公司/集团**类型无关**，客户类型不参与定价。
10. **客户类型价与时价**：现场目前**没有客户类型价**（个人/集团/企业执行同一价格），**时价几乎没有**；两者保留能力即可，本轮不深入开发，也不纳入验收。
11. **夜间节奏**：20:00 前后结算当日订单并生成配送单，随后启动采购与分拣；次日 8:00 前完成全部订单打印与出车准备。采购员除采购外还承担其他运输任务，系统不应要求采购员在配送途中补录单据。

## 六、未决事项（需现场或负责人确认）

- 电子秤协议（SOHE RS232/AD/HTTP）、COM 口/波特率、输出单位；优先把秤切到市斤（`sj`），若只能输出 kg，按 `kg → 斤 ×2` 显式换算。
- 哪些岗位可以修改仓库负库存开关；赠品是否允许负库存（建议不允许）。
- 采购价 7 天窗口从采购单提交起算是否可接受；收货确认前是否必须已有价格。
- FIFO 核销按账单日期还是到期日排序；抹零是否需要第二人审批、是否允许冲销红字应收。
- 分拣单/送货单纸张尺寸、是否显示订单号、批量打印按配送日期还是线路。
- 订单整单粘贴是否允许按客户名称自动匹配客户（建议先在订单抽屉选定客户，粘贴只匹配商品）。
- 分组价遇到不同计量单位（如斤/箱）的规格时是否仍统一价格，还是只对同一单位的规格生效；个别规格需要例外价时如何维护。
- 客户类型价与时价是否长期保留入口（现场暂不使用，建议保留能力、界面不引导）。
- 采购员从市场到仓库的运输是否需要系统记录（当前按“不入库、不记调拨”处理）。
