# 高德地图与可视化大屏技术调研

> 日期：2026-09-19
> 性质：**纯需求/技术调研，未修改任何代码、未新增任何依赖**。
> 范围：① 物流配送模块接入高德地图的依赖与方案选型；② 首页提供可视化大屏入口，以及大屏本身的技术选型。
> 依赖版本均于 2026-09-19 通过 npm registry 实时核实。

## 2. 项目现状盘点（调研核实）

### 2.1 前端 `xsy-scm-web`

- 技术栈：Vue 3.4.27 + TypeScript 5.6.3 + Vite 5.2.12 + ant-design-vue 4.2.5 + Pinia 2.1.7 + vue-router 4.3.2（hash 模式），`echarts 5.4.3` 已在依赖中但**仅首页 demo 使用**（`src/views/system/home/components/echarts/`，直接 `echarts.init`，无统一封装、无 resize/dispose）。
- **无任何地图、配送、大屏代码**：全 `src/` 检索 `AMap/高德/leaflet/baidu/lng/lat` 均无实现命中；`src/views/business/scm/` 下只有 common/customer/inventory/order/pricing/product/purchase/supplier 八个目录；订单状态枚举（`src/constants/business/scm/order-const.ts`）只有 DRAFT/PENDING/CONFIRMED/CANCELLED，无配送态。
- 唯一的坐标线索：`src/views/business/scm/customer/components/customer-form-drawer.vue` 头部注释——客户表单曾剪枝 `longitude/latitude`，标注「随『客户地图』一起做」，是接入地图时恢复字段的直接落点。
- 首页：`src/views/system/home/index.vue`，SmartAdmin 工作台（公告 + mock 图表 + 待办卡片）；`HomeQuickEntry` 快捷入口组件**当前被注释掉**，可作为大屏入口卡片的参考样式。
- 路由机制：菜单为动态 `buildRoutes`（name = menuId，组件经 `import.meta.glob('../views/**/**.vue')` 匹配）；静态路由集中在 `src/router/routers.ts`（login/home/helpDoc/404/403）。`src/router/index.ts:26` 的全局守卫对**除登录页与 404 外的所有路由要求登录态**——独立大屏路由也不例外。
- env 仅 `VITE_APP_API_URL` / `VITE_DEV_PORT` / `VITE_APP_TITLE`，无任何地图 key；`vite.config.ts` 无 CDN/external 配置（高德 JSAPI 走 loader 动态加载，不需要改构建配置）。

### 2.2 后端 `xsy-scm-server`

- SmartAdmin 双模块结构（`sa-admin` / `sa-base`），全库检索无 `longitude/latitude` 字段、无地图相关接口、无 screen 域。坐标、配送、大屏均为全新增。

### 2.3 legacy 参考项目（只读）的可用遗产

- **从未接入过任何地图 SDK**，地图选型当年就是「待确认 08-02（高德/百度）」——接入高德没有历史包袱。配送完整设计见 `project-reference-examples/xsy-scm/docs/requirement/08-物流配送.md`（t_route / t_route_order / t_delivery_track / t_sign_record、线路状态机、轨迹回放、移动端签收，均未落地）。
- **大屏后端范式完整**：`module/business/screen/`（`POST /screen/data/business|stock|purchase` 只读聚合 + `t_screen_config`（layout_json、refresh_interval）+ `ScreenCodeEnum`：1 经营、2 库存、3 采购、4 分拣绩效（待分拣）、5 配送（待配送）、6 溯源（待溯源））；大屏前端为零。

### 2.4 既定业务范围（不重新发明）

## 3. 高德地图接入调研

### 3.1 Key 体系与账号要求（接高德的前置事项）

- **JS API key（Web端 JS API 类型）**：前端渲染地图用。自 2021-12-02 起申请的 key **必须配对安全密钥 `securityJsCode`**，在加载 JSAPI 前设置 `window._AMapSecurityConfig`，否则报 `INVALID_USER_SCODE`。
- **Web 服务 key（Web服务 类型）**：服务端 REST 调用用（地理编码、路径规划、距离测量等），与 JS API key 是**两个独立 key**，不能混用；Web 服务 key 绝不能下发到前端。
- 安全密钥生产环境官方推荐走**域名代理转发**（`serviceHost`），避免 `securityJsCode` 打进前端 bundle；开发环境可直接配置。
- 账号需实名认证（个人或**企业**；未认证无法购买配额与商用授权）。配额政策 2025-05-15 起调整为：基础服务**取消日配额、保留月配额**，可按组购买。企业商用请提前确认授权与配额（待决策 D-1）。
- JS API key 可配置**域名白名单**防盗用。

### 3.2 候选依赖对比（版本于 2026-09-19 经 npm registry 核实）

| 依赖 | 最新版本 | 性质 | 与本项目适配性 | 结论 |
| --- | --- | --- | --- | --- |
| `@amap/amap-jsapi-loader` | 1.0.1 | 高德**官方** JS API 2.0 加载器 | 零框架耦合、Promise 化加载、官方维护；解决异步加载不完整/多版本混用 | ✅ **基础必选** |
| `@amap/amap-jsapi-types` | 0.0.15 | 高德**官方** TS 类型（JSAPI 2.0） | TS 项目必配，符合 §35.2 明确类型要求 | ✅ **必选** |
| `@vuemap/vue-amap` | 2.1.17 | 社区 Vue3 组件库（基于 JSAPI 2.0 + Loca，含 TS 提示） | 活跃维护（2025-09 仍在发版）；组件化拼页面快，但多一层抽象 | 🟡 可选：业务地图页多、追求拼装速度时引入，否则不必 |
| `vue-amap`（ElemeFE 老库） | 0.5.10 | Vue2 组件库，**基本停更** | 不兼容 Vue3 | ❌ 排除（注意别装错包） |
| `@amap/amap-vue` | 2.0.13 | 社区封装 | 社区规模小 | ❌ 不选 |
| `echarts-extension-amap` | 1.12.0 | ECharts 的 amap 坐标系扩展（支持 ECharts 5） | 让 ECharts series 直接叠在高德底图上 | 🟡 仅当大屏需要「ECharts 图表与地图深度联动」时评估 |
| Loca 2.0 | 随 JSAPI 2.0 加载（非 npm 包） | 高德 WebGL 数据可视化（LineLayer 轨迹、HeatMapLayer 热力、海量点） | 轨迹回放/热力/大屏地图层性能远优于 ECharts 内置地图系列 | ✅ 配送轨迹与配送大屏推荐 |
| AMapUI 组件库 | CDN 按需加载 | 高德官方 UI 组件 | 当前功能点用不到 | 暂不需要 |

### 3.3 推荐架构（配送模块）

```text
前端（xsy-scm-web）
  @amap/amap-jsapi-loader 加载 JS API 2.0（+ Loca 2.0）
  + @amap/amap-jsapi-types
  统一封装 src/components/business/scm/map/：
    map-container.vue      地图容器（key 注入、加载态、销毁回收）
    address-picker.vue     地址选点（客户表单恢复 lng/lat 用）
    order-distribution.vue 线路订单分布（Marker/MassMarks）
    track-playback.vue     轨迹回放（Loca LineLayer，后续接入）
后端（xsy-scm-server，net.lab1024.sa.admin.module.scm.<delivery|customer>）
  统一代理高德 Web 服务 API（地理编码、路径规划 v5、距离测量）：
  key 存服务端配置，前端只拿业务结果（坐标补全、两两距离/时长矩阵）
```

- 选 loader 直用而非组件库的理由：项目 UI 一贯直接用 ant-design-vue 原生范式，无自动引入体系；地图交互页数量可控，自封装符合 §13/§14「不建多个不兼容版本」；少一层出问题难排查的抽象。若后续地图页面明显增多，`@vuemap/vue-amap` 是唯一值得考虑的 Vue3 组件库。
- 高德**不提供多点配送排线的现成 API**（路径规划是起终点间的）：「按区域/时间/订单量/金额加权排线」是自研算法 + 高德距离/时长矩阵的组合。排线权重规则属 §40 敏感业务规则，实现前需业务裁决（待决策 D-5）。
- 现实依赖顺序：**客户/订单先有坐标**（V2 已剪枝，数据库也无该列）→ 需要 Flyway 迁移补列 + 表单地图选点 + 存量数据补录方案，这是配送地图的前置数据工程（待决策 D-4）。
- 轨迹记录依赖司机端数据源（W6 小程序 / device-agent，均未启动），本期地图模块可先做分布可视化与静态展示，轨迹回放预研即可。

### 3.4 环境与部署注意

- 前端 env 需新增（示例名）：`VITE_AMAP_KEY`（JS API key）；开发环境另配 `VITE_AMAP_SECURITY_CODE`，生产走 Nginx 代理转发（`restapi/websdk` 相关域名的转发规则部署时一并确认）。
- 高德 JSAPI 由前端浏览器直连公网加载；**内网/离线部署无法使用**，需确认现场网络可达 `*.amap.com`（公开资料有离线方案但属商用授权范畴，不建议自建破解）。
- 页面基座是 `https`/`http` 均可，但 key 的域名白名单要含实际访问域名。

## 4. 可视化大屏调研

### 4.1 候选方案对比

| 方案 | 组成 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 纯 ECharts 自研 | echarts 5.4.3（已有）+ 自研布局/缩放 composable | **零新增依赖**；视觉完全按 §16 Screen Theme 定制；无第三方风格污染 | 边框/装饰等「科技感」效果需手写 CSS，工作量略高 | ✅ **推荐**（与 legacy「不引 BI、优先 ECharts」裁决一致） |
| B. ECharts + DataV Vue3 | A + `@kjgl77/datav-vue3@1.7.4` | 边框、装饰、轮播表等大屏件开箱即用；Vue3+Vite 原生兼容、社区活跃 | 默认科技蓝风格需贴 §16 色板定制；多一个依赖与包体 | 🟡 可选增强（首版建议不加，确有需要再引入） |
| C. echarts-extension-amap | A + `1.12.0` | ECharts 图层直接叠高德底图，联动简单 | 双渲染引擎叠加复杂，底图样式受限 | 🟡 仅当大屏需要图表-地图深度联动时评估；否则地图层交给 AMap+Loca |
| D. 高德 Loca 2.0 地图层 | 随 JSAPI 加载 | 轨迹/热力/海量点高性能 WebGL 渲染，配送大屏（编码 5）的既定内容 | 依赖 AMap key 与公网 | ✅ 展示配送轨迹/热力时采用 |
| E. 成品 BI / 低代码大屏平台（帆软、阿里云 DataV 等） | — | 低代码 | legacy 已裁决不引入独立 BI；许可成本、内网部署、与既有栈割裂 | ❌ 排除 |

### 4.2 大屏适配（AGENTS.md §16：1920×1080 整体 scale）

- 推荐**自研 `useScreenScale` composable**（约 30 行：按窗口宽高比对固定 1920×1080 容器做 `transform: scale()` 等比缩放居中），不新增依赖；候选小依赖 `vue3-scale-screen@1.0.1`（极小）可作参考实现或直接引入，二者皆可，不构成风险。
- ECharts 实例在 1920×1080 逻辑容器内 init，天然不受缩放影响；需统一封装（init/resize/dispose/主题色），替换首页现存 demo 写法。

### 4.3 首页入口方案

| 方案 | 实现 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 首页入口卡片 + 独立全屏静态路由（推荐）** | `src/router/routers.ts` 增加独立于 SmartLayout 的静态路由 `/screen`（无侧栏/Header，Screen Theme 独立生效）；首页（参考被注释的 `HomeQuickEntry` 卡片模式）加大屏入口，`window.open` 新窗口打开 | 主题彻底隔离（大屏不吃 Admin 布局与 Tabs）、真全屏体验、天然适合壁挂 | 现守卫下 `/screen` 仍需登录态（见下） |
| B. 动态菜单 iframe（frameFlag + frameUrl） | 后台菜单配置外链指向大屏地址 | 前端零路由改动，菜单/按钮权限直接复用 | iframe 嵌套全屏体验差、缩放滚动易出问题 |
| C. 普通动态菜单页面 | `views/screen` 挂菜单 | 走原生权限体系 | 页面被套在 Admin Layout 内，不符合大屏形态，基本排除 |

- **登录态问题（壁挂场景）**：`src/router/index.ts` 守卫要求所有页面有 token。壁挂大屏需保持专用账号长期登录，或将来为大屏开启「只读免登/token 化」——涉及鉴权边界，属 §24 敏感变更，列为待决策 D-6，默认先要求登录。
- 大屏页面与数据接口的权限：页面不需要进 t_menu 也能用（静态路由），但**后端聚合接口必须有 `@SaCheckPermission`**；若希望按角色控制可见性，可另配一枚隐藏菜单权限。

### 4.4 后端聚合接口参考

- V2 当前无 screen 域。首个大屏建议沿用 legacy 范式重建：`net.lab1024.sa.admin.module.scm.screen`（或 support）+ 只读聚合 Controller + `t_screen_config`（layout_json、refresh_interval）思想；SQL 聚合禁全表扫描（§30），指标口径与报表一致。
- 首版指标应从**已落地业务域**取数：订单（W4）、商品（W1）、客户/供应商（W2）、定价（W3）、库存（W6-1）、采购（W5）；销售额/应收类指标受财务未实施限制，先做订单量/销售额快照口径并显式标注（与 legacy「口径与财务一致」约束呼应，待决策 D-7）。
