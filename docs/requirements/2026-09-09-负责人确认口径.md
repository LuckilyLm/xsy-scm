# 负责人确认口径（2026-09-09）

来源：负责人提供的 `当前疑问.md` 与 `功能清单模块.docx`。本文只记录已确认的业务口径，作为后续详细设计和实现的输入；历史规格中的待确认问题不删除，改由本文覆盖。

## 已确认决策

1. **商城**：一个逻辑商城，面向不同展示端；当前手机端确定为微信小程序，不能拆成两套独立商城账和业务规则。
2. **多次收货**：一张采购单对应多张收货记录。每次到货新增记录，允许少收或多收，实际差异必须留痕；收货数量仍受采购单约束，超收处理规则需在详细设计中明确上限、审批或异常状态。
3. **采购单生成**：由人工触发，按选定的固定时间段统计订单后生成。生成操作提供“计算库存”选项，用于决定是否按实时库存扣减采购需求；默认值和扣减时点待产品进一步确认，实施时不得静默扣减。
4. **收货入库**：支持两种操作模式：收货确认后直接入库，或收货确认后再由仓库执行入库确认。页面提供明确按钮选择，不能把两者混成无提示的隐式行为。
5. **价格优先级**：当前先实现协议价优先；客户价、时价、活动价同时存在时的完整优先级暂不扩展。协议价不存在时的回退顺序需在价格专项设计中确认。
6. **移动端**：本阶段“手机端”指微信小程序；公众号 H5、原生 App 是否建设不属于本次确认范围。

## 与原始需求的关系

`功能清单模块.docx` 是范围输入，列出了商品、客户、营销、订单、采购、库存、分拣、物流、财务、后台、商城、订单助手和溯源模块。本文对其中负责人已回答的问题作口径收敛，不代表这些模块已经实现或验收。

## 影响的开发文档

- Sprint 2 价格设计：协议价优先。
- Sprint 3 采购设计：人工按时间段生成采购单、多次收货保留多条记录、少收/多收留痕、收货与入库分为可选模式。
- 商城规划与总体架构：一个逻辑商城，多展示端；微信小程序为当前移动端首选。

## 仍需补充确认

- “计算库存”选项是否扣减可用库存、扣减发生在预览还是正式生成，以及并发下的锁定口径。
- 超收是否允许直接确认、是否需要审批、是否设置容差；少收如何关单。
- 直接入库和二次入库确认的状态机、权限和库存流水时点。
- 协议价不存在时客户价、时价、活动价的后续优先级。
