# P1 采购收货规则详细规格

> 历史参考：本文保留原始业务/设计语义。技术栈、实施状态和进度均为 legacy 快照；当前实现以 V2 对应波次的 target-design、approval 与验收报告为准。已删除的旧计划及验证记录可从 Git 历史恢复。

## 范围

P1 将已确认销售订单按半开时间段 `[startAt, endAt)` 汇总为可追溯采购需求，并支持同一采购单多张独立收货记录。数据库迁移从 V27 开始，仅追加或调整未改变历史语义的约束；V8–V26 不修改，历史 receipt/confirmation 数据只读兼容。

## 采购需求生成

请求必须指定启用仓库、开始和结束时间（开始早于结束），并可指定 `calculateInventory`，默认 `true`。服务事务内重新读取目标仓库余额和 confirmed 销售订单行。按 SKU、销售订单确认时间及订单行 ID 稳定排序，将库存从早到晚抵扣；原始需求量、抵扣量和建议采购量均保留，建议量不得小于零。每个销售订单行只能建立一个有效来源，即使建议量为零也要保存来源，避免重叠区间重复采购。生成批次保存请求哈希、参数、汇总和结果，幂等键重放必须返回同一结果；不同哈希冲突失败。

## 收货与库存

一张采购单可有多张 P1 收货记录。每次收货是独立快照，记录本次计划量、到货量、累计量、剩余/差异和超收量。`DIRECT` 在同一事务内写库存余额及 `PURCHASE_IN` 流水；`DEFERRED` 仅确认并进入 `PENDING_PUTAWAY`，由具备 `purchase.receipt.putaway` 权限的命令二次入库。二次入库按收货记录唯一来源和幂等键防重。标品使用数量，非标品必须记录人工实际重量；金额和数量均为 decimal/BigDecimal。

超收容差从 `sys_config` 的 `purchase.over_receipt_tolerance_percent` 读取，默认 10，必须在 0–100 范围内。累计有效收货不得超过计划量乘以 `(1 + tolerance / 100)`，超限整笔回滚。历史收货不重写，也不再追加确认批次。

## 少收关单和权限

有有效收货且存在未收数量时，可携带订单版本、幂等键和非空原因执行少收关单；每行保存未收差异，采购单进入 `SHORT_CLOSED` 终态。达到计划量（包括容差内超收）进入 `RECEIVED`。已关单或已完成采购单禁止新收货。二次入库权限码为 `purchase.receipt.putaway`，迁移仅授予管理员，普通角色由后台授权。

所有表保持软删除/乐观锁字段、无数据库外键；库存流水追加且保持 `before + change = after`。查询应区分历史确认批次与 P1 独立收货记录。
