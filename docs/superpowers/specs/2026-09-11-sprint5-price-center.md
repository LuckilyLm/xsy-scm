# Sprint 5 价格中心与商城专项规格

状态：待人工规格评审  
冻结日期：2026-09-11

## 1. 目标与边界

本专项收敛已有商品、客户可见性、协议价、商城目录、购物车、结算预览和销售订单合同。它不重写协议价 CRUD，不实现支付、库存预占、称重或完整营销引擎。

后端是唯一价格权威。Web 与微信小程序只能提交客户、SKU、数量、地址和幂等意图，不能决定成交单价、优惠资格或订单金额。

## 2. 价格来源与优先级

在请求时点 `at`，针对客户 `customerId` 和可见、可售的 SKU，价格按以下顺序选择：

1. 有效客户协议价（`AGREEMENT`）；
2. 有效客户类型价（`CUSTOMER_TYPE`）；
3. SKU 基础售价/市场价（`BASE`/现有兼容来源）；
4. 三者都不存在或价格为空时，返回缺价，不生成可购买价格。

活动价本 Sprint 不参与成交计算。未来接入活动价时必须新增明确优先级和资格快照，不能通过修改当前解析器顺序隐式改变历史订单。

同一来源同一客户/SKU 在同一时点不得有重叠有效区间。有效区间采用半开形式 `[effectiveFrom, effectiveTo)`；`effectiveTo` 为空表示无穷未来。时间使用带偏移时间戳并由服务端统一比较，客户端不得按本地时区重算。

零价不是缺价：若业务允许录入零价，需显式保存并展示为 0.0000；本专项默认价格必须非负，空值代表缺价，是否允许零价沿用现有校验并在实现测试中固定。

## 3. 客户、SKU 与可见性

- 客户必须启用，停用客户的商城会话、目录、购物车、预览和提交均拒绝或要求重新登录。
- SKU 必须属于启用的三级分类、未软删除、处于可售/上架状态，且通过 `ALL_ENABLED` 或 `ALLOWLIST` 可见性判断。
- 目录可返回缺价 SKU，但必须带 `priceStatus=UNPRICED`/等价明确字段和不可购买标记；不能以 0 元替代。
- 购物车读取、加购和改量重新校验可见性、上架状态、起订量和步长。商品下架、客户失去可见性或价格变缺时，购物车保留原订购意图并标记不可结算，不能静默删除或按旧价提交。
- 起订量、增量步长和数量精度由交易 SKU 定义，Web 与小程序仅展示服务端返回的约束。

## 4. 预览、锁价与订单快照

结算预览必须重新解析每个 SKU 的价格，并返回：SKU、原订购数量、解析单价、价格来源、来源记录标识、解析时间/快照时间、行金额及整体提交指纹。预览不改变库存，也不产生订单。

订单提交必须重新执行客户状态、地址归属、可见性、SKU 状态、数量规则和价格解析；客户端传入的单价只可作为展示字段，不能覆盖后端结果。服务端保存订单项的：

- 原订购数量；
- 锁定单价与行金额；
- 价格来源及来源记录标识；
- 价格快照时间；
- 后续实际数量/实际重量字段（本阶段不实现称重回写）。

提交必须要求 `Idempotency-Key`。相同客户、相同幂等键和相同请求指纹返回同一结果；同一幂等键复用不同客户或不同请求指纹必须拒绝。指纹至少覆盖客户、地址、SKU、原订购数量和服务端解析价格版本/快照，不能只覆盖 SKU 和单价。

## 5. 缺价错误语义

- 目录：成功返回商品及不可购买缺价状态。
- 加购/改量：拒绝缺价行，返回稳定业务错误码和 SKU 标识。
- 预览：拒绝整次预览并返回所有缺价行，不能返回部分金额让客户端误提交。
- 提交：即使绕过预览也必须拒绝缺价行；不得创建草稿销售订单。
- 前端：展示明确提示和重试/刷新入口，不静默当作 0 元。

具体错误码应沿用当前 `ApiError`/Mall 错误码命名规则，新增代码必须在后端测试和客户端映射中固定。

## 6. 客户类型价与价格组最小合同

客户类型价按客户当前启用类型生效，优先级低于客户协议价、高于基础售价。客户类型变更不会改写历史订单；新目录/预览按请求时点读取当前类型。

价格组仅作为后台批量维护和查询维度，不改变以上成交优先级。一个客户在请求时点最多解析一个有效类型价来源；价格组成员和有效期变更必须通过事务校验，避免同一客户类型/SKU 重叠。

若现有数据库尚无客户类型价表，本阶段先冻结服务合同和错误/审计语义；实现只在确认字段、迁移版本和权限后追加兼容迁移，不修改已应用迁移。

## 7. 批量调价/导入

批量请求包含稳定行号、客户类型/价格组、SKU、价格、生效区间和版本（如适用）。服务端先完成整批校验，再在单事务内写入；任一行失败则全部回滚。响应必须包含每个失败行的行号、SKU/对象标识、稳定错误码和人类可读消息。

批量成功或失败均追加审计记录，至少记录操作者（当前系统身份可为 `SYSTEM`）、批次标识、输入摘要、影响范围、结果和时间；不得记录敏感 Token。不能以逐行成功提交替代整批语义。

## 8. 审计与查询

价格历史查询必须能按客户、客户类型/价格组、SKU、来源、生效区间和操作时间筛选，并分页返回当前值与历史变更。订单锁定价格和人工改价历史独立于当前价格表，基础资料修改不得静默改变已锁定订单。

## 9. 客户端一致性验收

Web 与小程序均需覆盖：会话失效、客户停用、可见/不可见 SKU、上架/下架、协议价命中、基础售价回退、缺价、起订量/步长、购物车旧价刷新、预览金额、重复提交和订单查询。各页面必须有加载、空、失败、重试状态。

## 10. 未冻结事项

活动价的参与顺序、优惠叠加、零价是否允许、价格组后台权限细节和价格历史的角色可见范围仍需单独业务确认；在确认前不得以代码默认值扩大范围。
