# Sprint 5 价格中心与商城基线实施计划

## 背景与已确认决策

- 基线：当前 `feature/sprint5`/`feature/sprint4` 代码，不整体合并 `feature/sprint4-miniprogram`。
- 价格优先级冻结为：有效协议价 > 客户类型价 > 基础售价；活动价本 Sprint 不参与成交。
- 无价 SKU：目录可以展示缺价状态，但购物车、结算预览和订单提交拒绝该行。
- 批量调价/导入：整批回滚；返回可定位的行级错误，并记录成功/失败审计结果。
- 后端是价格、可见性、起订量、订单金额的唯一权威；客户端只展示和提交意图。
- 本阶段先冻结规格与复用矩阵，再按批准范围编码。

## 实施步骤

1. **完成复用审计产物**
   - 记录共同祖先、目标分支提交图和逐提交文件分类。
   - 对小程序身份、目录、购物车、结算预览、订单查询及服务层逐项核对当前 `/api` 合同。
   - 将营销、支付、供应商协同、硬件、H5 扩展和 Sprint 9–12 域明确标记为 defer/reject。
   - 输出 `docs/superpowers/specs/2026-09-11-sprint5-reuse-matrix.md`，不引入目标分支的删除、迁移重排或未批准后端域。

2. **冻结价格专项规格**
   - 输出 `docs/superpowers/specs/2026-09-11-sprint5-price-center.md`。
   - 定义客户状态、SKU 上下架/可售状态、客户可见性、起订量/步长、有效期半开区间、时区和缺价错误语义。
   - 定义价格来源、锁定值、快照时间、来源标识和人工改价审计要求；活动价留作后续扩展点但不进入本期成交计算。
   - 定义价格组/客户类型价的最小数据合同、批量整批回滚接口和行级错误码；若当前业务未提供足够依据，明确仅冻结合同、不实现未批准字段。
   - 定义购物车价格/可见性变化时的重新校验和结算指纹范围，保持原订购量与后续实际结算量分离。

3. **按最小增量实现**
   - 先复用并修正小程序纯客户端基础：会话失效、加载/空/错/重试、重复提交幂等键；禁止移植后台组件和权限模型。
   - 补充后端聚合或价格查询能力，仅在现有合同不足时修改对应 customer/mall/order 文件和追加 Flyway 迁移；不改已应用迁移。
   - 为协议价/客户类型价/基础售价解析、缺价、可见性、批量整批回滚、价格快照和幂等补充单元/集成测试。
   - 为 Web 和小程序补齐客户商品、价格来源/缺价、购物车、预览、重复提交和订单查询主链路测试。

4. **质量门禁与证据**
   - 在服务端运行编译、单元测试、受影响 PostgreSQL 集成测试和 Flyway 空库/升级验证。
   - 在 Web 运行 lint、typecheck、test、build。
   - 在小程序运行 lint、typecheck、微信小程序构建和 H5 构建。
   - 后端与前端启动条件满足时运行 Playwright；若环境阻塞，保存真实错误到 `docs/superpowers/verification/`，不虚报通过。
   - 保存当前提交的验证记录，并确认主工作区无非计划文件变更。

## 约束与停止条件

- 不实现支付、库存预占、称重、复杂营销、供应商门户或 Sprint 6+ 功能。
- 不整体 cherry-pick/merge 小程序目标分支；每个复用提交先审计再单独适配。
- 若现有 API 无法在不破坏 Sprint 4 收货/订单合同的情况下支持价格规则，停止并报告合同缺口，不猜测数据库迁移。
- 规格和实现先获得批准；本计划批准后再开始编辑代码。
