# Java 工程规范与质量基线

状态：长期规则。阶段性整改过程和某次测试数字从 Git 历史追溯，不在本文件持续堆叠。

规则优先级见根目录 [AGENTS.md](../../AGENTS.md)。

## 包结构与职责

- SCM 正式业务包使用 `com.xsy.scm`，保持 Controller → Service → Manager / Policy → DAO 的依赖方向。
- Controller 不直接访问 DAO；领域服务不依赖 Controller；`common` 不反向依赖具体业务域。
- Finance 对订单、采购、库存、配送等业务事实保持只读消费；跨域写通过正式领域命令或契约完成。
- Service 负责事务编排、状态转换和领域协作；超过 400 行时审查职责，但按业务边界拆分，不按行数机械拆类。

## 命名与安全重构

- 重命名先定位声明与引用，再做窄范围替换；禁止整文件单词正则替换。
- 业务字段名表达完整语义，避免为了缩短代码引入第二套简称。
- 自动审计无法确认的结果标记为人工复核，不自动记为通过。
- 已应用 Flyway migration 不修改；新增数据库变化只追加新版本。

## 枚举、权限与校验

- 业务状态、类型、来源优先复用现有 Enum；数据库 CHECK、后端 Enum 和前端展示语义同步维护。
- 相同拼写不代表同一业务事实，不机械合并不同聚合的状态、价格来源或财务方向。
- 权限使用领域 Permission Catalog；注解、手工检查、范围包装方法与菜单发布保持一致。
- 输入表单校验提供可读 message；禁止把 magic string 扩散成新的隐式协议。
- 工具优先使用 JDK → Spring → Apache Commons；只为明确领域语义创建新工具。

## 注释与格式

- 注释记录原因、不变量和易错点，不维护阶段编号、提交过程、一次性测试数量或过期计划。
- 公共契约、并发/事务、跨域边界和非直观规则必须说明；意图明确的私有实现不强制补 Javadoc。
- 显式 import，禁止 wildcard 和无用 import。
- 按仓库格式配置保持 UTF-8、4 空格、Java 120 列、末尾换行和无行尾空白；已应用 migration 的字节和换行不得为“统一格式”重写。

## 门禁

正式入口为：

- `tools/verify.ps1`
- `tools/verify.sh`
- `tools/verify.py`

Spotless / Checkstyle 管格式与基础规范，ArchUnit 管依赖边界；项目守卫覆盖权限、旧包、业务字符串、命名、阶段注释、跨域 DAO 等项目特有不变量。

- baseline 只允许收缩；新问题不得增加。
- 禁止为通过门禁扩大 exclude/suppression、降低检查级别或削弱业务测试。
- 迁移冻结清单不可随意重写；[迁包工具说明](package-migration-readiness.md)及其机器清单保留给工具读取。
- 报告必须区分已通过、失败、跳过、未执行和未覆盖。
- 本地验证、Git 提交、生产部署和现场验证互不替代；历史远程 CI 记录只代表其对应提交。
