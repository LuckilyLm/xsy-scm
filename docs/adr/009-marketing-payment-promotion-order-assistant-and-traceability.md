# ADR-009：营销支付、推广归属、订单助手与溯源

- 状态：Accepted
- 日期：2026-10-02
- 覆盖：ADM-12～ADM-15

## 背景

营销、支付、推广、移动订单协同和商品溯源将跨越订单、Finance、库存及客户身份。实施需要冻结优惠和资金来源，保持正式订单与库存事实唯一，并限制公开溯源信息。

## 决策

- 现有基础定价顺序保持“协议价 → 客户类型价 → 市场价”；活动价在选出的基础价之后计算。活动规则按版本冻结，互斥组决定可否叠加，不允许客户端自行组合优惠。
- 订单优惠按订单行金额比例分摊并冻结；舍入差额以确定性规则归集。退款按原订单行优惠分摊反向，不使用退款时的当前活动重算。
- 优惠券占用、核销、释放和赠品来源必须可追溯并具备幂等保护；结算预览不等于最终占用，提交时由服务端重验适用范围、版本和并发状态。
- 支付采用 provider-neutral 的 intent、transaction、callback、refund 和 reconciliation 模型。回调按渠道事件/交易标识幂等，验签后的状态转换由服务端执行；支付成功与 Finance 收款事实建立唯一映射，但不建立第二套财务账。
- 本地 mock provider 必须覆盖成功/失败回调、重复回调、退款和对账。真实支付渠道通过同一 provider 契约接入，渠道密钥和通知地址不得进入业务规则或客户端。
- 客户余额使用追加资金流水表达充值、消费、退款和更正，不直接修改客户主档余额字段；余额由有效流水汇总。货到付款仅在财务确认实际收款后形成资金事实，不因订单选择该方式提前记实收。
- 推广码记录版本、有效期和归属业务员。客户来源默认采用首次有效绑定；已有客户再次扫码不自动改派。撤销或人工转归属必须是显式授权、带原因且可审计的命令，并且不改写历史订单归属。
- 订单助手是员工端对正式订单、采购收货和库存命令的受控投影，不新建订单或库存表。可编辑动作受订单状态、字段白名单、版本、幂等键和服务端数据范围约束；“针对订单入库”必须编排正式采购收货或库存来源，不提供直接改余额入口。
- 溯源首期采用批次加包装码。采购收货时建立批次；包装拆分、合并、补码和作废保留父子关系、来源动作与操作者，码唯一且状态可追溯。
- 内部溯源查询遵守仓库和业务权限；公开查询只返回批准的白名单字段，不显示客户、价格、内部人员、供应商敏感信息或内部附件。报告附件仍遵守对象关系与文件访问策略。

## 明确排除

- 不纳入总账/凭证、自动结算、多币种、无依据的余额字段直改或支付回调直接改订单/库存。
- 不因重复扫码自动改变既有客户归属，不让二维码绕过客户身份或数据范围。
- 不允许订单助手离线写入、直接写业务表或另建订单/库存状态机。
- 溯源首期不是逐个散装单品的强制赋码体系，不承诺区块链、防伪鉴真或公开全部供应链数据。

## 外部验收边界

营销规则、mock 支付、余额流水、推广绑定、订单助手契约和批次包装码可在本地验证。微信或其他真实支付渠道的商户主体、签名证书、回调公网可达性、退款权限和生产对账，实体标签材质/打印/扫码兼容性以及公开查询域名与隐私合规必须在目标环境单独验收；mock 成功不得表述为真实支付或现场扫码已上线。

## 结果

ADM-12～ADM-15 以冻结快照、追加资金事实、首次有效归属、正式领域命令和白名单公开查询形成统一且可审计的跨域边界。
