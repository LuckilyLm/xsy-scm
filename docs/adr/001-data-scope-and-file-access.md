# ADR-001：数据范围与附件授权

- 状态：Accepted
- 日期：2026-09-24
- 原始决策记录：[2026-09-28 决策归档](../archive/decisions/decisions-2026-09-28.md)

## 背景

非管理员业务角色需要按员工职责读取和写入 SCM 数据。附件也必须继承业务对象的访问权，不能仅凭上传目录决定访问范围。

## 决策

- SCM 数据范围由 `ScmDataScopeService` 集中解析并显式传给 DAO；不使用 SmartAdmin `@DataScope`。
- 业务归属和仓库范围按各自事实字段相交。用户传入的筛选只能缩小授权集合，空范围必须失败关闭；放宽范围需要显式的 `*:scope:all:query` 权限。
- 读写路径及仓库选择器遵守相同范围。管理员例外只用于明确的管理员身份，不以通过普通权限检查代替范围验证。
- 客户修改、状态变更、删除及客户下拉均按客户负责人的当前范围授权；共享结算钱包的人工更正和充值创建同时要求业务客户与结算主体在当前范围内。幂等重放返回旧结果前仍须重验相应对象的当前范围。
- 支付退款列表同时按支付意图的业务客户范围及其销售订单负责人范围收窄，空范围失败关闭；功能点权限不替代行级范围。
- 文件关系由通用 `support/file` 层的 `t_file_relation` 维护，业务对象访问权决定附件访问权；`FileService` 是服务端 URL 解析入口。
- 未绑定上传进入私有暂存区并在确认无关系、无业务字段引用后回收。商品图片只允许绑定 `public/` 文件。

## 结果

业务域通过显式作用域保护查询和写入，OA 与 SCM 共用文件关系能力。对象存储模式是私有附件保密性的验证环境；本地静态上传目录不提供同等级的读取保护。
