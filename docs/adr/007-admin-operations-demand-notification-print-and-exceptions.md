# ADR-007：后台净需求、通知、打印与异常聚合

- 状态：Accepted
- 日期：2026-10-02
- 覆盖：ADM-05～ADM-08

## 背景

采购净需求、事件通知、可配置打印和异常订单分析需要形成后台操作闭环，但不得把预览变成库存写入、重建底座消息系统、让模板执行任意代码，或建立第二套订单状态机。

## 决策

- 采购净需求按仓库、SKU 和单位计算；需求扣减同维度可用库存、有效在途未收数量和已有采购覆盖。不同单位不换算、不混加，现有库存预留和已履约数量按其正式事实口径参与解释。
- 每次计算冻结批次、基准时点、输入快照、解释行和来源分摊；从同一冻结批次生成采购需求必须幂等。计算和预览不改变库存余额；人工毛需求入口保留并明确命名，不伪装为净建议。
- 冻结批次必须可回看：回看返回批次头、SKU 级解释行与逐行建议，全部数字取自冻结快照、不回表重算，因此回看与生成逐字一致。回看可见性按仓库范围与采购员范围<b>相交</b>判定，两个维度不互相替代。
- 所有筛选只能收窄仓库和业务归属授权范围；空范围失败关闭。生成采购需求仍由采购域校验版本、范围和并发事实。
- 通知首期仅复用 SmartAdmin 站内信，不新建消息中心或外部渠道。事件仅包括订单首次确认和库存阈值由 `NORMAL` 转为 `LOW`/`HIGH`。
- 通知以业务事件唯一键防重；异常持续期间不重复发送，恢复为 `NORMAL` 后再次进入异常可再次提醒。接收人按正式职责确定，消息跳转不授予详情访问权，打开详情时重新校验范围。
- 阈值跃迁的检测采用**周期性扫描**，不挂在库存余额写路径上：余额变更分散在九条记账腿与预留的占用/释放上，逐点挂钩会把通知逻辑编进最热的记账路径，且任何新增记账腿都会静默漏掉通知。代价是事件时点从「余额变更那一刻」变成「下一轮扫描」，间隔由定时任务配置决定；恢复语义不受影响。
- 跃迁记忆按 `(仓库, SKU)` 保存最近观察到的状态与一个纪元号，纪元在回到 `NORMAL` 时自增。事件唯一键由 `(仓库, SKU, 纪元, 状态, 接收人)` 组成：带接收人是因为一个仓可能有多名仓管，键不含接收人会让唯一约束把第二个人之后全部挡掉；带纪元是因为「恢复后再次异常」必须落在新的键上。
- 库存预警的接收人取自仓库授权行（`employee_warehouse_scope`，排除停用人员），没有授权行时不广播、不猜人。通知正文只含可用量、阈值与仓库/SKU 标识，不含金额与成本 —— 授权行包含默认看不到成本的仓管角色，通知不能成为绕过金额权限的旁路。
- 打印模板采用受控 JSON 模型、字段白名单和受限版式，不接受任意 HTML、脚本或表达式执行。采购单、发货单和分拣小票提供内置默认模板。
- 受控模型只有七个字段：标题、纸张、方向、表头字段、明细列、是否打印合计行、页脚备注。没有位置、字号、表达式，因此不存在需要求值器才能渲染的模板。字段只能从**单据类型的白名单**里挑 key，标签与对齐由服务端给出（模板改不了标签，否则可以把「计划数量」标成「已收数量」）；标题与页脚备注按纯文本处理并拒绝尖括号。纸张只提供 A4 与 80mm 小票，且小票不允许横向。
- 渲染在服务端完成：模板只决定「打印哪些列」，单元格文本与列定义由服务端算好后下发。金额字段在渲染时按**调用者**的金额权限剔除并记入「被剔除字段」，行内的 key 一并删掉 —— 只删列定义而把值留在行里，等于「界面上看不到、接口里拿得到」。授权不写进模板：同一份模板对不同的人渲染出不同的列。
- 打印一张业务单据不新增权限，要求该单据自己的查看权（例如采购单用 `scm:purchase:query`），且功能权限与数据范围两者都要过。反过来，打印记录查看权不附带读单据内容的能力：重印同样校验该单据的查看权。
- 正式打印冻结模板版本、内容快照、业务数据快照、操作人和时间；历史重印使用原快照。预览不登记正式打印；打印不触发提交、发车、分拣完成等业务状态变化，并保留既有打印计次语义与金额权限。
- 重印只读快照、不回业务表重算，但金额按**当前**调用者重新剔除：快照冻结的是内容，不是授权，否则一条历史记录就能把金额权限绕过去。打印记录表上有触发器拒绝 UPDATE / DELETE。
- 异常订单首期只读聚合分拣数量差异、配送异常签收和售后拒绝三类既有事实，提供统一筛选、统计、导出和来源跳转；时间、状态和数量均来自源事实，不复制处理状态。
- 异常聚合不建立第二套订单状态机，不代替源域处理，不把待办聚合当通知投递；列表、统计和导出必须使用相同口径与数据范围。

## 明确排除

- 不自动创建采购单，不静默修改库存，不把采购金额当应付，也不推断跨单位换算。
- 不纳入短信、邮件、微信等外部通知渠道，不重复实现库存阈值判断或既有报损报溢驳回通知。
- 不提供任意模板代码、任意数据库字段或客户端绕过金额权限的能力。
- 不扩展异常类别为通用工单、处置状态机或自动业务补偿。

## 外部验收边界

站内信、计算快照、打印快照和异常聚合可在本地完成合同与权限验证；目标打印机的纸张、驱动、浏览器缩放和现场版式必须在部署环境验收。若以后接入外部消息渠道，其账号、送达率、模板审核和生产配额另行决策与验收，不能由站内信通过推断。

## 结果

ADM-05～ADM-08 获得可解释、可重试、可审计且不越过源域事实的统一后台操作边界。

ADM-07 三类单据共用受控模板、服务端渲染与不可变冻结记录。发货单以线路为业务主键，明细保留停靠序、客户、订单及商品来源；分拣小票以任务为主键，不包含金额，不混加不同单位数量。

模板选择按源单据查看权与数据范围开放，不要求模板维护权。重印及幂等重放重新校验当前源单据范围和金额权限，但内容仍读取冻结版面；历史单据状态改变不重算快照。打印记录列表仅显示当前可见单据的记录。模板打印与原有配送按订单/客户、分拣按任务的登记计次入口分离，生成冻结记录不自动累计原业务计次，页面明确提示计次入口；历史重印也不计次。
