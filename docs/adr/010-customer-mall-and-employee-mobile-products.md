# ADR-010：客户商城与员工移动端双产品

- 状态：Accepted
- 日期：2026-10-02
- 修订：2026-10-03，员工配送端按 ADR-008 仅展示计划路线，不接入 GPS 采集/回放。
- 覆盖：ADM-16～ADM-17

## 背景

客户商城和员工操作端面向不同身份、数据范围与验收主链。冻结的 `xsy-scm-miniapp/` 不能作为继续改造的正式产品，也不能把客户与员工能力合并为一套移动权限模型。

## 决策

- 新建 uni-app + Vue 3 正式移动工作区；客户商城与员工端使用分离的应用入口、身份模型、路由/页面、能力集和验收范围。冻结 legacy 目录不修改、不迁移旧认证或业务实现。
- 两个移动产品均复用服务端正式领域服务、SmartAdmin 底座能力及 SCM 集中数据范围，不复制客户、商品、订单、采购、库存、分拣、配送或 Finance 状态机。客户端筛选和缓存不能扩大服务端授权。
- 客户商城首发形态为微信小程序，采用独立客户身份绑定；客户只能访问绑定客户的可见商品、定价、地址、订单、履约、售后和资金信息。商城订单通过受客户身份约束的适配器进入正式订单服务并标记 `MALL` 来源。
- 商城首期支付支持 mock、账期和货到付款；真实微信支付复用 ADR-009 的 provider 接口。库存、活动、优惠券、支付方式和授信在结算预览后仍须在幂等下单时由服务端重验。
- 商城可提供目录、搜索、分类、购物车、常用菜品、再来一单、主题/版块、新品/促销、订单及实重/配送/售后投影；它们不形成独立商城账。语音下单只把 provider 结果转换为待确认文本/草稿，客户明确确认后才可提交订单。
- 员工端首期覆盖采购协同与收货、分拣任务、配送线路与订单级签收、订单助手及溯源扫码。登录上下文显式映射员工、司机、授权仓库、任务、线路和能力集；每个命令在服务端重新校验。
- 所有移动写命令携带幂等键和期望版本，记录身份、设备/请求来源和审计信息。照片仅按对应领域合同上传和授权访问，不能作为绕过正式状态转换的写入口。配送使用仓库/停靠点的登记坐标展示路线示意，不上传员工实时位置，不申请持续或后台定位权限。
- 移动端不实现离线业务写入或客户端冲突合并；弱网仅安全重试同一幂等命令。版本冲突、范围变化或业务状态变化必须向用户明确提示并重新获取服务端状态。
- 客户商城与员工端分别完成认证、权限、主链和发布验收；一个产品通过不代表另一个产品通过。

## 明确排除

- 不修改或直接复用 `xsy-scm-miniapp/` legacy 实现，不机械复制旧代码，不建立第二套认证和业务账。
- 商城首期不默认包含公众号 H5、原生 App 或其他展示端；语音结果不得直接下单。
- 员工端不支持离线写入、未经裁决的冲突合并、供应商代分拣、部分签收或客户端直改库存/财务。
- 不因移动端便利降低数据范围、幂等、版本、附件访问或审计要求。

## 外部验收边界

本地及测试环境可验证移动契约、mock 支付、权限、幂等、弱网重试和构建产物。微信主体与类目、开发者账号、隐私清单、域名备案/白名单、真机兼容、审核发布、真实微信支付，以及实际纳入范围的现场相机和网络质量必须在目标环境分别验收；构建成功、模拟器通过或代码合并不等于小程序已审核、发布或生产可用。

## 结果

ADM-16 与 ADM-17 作为两个正式移动产品共享服务端事实与安全边界，但保持身份、功能和验收隔离；legacy 继续冻结。
