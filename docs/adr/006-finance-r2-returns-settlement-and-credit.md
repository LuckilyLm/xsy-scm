# ADR-006：Finance R2、退货、集团结算与授信

- 状态：Accepted
- 日期：2026-10-02
- 覆盖：ADM-01～ADM-04

## 背景

Finance R2、销售退货实物回库、集团统一结算和账期授信共享收入、成本、结算方、到期日与余额口径。实施必须延续 Finance R1 的追加事实和跨域只读边界，不能建立第二套订单、库存或财务状态机。

## 决策

- 收入按 Finance 应收事件确认；利润口径为销售毛利，不是净利润，不纳入费用、税额、总账凭证或多币种换算。订单金额不等于收入或实收，采购金额不等于应付。
- 销售成本取销售出库时库存流水冻结的 `unit_cost`。缺失历史成本时结果标记为“不完整”，不得按 0、当前平均成本或当前采购价补算。
- 退货成本仅在实物验收回库后，按对应原销售出库成本反向计入；可售去向追加退货入库事实，报损去向不形成可售库存。签收异常、退款、红字应收或售后批准均不隐式回库。
- 退货成本必须保留原出库来源；多来源不能仅按汇总金额推断本次实物成本，历史成本缺失不得按 0 补算。来源分摊实现与验收需同时保持数量、单位及成本可追溯。
- 退货回库是库存域的独立幂等命令。累计接收数量不得超过已批准且已销售出库、尚未回库的数量；命令冻结来源订单行、仓库、单位、去向和原出库成本，并拒绝重复接收或单位不一致的整笔操作。
- 应收、应付形成时按当时有效结算条件冻结到期日；此后客户、供应商或账期主档变化不重算历史到期日。账龄基于冻结到期日和有效未核销余额。
- 对账严格分列债权债务发生、实际收付款、核销分配和未分配资金；可冻结对账单版本及其明细快照，但快照不取代原始追加事实。
- 集团客户必须显式指定结算方，业务单据和财务事实冻结历史结算方。允许同一结算方下属客户之间核销；付款人可以记录，但不能替代债权归属或结算方。
- 集团关系不扩大数据范围。查询、核销、对账和导出仍取原客户业务归属、仓库及操作权限的交集；Finance 只读消费订单、采购、库存和配送事实，不写这些业务表。
- 授信占用由有效未核销应收，加已确认但尚未形成应收的订单组成；核销或红字事实释放占用。并发下以服务端权威口径校验，不能依赖客户端余额。
- 授信额度为 0 表示未设置金额上限，不按金额阻断；逾期仍然阻断（2026-10-02 用户明确裁决）。
- 超额或逾期默认阻断下单/确认；具备明确例外权限的操作者可填写原因放行，例外必须审计。Finance 不直接改写订单状态或客户额度字段。
- Finance R1 的追加事实、更正用反向事实、金额保持正数且方向由类型表达、来源唯一与请求幂等、登记不自动核销等不变量继续有效。

## 账龄读模型补充（2026-10-03）

- 截止日按 Asia/Shanghai 当日结束计算；正常应收/应付、红字、核销及反向核销均按各自业务时点截断。实际收付款不直接抵减未核销余额。
- 未核销余额为 `max(原金额 - 截止日红字净额 - 截止日有效核销, 0)`；负净额或超额核销继续由既有财务明细展示，不混入正数账龄余额。
- 按未逾期、逾期 1～30 / 31～60 / 61～90 / 91～180 / 超过 180 天分组；缺失冻结到期日的历史事实单列“到期日未设置”，不按当前主档推算。
- 查询、分组汇总与导出共用 SQL 读模型。仓库与订单/客户/采购归属范围取交集；应收单头金额不猜测仓库分摊，受限仓库查询要求全部正常来源行均在可见范围内，选定仓库时要求全部来源均属于该仓库。
- 账龄页下钻展示现有财务单据的当前详情；账龄列表金额是所选截止日的余额，两者因截止时间不同可能不同。

## 明确排除

- 不纳入净利润、费用分摊、总账/凭证、发票税额、多币种、财务审批、采购退货或自动结算。
- 不允许部分签收、异常签收或退款自动撤销销售出库；不修改既有库存流水或财务记录。
- 不因集团关系、付款人或例外权限绕过 SCM 数据范围。

## 外部验收边界

本 ADR 可由本地数据库、确定性测试数据和并发场景验证口径、幂等与审计；真实历史成本完整性、生产账期/集团主数据质量、期初余额及生产对账结果必须在目标环境单独核验。代码、迁移或本地验收完成不代表生产财务数据已经校准或上线。

## 结果

ADM-01～ADM-04 共享一套可追溯的收入、出库成本、退货、到期日、结算方和授信规则，同时保持 Finance、库存、订单各自的事实权威边界。
