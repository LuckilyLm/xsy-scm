# 蔬东坡能力 vs xsy-scm 现有实现：功能差距分析

> **⚠️ 范围声明（2026-09-11 更新）**：本文以**蔬东坡全量能力**为对标，覆盖面超出项目需求文档。项目实际排期**只做需求文档内的需求**，因此本文仅作**参考视角**，不作为缺口依据或排期输入。
> 本文为 legacy 调查快照，不能代表当前 V2 完成度。当前范围与证据请见 [V2 文档总览](../../00-文档总览与索引.md)。

分析日期：2026-09-11
对比基准：蔬东坡 17.5 能力版图（见 [蔬东坡产品演进与能力调研](./蔬东坡产品演进与能力调研.md)）
项目现状来源：`xsy-scm-server` / `xsy-scm-web` / `xsy-scm-miniapp` 源码实测 + Flyway 迁移 + 既有页面级调查
状态：历史差距盘点，仅供产品研究，不作为当前 V2 排期或开发授权依据。

## 0. 结论速览

- 项目已完成 **"商品 → 客户定价 → 订单 → 采购 → 收货 → 库存 → 商城/营销 → RBAC"** 的基础闭环，**没有**分拣、配送、财务、溯源、BI 五大模块。
- 按蔬东坡能力版图粗估，项目覆盖约 **25%–30%**；且已覆盖部分的**纵深也普遍浅于**蔬东坡。
- 差距分两类：**① 模块级空白**（5 个模块零实现）；**② 模块内纵深缺口**（已建模块缺关键字段/规则）。

## 1. 项目现有实现盘点（实测）

### 1.1 后端模块（11 个）

```text
auth  common  customer  inventory  mall  marketing
order  product  purchase  supplier  system
```

控制器 30 个，Java 文件 474 个，Flyway 迁移 32 个，业务表约 54 张。

### 1.2 数据表（按领域）

| 领域 | 表 |
| --- | --- |
| 商品 | product_category、product_spu、product_sku、supplier_sku |
| 客户/定价 | customer、customer_type、customer_agreement_price（+操作日志）、customer_sku_visibility |
| 订单 | sales_order、sales_order_item、order_operation_log、order_return、order_return_item、order_refund |
| 采购 | purchase_demand（+allocation+generation_batch）、purchase_order（+item）、purchase_receipt（+item+confirmation+confirmation_item）、receipt_weighing_record |
| 库存 | inventory、inventory_movement |
| 商城/营销 | mall_customer_account、mall_customer_address、mall_customer_session、mall_cart_item、mall_order_address、marketing_coupon、marketing_customer_coupon、marketing_frequent_sku、marketing_home_section、marketing_promotion、marketing_theme_config |
| 系统 | sys_user、sys_role、sys_permission、sys_menu、sys_department、sys_dictionary（+item）、sys_config、sys_login_log、sys_operation_log 及各关联表 |
| 通用 | idempotency_record、SPRING_SESSION |

### 1.3 关键实现细节（决定差距判断）

- **定价**：`CustomerPriceResolver` + `customer_agreement_price`，规则为**协议价优先、市场价回退**；`customer_type` 存在但**无类型价表**。
- **库存流水**：`InventoryMovementType` 枚举**只有 `PURCHASE_IN` 一种**。
- **库存成本**：`inventory.averageCost` 字段存在，但**无成本计算服务**（无 CostService）。
- **订单状态**：`OrderStatus` 仅 `DRAFT / PENDING / CONFIRMED / CANCELLED` 四态，**未分离履约/结算状态**。
- **支付**：`SettlementMethod`（账期/货到付款/在线支付/余额充值）仅作为**展示用选项列表**存在于 marketing，**无实际支付、余额账户或结算闭环**。
- **打印**：全库**无打印/单据模板实现**。
- **分类**：`product_category` 有 `parentId` + `level`，**支持多级分类**。
- **SKU**：有 `barcode / specName / specValues / saleUnit / productType(标品非标品) / marketPrice / defaultSku`，**无别名、品牌、产地、多单位换算、起订量**。

### 1.4 前端与小程序

- Web：约 60 个页面组件，覆盖商品、客户、协议价、订单、退货退款、采购、库存、商城装修、系统管理。
- 小程序：仅 5 个页面 `home / category / cart / login / profile`。

## 5. 优先级建议

**P0 — 先补"已建模块的关键规则"（Sprint 5–6）**
1. 价格中心：客户类型价、阶梯价、客户折扣，统一取价优先级。
2. 订单生命周期：截单、审核、库存预占与释放、异常订单池。
3. 库存流水补全：至少补 `SALES_OUT / ADJUSTMENT / STOCKTAKE_*`，否则后续模块无法落账。

**P1 — 采购与仓储深化（Sprint 7–8）**
4. 询价 / 报价 / 比价 / 供应商评分；采购协议价。
5. 批次、库区库位、盘点、报损报溢、单位转换、CostService。

**P2 — 两个全新作业模块（Sprint 9–10）**
6. 分拣：波次、按商品/客户视角、称重、缺货、标签。
7. 配送：出库、装车、排线、司机、签收、异常。

**P3 — 结算与经营（Sprint 11–12）**
8. 应收应付、核销、对账、利润。
9. 溯源、损耗、BI、Open API。

**P4 — 长期（无明确排期）**
10. 供应商协同门户、移动作业端、在线支付与余额、设备接入、数据大屏、AI 录单、AGV。

## 6. 边界与提醒

- **差距 ≠ 待办清单。** 蔬东坡是运营 12 年的成熟 SaaS，本文列出的是"它有什么"，不是"我们都要做"。部分能力（AI 排线、AGV、完整总账、AI 录单）本项目已明确不做或列为长期。
- **先骨架后纵深。** 当前最大风险不是缺功能，而是**已建模块的规则未冻结**（价格优先级、订单状态模型、库存流水类型），这些不先补齐，Sprint 9–12 的新模块会反复返工。
- **库存流水类型是隐性阻塞项。** `InventoryMovementType` 只有 `PURCHASE_IN`，意味着出库、盘点、报损、调拨在数据层尚无落点，需在 Sprint 8 前先设计。
- **所有差距判断基于源码静态扫描**，未执行运行时验证；"待确认"项需业务或运行时证据补充。
