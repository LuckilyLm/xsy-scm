# 蔬东坡侧边栏功能与鲜蔬源需求对照

调查日期：2026-09-08
依据：[产品功能需求基线](../../requirements/产品功能需求基线.md) 的 13 个模块。
用途：供产品规划、web 页面设计和后续专项调研参考；不是新增开发范围或实现验收结果。

## 1. 结论与阅读导航

参考站的大部分核心业务都与我们的需求有关，但其菜单比需求更细，也有完整生产加工、积分、税务等额外能力。不宜照搬整套菜单。

本次逐个进入当前账号可见的 14 个一级入口，读取各模块当前选中的实际侧栏，排除页面中的隐藏旧菜单；另打开“管理员 → 配置”查看配置菜单。共记录：

| 范围 | 数量 |
| --- | ---: |
| 一级入口 | 14 |
| 业务二级菜单 | 133 |
| 管理员配置入口 | 16 |
| 纳入逐项映射的菜单 | 149 |
| 其中：直接对应需求主题 | 68 |
| 其中：部分对应或支撑能力 | 44 |
| 其中：需求外扩展 | 37 |

上述数字按菜单计数，不是需求覆盖率。同名的客户/采购对账及结算单分开计数；应用中心的功能卡片不包含在 149 项中。

- **先看本文**：按我们的 13 个模块理解对应关系、重点和证据缺口。
- **查具体菜单**：[侧边栏逐项需求映射明细](./侧边栏逐项需求映射明细.md)，逐项列出 149 个入口、对应程度和边界。
- **看页面细节**：[功能参考与借鉴记录](./功能参考与借鉴记录.md)。
- **看工作台布局**：[管理后台仪表盘参考](./管理后台仪表盘参考.md)。

“直接对应”只表示业务主题与原文相符，不能解释为菜单下所有功能均已验证。此次以菜单核对为主，没有逐个操作全部二级页面，更没有执行新增、修改、收货、支付、打印或发布。

## 3. 参考侧栏全貌

此处用于快速浏览，逐项链接与分类见明细文档。

### 首页

无普通二级菜单。主要内容为经营指标、趋势、待办、预警、客户数据和大屏入口。对应财务报表与后台管理，不必另外设计一套业务数据源。

### 商品（5 项）

商品档案、商品分类、辅助资料、商品图片、售卖情况。

其中价格、规格、采购归属和指定客户售卖在商品页内，不是全部独立成侧栏菜单。

### 溯源（9 项）

检测报告、溯源查询、设备记录、到期统计、检测属性、文件分类、企业信息、厂商管理、溯源配置。

原需求只明确一物一码，整套检测资料管理属于配套候选，不能自动全量纳入。

### 订单（10 项）

订单列表、订单商品、订单汇总、批量核价、智能定价、退货退款、实收变更、异常订单、订单标签、变更记录。

优先参考订单、售后、汇总、核价、异常和日志；智能定价和标签不是原文必需项。

### 采购（10 项）

采购单、智能预采、采购退回、采购情况、采购历史、计划统计、询价报价、询价记录、供应商、采购员。

“智能预采”不等于销售驱动采购；询价、采购退回是扩展。供应商和采购员是采购基础资源，也支撑商品默认采购设置。

### 加工（11 项）

销售汇总、生产加工、预生产、领料单、完工入库、退料单、产出比率、工人绩效、BOM 表、生产线、工人管理。

**整组不在当前功能清单明确范围内。** 这里的销售汇总服务于加工，不应与订单汇总生成采购需求混为一谈。商品多规格转换也不能作为引入 BOM 生产系统的理由。

### 库房（18 项）

商品分拣、客户分拣、预打包、分拣绩效、核验报表、发货出库、入库管理、出库管理、库存盘点、报损报溢、现有库存、出入库、原料分割、分割记录、分拣员、分拣框、仓库档案、期初库存。

这一组横跨我们的分拣与库存两大域。页面可以相互导航，但业务服务、状态变更和库存流水边界必须保持清楚。预打包、绩效、装框等不是首期必需；规格转换应另看应用中心的“商品转换”。

### 配送（8 项）

线路、物流排线、区域、司机、车辆、配送地图、实时监控、司机绩效。

前六项直接对应配送主题。实时监控的入口路径含 `video`，本次未深入验证，不能将其算作已满足线路轨迹记录。

### 客户（10 项）

客户档案、客户类型、集团管理、客户标签、客户看板、下单情况、订货历史、收货统计、协议价、客户积分。

档案、类型、集团、协议价是核心参考；数据页面也对应财务报表需求。标签、积分并非原文明确需求。

### 营销（11 项）

特价活动、优惠券、满减满赠、限时抢购、积分活动、商品预售、支付有礼、短信群发、新品需求、反馈建议、商品评价。

前四项直接匹配。新品需求是客户提需求，不是首页新品推荐；短信群发不是订单消息提醒。

### 商城（8 项）

首页设置、首页弹窗、商城模板、商城公告、服务条款、关于我们、售后规则、店铺。

这是商城运营配置，不是客户下单页面本身。购物车、分类、快捷下单在 H5/小程序端，应分别验证。

### 财务（15 项）

- 客户侧：客户结算、批量对账、客户费用、结算单、客户账款、客户余额。
- 采购侧：采购结算、批量对账、采购费用、结算单、采购账款。
- 其他：账期统计、支付流水、资金流水、发票开具。

两组“批量对账”“结算单”不是重复功能；对象分别是客户与供应商/采购。费用、发票不是原需求明确必需项。

### 报表（18 项）

营业数据、商品销量、订单统计、客户统计、支付报表、采购汇总、供货统计、价格波动、预估毛利、销售毛利、财务毛利、仓库毛利、利润表、进销存、损耗概况、采购损耗、库房损耗、退货损耗。

不需要复制全部毛利口径。先完成原文要求的经营、销售、采购、销售员业绩、单品与客户利润，再判断多层损耗和财务口径扩展。

### 应用

无普通业务二级菜单，以应用分类和卡片展示。相关项见下一节；应用说明仅作为功能线索，不代表账号已开通或行为已验证。

### 管理员 → 配置（16 个入口）

企业信息、系统参数、支付方式、原因管理、操作日志、失败日志、操作员、角色管理、送货时间、运营时段、微信配置、生活号、打印模板、新版打印、打印配置、系统还原。

员工管理、商城运营、第三方、打印是页面分组标题，不重复计数。角色入口带会话参数，文档不保存该链接；通过配置菜单人工定位即可。系统还原未打开或执行。

## 4. 应用中心里与需求相关的功能

来源：[应用中心](https://scm.sdongpo.com/cc_wangyan/superAdmin/viewCenter/v1/appCenter/list)。以下均为实际看到的卡片与介绍，不是执行结果。

| 应用卡片 | 对应需求 | 程度与注意点 |
| --- | --- | --- |
| 单据管理 | 订单补单 | 直接主题对应，介绍提到发货后加补商品；与我们补单状态规则仍需对照 |
| 自动打单、打印小票、分拣单调用规则 | 发货单/分拣小票及打印 | 直接主题对应；自动触发和按客户商品选模板不应默认全量照搬 |
| 自动生成采购单 | 自动生成采购单 | 部分对应：介绍为每日定时生成，原文强调订单实时汇总 |
| 采购助手（小程序） | 移动采购任务、收货 | 部分对应：未验证二维码分享、接单及重量回传 |
| 供应商后台、供应商端（小程序） | 供应商代分拣 | 直接主题对应：介绍明确商品分拣；任务授权与跨供应商隔离未验证 |
| 分拣阈值管理 | 分拣误差阈值 | 直接对应：介绍按分类设置，具体计算基准、容差单位与拦截方式待确认 |
| 商品转换 | 多规格转换 | 直接主题对应：介绍涉及规格/等级/包装转换；库存及成本算法未验证 |
| 车辆 GPS 定位、配送助手 | 线路轨迹及配送 | 部分对应：定位和移动配送相关，历史轨迹记录与回放未验证 |
| 集团管理后台 | 下属单位采购、集团管理 | 部分对应：集团下单/审核介绍不证明统一结算已满足 |
| 订单助手（小程序） | 订单助手 | 部分对应：介绍包括发货、退货、商品改价；“订单入库”没有精确证据 |
| 分拣软件（APP） | 实重分拣和打印 | 部分对应：看到 Windows/安卓分拣软件介绍，没有设备测试 |
| 掌上库房（APP） | 入库/盘点 | 部分对应：扫码作业补充，原文没有要求单独建设 APP |
| 商品溯源（小程序） | 扫码溯源 | 直接主题对应；扫码核验是另一种作业码，不能混同 |
| openAPI 权限管理 | 后台权限 | 仅部分相关，接口接入权限不能替代操作员/角色及业务数据权限 |
| AI 录单工作台、AI 订单导入、订单录入 AI 识别 | 智能语音下单、快速录单 | 只与录单相关；不能把 Excel/订单识别视为已具备语音下单 |

## 5. 尚未确认对应实现的原文要求

这些都是需求中明确存在的内容，但本轮没有足够证据判定参考站已完整实现。不是说网站没有，而是需要继续专项验证：

1. 业务员专属推广二维码，客户与供应商绑定的具体粒度。
2. 集团下属单位独立采购与集团统一结算的完整归属关系。
3. 采购二维码分享、实时接单、价格和重量回传，以及多次实重收货。
4. 分拣实秤读数到客户手机订单实重展示的完整同步链路。
5. 库存进价加权平均公式、规格转换成本以及库存和商城联动规则。
6. 配送多条件自动排线、历史线路轨迹和线路发货单一键打印。
7. 销售员业绩、单品利润、客户利润的准确报表维度和计算口径。
8. 订单消息提醒、角色操作权限粒度、日志实时性和全部单据模板编辑能力。
9. 客户登录后的常用菜品、再来一单、智能语音下单、账期/货到/在线/余额充值，以及客户商品汇总报表。
10. “订单助手针对订单进行入库操作”的精确业务含义与实际入口。

之前已验证 H5 首页/分类游客浏览以及后台部分列表和配置；这些证据不能替代上述客户登录、支付、硬件和事务行为的验证。
