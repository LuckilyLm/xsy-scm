调查日期：2026-09-08

本文提取目录组织、页面分层和交互实现思想，供 `xsy-scm-web` 及未来 `xsy-scm-miniapp` 参考。SmartAdmin 目录只读，不复制 Vue 源码、包名、接口、表名或业务模型。

## 1. 先明确技术边界

| 工程 | 参考技术栈 | 可借鉴范围 | 不应直接迁移 |
| --- | --- | --- | --- |
| SmartAdmin Web TypeScript | Vue 3 + TypeScript + Ant Design Vue + Pinia + Axios | 页面分层、查询表格、路由权限、字典和通用组件 | Vue SFC、Ant Design Vue API、Pinia store、旧版权限指令 |
| SmartAdmin Web JavaScript | Vue 3 + JavaScript + Ant Design Vue | 与上项相同，适合查看运行时写法 | JavaScript 代替当前 TypeScript、无类型接口 |
| SmartApp | UniApp + Vue 3 + Pinia | 移动页面拆分、下拉刷新、分页、平台请求、页面配置 | UniApp/Vue 技术栈、员工身份、原有 Bearer Token 约定 |
| 当前 xsy-scm-web | React 19 + TypeScript + Ant Design/ProComponents + React Router + TanStack Query + Axios | 当前项目事实源；新代码以此为准 | 不为模仿参考工程替换框架 |

当前 `xsy-scm-web` 已有严格 TypeScript、React Router 懒加载、TanStack Query、统一 `apiClient` 和 CSS Modules。参考工程的价值主要在信息架构与边界意识，不在具体语法。

## 2. SmartAdmin Web 的组织方式

参考 Web 将代码按职责和业务域拆分：

```text
src/
├─ api/                 # 按 business/support/system 分组的请求方法
├─ components/
│  ├─ business/         # 分类树、业务选择器
│  ├─ framework/        # loading、枚举等框架组件
│  └─ support/          # 字典、表格列设置、操作栏
├─ constants/           # 业务枚举、字典编码、表格 ID
├─ directives/          # 权限指令
├─ layout/              # 管理端壳
├─ lib/                 # Axios、错误上报、加解密
├─ router/              # 登录、首页、业务、帮助路由
├─ store/               # 用户、菜单、字典、应用配置
├─ theme/               # Ant Design 和项目主题
├─ types/               # 类型声明
└─ views/               # 按 system/business/support 分组页面
```

参考商品页面进一步拆出列表和表单：

```text
views/business/erp/goods/
├─ goods-list.vue
└─ components/
   └─ goods-form-modal.vue
```

对当前 React 的对应建议：

```text
xsy-scm-web/src/
├─ api/                 # 已有，按 product/customer/order/purchase 分组
├─ components/common/   # 已有 PageContainer、AmountText、StatusTag 等
├─ pages/<domain>/      # 页面与页面内部组件
├─ router/              # React Router
├─ stores/              # 仅放确有跨页面价值的客户端状态
├─ types/               # 请求、响应、页面模型
└─ styles/              # CSS Modules 与项目 token
```

业务页面应保持“页面负责编排、组件负责展示或局部交互、API 负责请求、服务端负责业务规则”。不要把计算价格、权限判断、状态流转或数据库含义隐藏到展示组件中。

## 3. Web 页面写法可借鉴点

### 3.1 查询页标准流程

参考商品页采用：

```text
查询区
→ 快速筛选
→ 操作栏
→ 表格
→ 分页
→ 新增/编辑弹层
```

查询区含分类树、关键字、字典选择、状态单选和查询/重置。表格提供批量选择、导入、导出、列设置、排序和行级操作。

当前 React 应优先使用已有 ProTable、ProForm、ProDescriptions 或项目通用组件；如果使用普通 Table，应明确处理分页、加载、空状态、错误和重试。筛选值应形成稳定的查询参数和 TanStack Query key，重置时回到明确默认值。

### 3.2 表单和详情

参考表单把新增和编辑共用一个表单模型，通过打开时重置默认值、编辑时覆盖记录、提交成功后关闭并刷新列表完成闭环。抽屉底部固定取消/提交操作。

当前项目的复杂业务采用独立全页编辑器更合适，尤其订单、采购和收货；简单主数据可以使用 Drawer。表单模型应与 API 请求模型分离，金额和重量使用字符串或明确的十进制转换，不能让 JavaScript 浮点数成为权威金额。

### 3.3 字典、枚举和状态

参考工程将代码枚举与可配置字典分开，页面通过 `SmartEnumSelect`、`DictSelect`、`DictLabel` 展示。

当前项目应继续遵守：订单、采购、库存等关键状态优先使用 Java Enum；只有确需运营配置的辅助选项才使用字典。状态标签集中到 `StatusTag` 等组件，不在每页散落同一套颜色和文字映射。

### 3.4 权限入口

参考工程在按钮上标记类似 `goods:add`、`goods:update`、`goods:delete` 的功能权限，并通过权限指令移除无权节点；路由守卫负责登录和动态菜单。

当前 React 应把权限表达为类型明确的 `Permission`/`AuthGuard` 或 hook，按钮隐藏只是体验层处理。服务端仍必须校验用户、角色、菜单/动作、API 和数据范围；危险操作继续要求确认和审计。不要照搬“直接从 DOM 删除无权节点”的指令实现。

### 3.5 表格效率

可借鉴的操作包括：列显示设置、列宽调整、固定操作列、服务端排序、批量选择、导入导出和全屏查看。参考工程会将用户列配置按表格 ID 保存。

当前实现应先确认确有多个页面需要列配置，再抽取共享能力。列配置不能改变服务端权限，也不能把隐藏列当作数据脱敏。导出接口应单独处理文件响应和错误响应。

### 3.6 错误、加载和网络请求

参考 Web 的 Axios 层集中处理 Token、响应码、网络超时、登录失效和下载文件；页面使用 loading、message 和错误上报。

当前 `xsy-scm-web/src/api/http.ts` 已经有更严格的 `ApiEnvelope`、`ApiError`、15 秒超时和统一错误转换，应以当前实现为准。参考工程中 `res.code && res.code !== 1` 这类宽松判断不应迁移；当前成功码是 `0`，错误需保留稳定错误码。页面错误应优先卡片内展示和重试，避免并发请求造成 Toast 风暴。

## 4. SmartApp 的移动端组织方式

SmartApp 使用 `pages.json` 注册页面，页面按业务目录组织，并把页面拆成列表、筛选弹窗、详情和统计等组件：

```text
src/
├─ api/system、api/business、api/support
├─ constants/system、constants/business、constants/support
├─ lib/smart-request.js、smart-sentry.js
├─ store/modules/system/user.js
├─ pages/home/components/
├─ pages/goods/components/
├─ pages/enterprise/
├─ pages/order-detail/components/
└─ uni_modules/
```

商品页面的典型流程是：

```text
初始化查询
→ 下拉刷新重置到第 1 页
→ 搜索或筛选重置列表
→ 上拉加载下一页并追加
→ 请求失败结束加载并上报
```

这套交互适合未来小程序商品浏览，但要重写为 Taro/React 或经批准的其他技术栈。客户端只提交筛选、SKU、数量和地址等输入；客户身份、可见性、当前价格和订单归属由服务端确定。

### 4.1 移动端页面规范建议

- 页面入口和底部导航集中配置；不在多个页面复制导航状态判断。
- 长列表必须支持下拉刷新、上拉分页、空状态、失败重试和重复触发保护。
- 筛选弹窗关闭后显示当前筛选条件摘要，并将查询条件与列表刷新绑定。
- 商品卡片统一显示名称、规格、单位、价格来源/状态、起订量、数量控制和加购动作。
- 订单详情拆成基本信息、商品明细、结算/收货等区块；显示订购数量与实际数量的差异。
- 登录失效统一清理客户会话并回到登录/绑定页；不得仅依靠页面是否显示“我的”来判断权限。
- 图片上传、预览、失败重试及大小限制集中封装；商品大图和附件不放进数据库实体。

## 5. 参考工程中应避免照搬的做法

1. SmartAdmin Web 和 App 都是 Vue；当前后台是 React，未来商城方案也优先延续 React，不能复制 `.vue` 文件。
2. 参考请求层使用 `Authorization: Bearer` 和自定义旧响应码；当前后台采用自己的 Spring Security Session/CSRF 方案，小程序客户身份需另行设计。
3. 参考工程存在直接使用全局 `document` 计算表格高度、移除 DOM 节点、页面内监听 `window.resize` 等做法。React 页面优先使用容器尺寸观察、条件渲染和组件生命周期清理。
4. 参考商品导入示例包含 mock 上传地址，不能进入正式项目；上传和导入必须走当前后端接口并验证文件类型、大小、权限和错误反馈。
5. 参考 App 的错误处理有重复 Toast，且 `console.log` 较多。生产代码不打印客户数据、Token、完整响应或敏感字段。
6. 参考配置中存在加解密、旧版本依赖和大量业务插件；引入前先证明必要性，不因参考工程使用就添加依赖。
7. 参考项目没有针对关键业务的测试文件；当前项目应按风险覆盖价格、权限、订单、收货、库存和设备确认，不以参考工程的测试缺失作为标准。
8. 参考工程的 `noUnusedLocals`、Vue ESLint 规则和 150 字符格式宽度不能直接替换当前 ESLint/TypeScript 配置。当前配置是项目事实源。

## 6. 当前项目可采用的编码约定

### Web React

- 每个页面按领域放入 `src/pages/<domain>/`，页面内部组件放 `components/`。
- API 方法按资源命名，输入和输出类型放在 `src/types/` 或页面同域类型文件；不在组件内拼接散落 URL。
- 服务端数据使用 TanStack Query，客户端临时交互使用 React state；不要把服务端列表复制到 Zustand。
- 使用 `import type`，保持当前 ESLint `consistent-type-imports` 规则。
- 复用 `PageContainer`、`AmountText`、`StatusTag` 和既有 token；新颜色和间距先检查 token。
- 复杂表单采用不可变 form model；提交按钮处理 loading、重复提交和服务端错误。
- API 统一经过当前 `apiClient`；不要重新创建一套 Axios 实例或旧响应码适配层。
- 重要操作提供确认、操作原因（如规则要求）和成功后的定向刷新；不通过整页强制刷新掩盖状态问题。
- 组件只负责展示和用户交互，价格、库存、权限、状态转移和审计由后端或领域服务负责。

### 未来小程序 / H5

- 与后台平级独立工程，页面、请求、客户会话和 Mall Theme 独立维护。
- 优先采用 Taro + React + TypeScript（须经小程序详细设计确认），目录可参考 SmartApp 的 page/api/constants 分层。
- 使用平台抽象的请求、存储、导航和上传适配器，避免页面直接依赖微信 API。
- 搜索、分类、购物车、结算、订单和“再来一单”均通过客户身份作用域访问。
- 价格、可见性、起订量、订购步长和非标品实际数量由服务端最终确认。
- 只在必要时引入移动端状态容器；购物车是否持久化、客户切换是否清空都需明确规则。
- 真机验收优先于 H5；至少覆盖登录失效、弱网、重复提交、无可售商品、规格切换和订单实重展示。

## 7. 建议的 Review 清单

提交 web 页面或未来小程序页面时，检查：

- 页面是否有明确的加载、空、错误、重试和成功状态。
- 查询条件是否可复现，分页/刷新是否会出现旧响应覆盖新查询。
- 权限是否同时存在于 UI 体验层和服务端 API 层。
- 金额、重量、价格来源和状态是否使用统一类型与格式化组件。
- 订单、采购、收货、库存等操作是否保留来源、版本、幂等和审计边界。
- 是否复用了现有组件和 token，是否无意引入第二套 UI 库或状态管理。
- 移动长列表是否处理下拉刷新、上拉加载、重复触发和弱网。
- 是否把 SmartAdmin 的 Vue、旧认证、mock 地址或敏感日志带入当前项目。
- 是否执行项目要求的 lint、typecheck、test、build；浏览器页面还需检查 Console、Network 和主要路径。
