# 登录与权限后端补充记录

本次按用户要求对照 SmartAdmin 补充通用登录、权限能力，仅开发后端，不修改前端，不运行测试。保留 Java 21、Spring Security、Spring Session JDBC、PostgreSQL 和既有 RBAC，不修改参考工程或原始 DOCX。

## 需求与现状

`docs/requirements/产品功能需求基线.md` 已包含“完善的权限管理配置，角色、操作权限自定义”和“系统日志实时记录”，因此权限与日志并非完全位于原需求之外。本记录补充原文未细化的安全边界及接口合同。

当前代码已具备账号登录/退出、BCrypt 密码校验、登录失败锁定、修改/重置密码、强制改密后端限制、用户/部门/角色/权限/菜单管理及授权分配。已有登录日志和系统操作日志表及写入逻辑，但缺少分页读取 API。

| 核对项 | 本次处理 |
| --- | --- |
| 登录事件缺少请求来源 | 登录成功、失败和锁定传入 IP、User-Agent；注销沿用已有采集 |
| 请求元数据超长会导致日志落库失败 | 按现有字段上限截断，去除控制字符；不记录密码、Cookie、Session ID |
| 登录审计失败与锁定后的会话清理失败被静默忽略 | 增加固定诊断消息，仅包含内部用户 ID、受控结果类型，不输出异常原文 |
| 登录/操作日志不可查询 | 增加分页、过滤和独立读取权限，只提供摘要查询 |
| 历史角色权限中的管理员 marker 被信任 | 管理员豁免只根据认证主体的 administrator 标识；权限 SQL 和两个身份读取入口排除角色授予的 marker |

## 接口合同

统一返回 `ApiResponse<PageData<T>>`。

| API | 必需权限 | 专用过滤字段 |
| --- | --- | --- |
| `GET /api/system/login-logs` | `system:login-log:list` | `userId`、`username`（精确匹配）、`result` |
| `GET /api/system/operation-logs` | `system:operation-log:list` | `actorUserId`、`module`、`operationCode`、`targetType`、`targetId`、`success` |

共同参数：`page` 默认 1，范围 1 至 2147483647；`pageSize` 默认 20，范围 1 至 100；`startTime` 和 `endTime` 为可选的带时区 ISO 8601 时间，包含边界，开始时间不能晚于结束时间。按 `occurred_at DESC, id DESC` 稳定排序。非法参数返回既有 400 校验响应。

登录结果限定为 `SUCCESS`、`FAILURE`、`LOCKED`、`LOGOUT`。未登录请求受既有认证入口控制，无相应权限返回 403。管理员使用既有统一管理员豁免；普通 `system.manage` 权限不能替代日志读取权限。日志路径下未注册的方法及子路径显式拒绝，不提供删除、修改或无界导出接口。

操作日志响应仅包含操作者、模块、动作、对象、结果、错误码和时间，不返回 before/after 原始 JSON 或请求内容。IP 使用 Servlet 的远端地址，不自行信任客户端传入的转发头；部署在反向代理后时，真实客户端地址依赖运维侧可信代理配置。

## 数据与会话

新增 `V26__audit_log_query_permissions.sql`，只增加两项权限，不修改已应用迁移、不自动授予普通角色。本次未执行迁移，应用部署时由 Flyway 执行。

Spring Session JDBC 是 Spring Session 的数据库存储实现，继续使用既有 PostgreSQL 会话表。本次没有更换会话技术，也没有引入新的依赖。

管理员判定的行为变化：仅包含 `system.administrator` 字符串的普通认证对象不再拥有管理员豁免；必须是携带管理员标识的项目认证主体。读取 SQL 同时排除异常历史 marker 关联，原数据库关联保留，不进行历史数据删除。
