# XSY-SCM PostgreSQL 建表脚本

本目录是 XSY-SCM 全库 **MySQL → PostgreSQL** 的转换结果，由 `deploy/tools/mysql2pg.py`
从 MySQL 结构自动生成，**已在 PostgreSQL 16 上完整验证**（建表 0 报错、数据逐行 MD5 一致）。

## 二、快速使用

```bash
# 1) 建库（UTF8；中文排序建议指定 collation）
psql -U postgres -c "CREATE DATABASE xsy_scm ENCODING 'UTF8' TEMPLATE template0;"

# 2) 一次性导入结构 + 数据
psql -U postgres -d xsy_scm -v ON_ERROR_STOP=1 -f all-in-one.sql

# 或：只建结构，不导数据
for f in 0*.sql; do psql -U postgres -d xsy_scm -v ON_ERROR_STOP=1 -f "$f"; done
```

`ON_ERROR_STOP=1` 建议保留，任何一句失败立即中断，避免出现半截库。

## 三、类型映射规则

| MySQL | PostgreSQL | 说明 |
|---|---|---|
| `tinyint` / `tinyint(1)` | `smallint` | **不映射为 boolean**。项目里 `xxx_flag`、`status`、`type` 在 Java 侧都是 `Integer`，映射成 boolean 会破坏 MyBatis 映射 |
| `smallint` | `smallint` | |
| `int` | `integer` | |
| `bigint` | `bigint` | |
| `decimal(p,s)` | `numeric(p,s)` | 金额 / 重量，语义与精度完全保留 |
| `varchar(n)` / `char(n)` | `varchar(n)` / `char(n)` | |
| `text` / `longtext` | `text` | |
| `datetime` | `timestamp`（即 `timestamp without time zone`） | |
| `date` | `date` | |
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | 81 个自增列 |
| `ON UPDATE CURRENT_TIMESTAMP` | **触发器** `xsy_set_update_time()` | PostgreSQL 无等价列属性，见下 |
| `unsigned` | 去掉 | PostgreSQL 无无符号整数 |
| `CHARACTER SET` / `COLLATE` / `ENGINE` / `ROW_FORMAT` | 去掉 | 由数据库编码统一决定 |

## 四、必须知道的三处行为差异

### 1. `ON UPDATE CURRENT_TIMESTAMP` → 触发器

MySQL 的「更新时自动刷新 update_time」在 PostgreSQL 里没有列级语法。转换脚本为
**85 张含 `update_time` 的表**各挂了一个 `BEFORE UPDATE` 触发器，并创建了公共函数：

```sql
CREATE OR REPLACE FUNCTION xsy_set_update_time() RETURNS trigger AS $$
BEGIN
  NEW.update_time := CURRENT_TIMESTAMP;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

如果业务代码里已经显式维护 `update_time`（SmartAdmin 的 `BaseEntity` 通常会在
Service 层赋值），可以把函数和触发器整段删掉，避免双重写入。

### 2. 自增序列必须重置（脚本已包含）

`GENERATED BY DEFAULT AS IDENTITY` 在**显式插入主键时不会推进序列**。数据是带着主键
导入的，所以脚本末尾对全部 81 个自增列执行了：

```sql
SELECT setval(pg_get_serial_sequence('t_category', 'category_id'),
              (SELECT COALESCE(MAX("category_id"), 0) + 1 FROM "t_category"), false);
```

**漏掉这一步，应用上线后第一条 INSERT 就会主键冲突。**

### 3. 索引 / 约束重名

MySQL 的索引名只在表内唯一，PostgreSQL 的索引名在 schema 内全局唯一。项目里有大量
重名索引（如 `idx_status`、`idx_create_time`、`idx_order_id`），转换时按
「首个保留原名，后续改为 `表名_原名`」处理，例如：

```
idx_create_time              保留在第一个使用它的表
t_order_idx_create_time      后续重名的表
```

字段名、表名、主键、唯一约束的**列组合**均未做任何改动。

## 七、尚未处理（切库时需要一并改造）

本目录只交付**数据库侧**的转换。真正切到 PostgreSQL 还需要改：

1. **JDBC 驱动与连接串**：`sa-base.yaml` 中 `jdbc:p6spy:mysql://...` → `jdbc:p6spy:postgresql://...`，
   `driver-class-name` 改为 `com.p6spy.engine.spy.P6SpyDriver` + `org.postgresql.Driver`，引入 `postgresql` 依赖。
2. **MyBatis-Plus 方言**：确认分页插件使用 `PostgreSqlDialect`。
3. **裸 SQL 兼容性**：XML 里的 `DATE_FORMAT`、`IFNULL`、`GROUP_CONCAT`、`LIMIT x,y`、
   反引号、`ON DUPLICATE KEY UPDATE` 等 MySQL 专有写法需要逐个改写。
   （本次已扫描确认：**没有字段名与 PostgreSQL 保留字冲突**，不用改字段名。）
4. **大小写**：PostgreSQL 未加引号的标识符会折叠为小写，本转换全部使用小写命名，裸 SQL 可直接使用。

## 八、重新生成

```bash
# 1) 从线上库导出结构 + 数据
mysqldump -h127.0.0.1 -P3306 -uroot --skip-comments --skip-extended-insert \
  --no-tablespaces --default-character-set=utf8mb4 supply_chain > live_full.sql

# 2) 转换（同时读取 deploy/sql/xsy_scm_v3.30.0_supply_chain.sql 补齐 P1 表）
python deploy/tools/mysql2pg.py
```

脚本会把无法翻译的语法、PG 保留字冲突、未消费的列修饰符全部打印出来，不会静默丢弃。
