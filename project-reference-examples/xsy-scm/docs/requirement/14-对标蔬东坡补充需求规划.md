# 14. 对标蔬东坡补充需求规划

> 本文档用于承接对标分析：以**蔬东坡 SaaS（生鲜食材供应链 ERP）公开更新日志**为参考，梳理 XSY-SCM 现有 13 个模块需求（[00-总览与通用约定.md](./00-总览与通用约定.md)）之外的**补充需求**。
> 对标来源：https://www.yuque.com/sdongpo/news （版本 `11.6`~`17.5`，2022.02~2026.09），正文经语雀公开 API 获取。
> 定位：本文件是**补充需求池与规划入口**，明确「哪些能力我们已覆盖、哪些要补、分几批做、归属哪个模块、新增哪些表」。
> 状态：**需求草案，待评审确认**。凡标注「待确认」的条目需业务方拍板后才能进入设计。
> 编码铁律仍以仓库根目录 `AGENTS.md` 为准，本文档所有设计不得与之冲突。

## 1. 目的与对标方法

1. **不重复造轮子**：先判定 XSY-SCM 已覆盖的能力，仅对**缺口**做补充设计。
2. **命名对齐行业**：新增能力尽量沿用蔬东坡的功能命名（如「商品转换单」「询价报价单」「生产批号」「无单收货」「预包装」「拣货规则模版」），降低业务沟通成本。
3. **口径先对齐已定决策**：凡与总览 §13 已确认口径冲突的蔬东坡能力，**以我们的口径为准**（如成本价税分离、多站点模式，见 §6）。
4. **优先级按主链路价值排序**：与「订单→采购→库存→分拣→配送→财务」主链路强相关的优先。
5. **可追溯**：每条补充需求标注蔬东坡来源版本号，便于后续回查原文。

#### 4.1.5 核心流程

1. **账号开通**：平台为供应商开通账号并分配权限，供应商通过小程序 / H5 登录（复用 `xsy-app`）。
2. **自助接单与分拣**：供应商查看分配给自己的采购任务，回填单价、重量、到货时间；按分拣模式执行分拣（见下）。
3. **商品提报与别名**：供应商提报商品 / 维护商品别名 → 平台审核 → 通过后生成 `t_product`（草稿态），进入 01 商品上架流程。
4. **检测报告与厂商维护**：开启溯源后，供应商可提前维护生产日期对应的检测报告与厂商资质（蔬东坡 17.5）。
5. **自助对账**：系统按周期（09 应付）生成对账单 → 供应商确认 → 财务结算；导出支持携带订单标签（蔬东坡 17.5）。
6. **售后处理**：供应商侧退换货与赔偿，联动 05 采购退货、09 财务冲销。

##### 供应商分拣模式（蔬东坡 17.1）

| 模式 | 说明 |
| --- | --- |
| 按采购任务实时分配 | 订单商品与采购任务**一对一**，采购任务变更实时同步供应商分拣端，采购单未生成也可提前分拣；禁用按量分配 |
| 采购单生成后 | 必须等采购单正式生成后，供应商才能按采购单分配项分拣 |
| 默认供应商 | 仅按默认优先级（客户指定 > 客户类型指定 > 商品默认）分拣，订单生成后不再受采购任务影响 |

> 供应商端展示规则：分拣列表严格按「订单商品绑定的供应商」展示；差异分拣、按下单时间查询、客户名称显隐均受后台配置控制（蔬东坡 16.5 / 17.5）。

#### 4.1.6 业务规则与约束

- 供应商数据范围强隔离：供应商**只能看到分配给自己的**采购单、分拣任务、对账单，禁止越权（复用 `@DataScope` 思路，扩展供应商维度）。
- 密码必须加密存储；账号变更（改密 / 禁用）后历史登录态立即失效，走统一鉴权，禁止自建第二套认证。
- 「最近一次进价」等敏感字段按**权限项**控制（仅查看 / 查看编辑），默认仅查看。
- 商品提报通过后不直接上架，必须走 01 商品审核 / 上架流程。
- 对账单金额以 09 应付为唯一来源，不单独维护金额。
- 账号变更 / 提报审核 / 厂商资质变更必须留审计日志。

#### 4.1.7 主要接口与页面

- 供应商工作台：待接单、待分拣、待回填、对账单、报表
- 商品提报与别名维护：提交、审核（后台）、状态查询
- 厂商管理：厂商信息、资质证件、质检报告（蔬东坡 17.5）
- 对账单：生成（后台）、确认（供应商）、结算记录
- 售后：申请、审核、处理

### 4.2 模块 15：数据大屏

#### 4.2.1 功能概述

数据大屏面向**经营决策与现场看板**，聚合订单、库存、配送、溯源、分拣绩效五类实时指标。核心是**只读聚合 + 大屏渲染**，不产生新的业务数据，数据来源全部复用现有模块。

#### 4.2.2 业务对象

| 对象 | 说明 |
| --- | --- |
| 经营大屏 | 收入、成本、毛利、订单量、客户数等 |
| 库存大屏 | 库存余额、周转、预警、成本 |
| 配送大屏 | 线路进度、司机轨迹、准时率、在途车辆（蔬东坡 16.5） |
| 溯源大屏 | 批次量、扫码量、监管对接状态（蔬东坡 17.4，支持按分类设置展示） |
| 分拣绩效大屏 | 分拣员排名、包裹数、分拣数量、分拣重量（蔬东坡 16.5） |

#### 4.3.4 状态机

##### 凭证同步状态 `sync_status`

| 值 | 含义 | Java | 可流转到 |
| --- | --- | --- | --- |
| 1 | 未同步 | `UNSYNCED` | 2、4 |
| 2 | 同步中 | `SYNCING` | 3、4 |
| 3 | 同步成功 | `SYNCED` | —（终态） |
| 4 | 同步失败 | `FAILED` | 2 |

##### 发票状态 `status`

| 值 | 含义 | Java | 可流转到 |
| --- | --- | --- | --- |
| 1 | 可开票 | `INVOICEABLE` | 2 |
| 2 | 已开票 | `INVOICED` | 1（全部红冲后回到可开票）、3 |
| 3 | 已红冲 | `RED_FLUSHED` | —（终态） |

#### 4.3.5 核心流程

1. **凭证生成**：由应收应付 / 收付款 / 费用单（运费、押金筐、服务费）选择单据生成凭证，借贷分录按科目映射（蔬东坡 17.1）。
   - 订单运费：借 应收账款；贷 主营业务收入。
   - 押金筐及退筐：借 / 贷 应收账款与主营业务收入，按业务方向。
2. **同步推送**：按配置将客户、供应商、采购员、商品分类、单据同步至金蝶 / 用友；成功后**回写外部单号**。
3. **字段映射配置**：支持存货分类、客户分类与部门、供应商分类与部门、采购员分类与部门、销货/进货单部门与业务员等维度（蔬东坡 17.4 / 17.5 / 16.5）。
4. **异常处理**：同步失败可将单据置为「未同步」后重新发起；失败原因写同步日志。
5. **开票**：待开票订单提交开具 → 红冲 → 关联发票联动整单红冲（蔬东坡 17.1）。

#### 4.3.6 业务规则与约束

- 凭证**借贷必须平衡**（借方合计 = 贷方合计），不平衡禁止保存 / 推送。
- 金额口径与 09 财务报表一致（不含税、`HALF_UP` 到分）；科目映射关系需可配置。
- 密钥、`app_secret` 必须加密存储并可轮换，**禁止硬编码提交 Git**（遵循 `AGENTS.md` §18）。
- 同步必须幂等，重复推送不得生成重复凭证（唯一约束 + 幂等键）。
- 推送失败可重试，重试与结果写同步日志。
- 外部对接为异步，不得阻塞收付款主流程。
- 开票 / 红冲依赖第三方接口，需按**离线任务**处理并支持主动查询红冲状态。

#### 4.3.7 主要接口与页面

- 凭证管理：列表、详情、手工生成、推送
- 外部系统配置：参数维护、字段映射、连通性测试
- 同步日志：结果查询、失败重试
- 发票管理：待开票 / 已开票、开具、红冲、关联发票
- 编号前缀：凭证 `PZD`（`PZD202609070001`）

## 6. 需业务决策的冲突点

以下蔬东坡能力与 XSY-SCM 已确认口径或铁律**存在冲突**，需业务方拍板：

| # | 冲突点 | 蔬东坡做法 | 我们的现状 | 建议 |
| --- | --- | --- | --- | --- |
| C-1 | **反审核** | 退货退款 / 入库 / 实收变更支持反审核 | 总览 §5 已定「终态不回流，走冲销 / 反向单据」 | 二选一：维持冲销（推荐）或引入受控反审核 |
| C-2 | **多站点模式** | 17.3 多站点下单、单站点多小程序 | G-07 已定**单组织** | 明确不做，除非确有多站点诉求 |
| C-3 | **成本价税分离** | 12.2 库存成本价税分离 | G-02 已定**全部不含税** | 直接跳过 |
| C-4 | **批次与保质期** | 生产批号、批次库存、库区库位管理 | G-03 已定**不启用批次与保质期** | 生产批号模式可**解耦**库存批次引入（蔬东坡 17.5 同思路），建议采纳；库区库位暂不引入 |
| C-5 | **折扣率叠加** | 计算折前价 / 折后价、按维度折扣 | 01-01 已定取价「不叠加」 | 明确折扣率在取价链中的位置与是否可与其他价叠加 |
| C-6 | **规则模版拣货 / AGV** | 拣货规则模版、智能分拣机器人 | 07 为固定两种分拣模式 | 规则模版建议采纳；AGV 列为远期 |
| C-7 | **负库存 / 负毛利** | 负毛利禁止出库、实时库存校验 | 06-03「是否允许负库存」待确认 | 结合实时售卖库存校验一并决策 |
