# 10. 后台管理

> 原始需求（摘自 `功能清单模块.docx`）：
> - 各类单据自定义：采购单、发货单、分拣小票等；
> - 完善的权限管理配置，角色、操作权限自定义；
> - 系统日志实时记录；
> - 待办事项显示；
> - 帮助中心提供各种操作指南。

> 重要说明：本模块**大量复用 SmartAdmin 内置能力**。按 `AGENTS.md` 铁律，禁止重复造权限、日志、分页、异常、返回结构等轮子；以下逐项标注「复用」与「新建」，避免二开时做无用功。

## 1. 功能概述

后台管理是系统支撑层：单据模板、权限、日志、待办、帮助中心。除**单据模板自定义**与**待办事项**需要新建外，其余主要复用 SmartAdmin 内置能力并做业务适配。

## 2. 能力归属：复用 vs 新建

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 角色与操作权限配置 | **复用** | 使用 SmartAdmin 内置角色 / 菜单 / 权限点体系，仅补充业务权限点 |
| 数据范围（业务员看自己的客户） | **复用** | 使用 `@DataScope`，配置部门 / 员工 / 自定义策略 |
| 系统日志 | **复用** | 使用内置操作日志与登录日志，不自建第二套 |
| 帮助中心 / 操作指南 | **复用** | 使用内置帮助文档模块，关联到菜单与页面 |
| 字典 / 数据字典 | **复用** | 使用内置字典能力 |
| 单据自定义（采购单 / 发货单 / 分拣小票） | **新建** | 模板配置与打印渲染 |
| 待办事项 | **新建** | 业务待办聚合与提醒 |
| 重复提交 / 限流 | **复用** | 使用 `@RepeatSubmit` |

## 3. 关键字段

### t_print_template（单据模板）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `template_id` | BIGINT | 主键 |
| `template_code` | VARCHAR | 模板编码（`PURCHASE` / `DELIVERY` / `SORT_TICKET` 等） |
| `template_name` | VARCHAR | 模板名称 |
| `biz_type` | TINYINT | 业务类型：采购单 / 发货单 / 分拣小票 / 其他 |
| `content` | TEXT | 模板内容（HTML / 模板引擎） |
| `paper_size` | VARCHAR | 纸张规格（A4 / 小票 58mm / 80mm 等） |
| `default_flag` | TINYINT | 是否默认模板 |
| `status` | TINYINT | 启用 / 停用 |

### t_todo（待办事项）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `todo_id` | BIGINT | 主键 |
| `biz_type` | TINYINT | 业务类型（订单待确认 / 采购待收货 / 退款待审 / 报损待审 / 应收逾期等） |
| `biz_id` | BIGINT | 业务单 ID |
| `title` | VARCHAR | 待办标题 |
| `assignee_id` | BIGINT | 接收人（按角色 / 人） |
| `due_time` | DATETIME | 截止时间 |
| `status` | TINYINT | 待处理 / 已处理 / 已关闭 |

## 4. 状态机

### 模板状态

| 状态 | 说明 |
| --- | --- |
| `ENABLED` 启用 | 当前可用 |
| `DISABLED` 停用 | 停用，打印时不可选 |

### 待办状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `PENDING` 待处理 | 已生成 | 已处理、已关闭 |
| `DONE` 已处理 | 业务已处理（终态） | — |
| `CLOSED` 已关闭 | 作废 / 无需处理（终态） | — |

## 5. 核心流程

### 5.1 单据模板配置与打印

1. 在后台维护模板（编码、业务类型、纸张、内容）。
2. 业务环节（采购 / 发货 / 分拣）选择模板渲染预览。
3. 支持一键批量打印（如线路发货单批量打印，见 08 物流配送）。
4. 打印内容包含单据号、客户 / 供应商、商品、实重、金额、二维码。

### 5.2 权限配置

1. 在系统内置角色基础上配置业务菜单与操作权限点。
2. 配置数据范围（业务员仅看自己的客户 / 订单，采购员仅看自己的采购单）。
3. 后端接口必须真实校验，前端仅做按钮级展示控制。

### 5.3 待办聚合

1. 各业务环节在状态变更时生成待办（如订单待确认、退款待审、应收逾期）。
2. 按角色 / 人聚合展示在首页待办区。
3. 处理后关闭待办；业务状态回退时重新激活（规则待确认 10-04）。

## 6. 业务规则与约束

- **禁止重复造轮子**：权限、日志、分页、异常、统一返回结构、Bean 转换必须使用现有能力（`AGENTS.md` 明列）。
- 权限校验必须在后端生效，前端隐藏按钮不构成权限控制。
- 系统日志不得记录密码、token、密钥、完整身份证 / 银行卡等敏感数据。
- 模板内容不得硬编码客户 / 公司敏感信息；打印走服务端渲染，避免前端篡改金额。
- 待办生成需限流 / 去重，避免同一业务重复产生待办。
- 帮助中心内容需与业务页面分离维护（复用内置帮助文档模块）。

## 7. 主要接口与页面

- 模板管理：列表、编辑、预览、启用停用、设为默认
- 打印：单张 / 批量打印（采购单、发货单、分拣小票）
- 权限：角色、菜单、操作权限点、数据范围配置
- 日志：操作日志、登录日志查询
- 待办：首页待办列表与跳转
- 帮助中心：操作指南维护与页面关联
