# 04. 订单管理

> 原始需求（摘自 `功能清单模块.docx`）：
> - 支持商城下单、后台快速录单、订单消息提醒；
> - 支持补单、订单核算、实际称重数据同步到客户手机端显示；
> - 完善的退款、退货机制，异常订单分析报表；
> - 订单操作日志显示。

## 1. 功能概述

订单是供应链的驱动源头：上游驱动采购，下游驱动分拣、配送与财务。订单侧的核心约束是**价格快照**与**实重回写**——下单时锁定价格，履约后按实际重量核算，并把实际重量同步给客户。

## 2. 业务对象

| 对象 | 说明 |
| --- | --- |
| 订单 | 主单（客户、结算方式、金额、状态） |
| 订单明细 | 商品 / 规格、下单量、成交价快照、实重、核算金额 |
| 订单操作日志 | 全量操作留痕（含改价、取消、退款） |
| 补单 | 原单追加商品 |
| 退款单 / 退货单 | 逆向流程 |

## 4. 状态机

### 订单状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `DRAFT` 草稿 | 后台录单未提交 | 待确认、已取消 |
| `PENDING` 待确认 | 已提交未确认 | 已确认、已取消 |
| `CONFIRMED` 已确认 | 确认可履约 | 采购中、已取消 |
| `PURCHASING` 采购中 | 已汇总生成采购单 | 待分拣、已取消 |
| `SORTING` 待分拣 | 货已到位待分拣 | 分拣中、已取消 |
| `SORTED` 分拣中 | 分拣进行中 | 待配送 |
| `DELIVERING` 配送中 | 已发车配送 | 已签收 |
| `SIGNED` 已签收 | 客户签收 | 已完成、退款中 |
| `COMPLETED` 已完成 | 核算完成（终态） | 退款中（走逆向） |
| `REFUNDING` 退款中 | 逆向处理中 | 已完成、已退款 |
| `CANCELLED` 已取消 | 取消（终态） | — |
| `INVALID` 已作废 | 作废（终态） | — |

### 支付状态

| 状态 | 说明 |
| --- | --- |
| `UNPAID` 未付 | 账期 / 货到付款未结 |
| `PARTIAL` 部分支付 | 已付部分 |
| `PAID` 已付 | 结清 |

### 退款状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `PENDING` 待审核 | 提交申请 | 已通过、已驳回 |
| `APPROVED` 已通过 | 审核通过 | 已退款 |
| `REFUNDED` 已退款 | 完成退款（终态） | — |
| `REJECTED` 已驳回 | 审核不通过（终态） | — |

## 5. 核心流程

### 5.1 下单（商城 / 后台录单）

1. 选择客户，系统按客户分级 / 协议价取价。
2. 选商品（受客户商品可见性过滤），加入购物车或录单明细。
3. 计算金额：明细小计 → 促销优惠 → 优惠券 → 应付金额。
4. 选择结算方式，提交订单。
5. **价格写入订单明细快照**（`snapshot_price`），后续改价不影响本单。
6. 消息提醒相关角色（业务员、采购、客户）。

### 5.2 履约与实重回写

1. 订单汇总进入采购（见 05 采购管理）。
2. 收货 / 分拣得到实际重量 `actual_weight`。
3. 系统按实重重算明细金额 `item_amount` 与订单 `actual_amount`（订单核算）。
4. 实重数据同步到客户手机端（订单助手 / 商城订单详情）展示。

### 5.3 补单

1. 在原订单基础上追加明细（同客户、可合并配送）。
2. 补单生成新明细或关联子单（实现口径待确认 04-03）。
3. 重新触发汇总与采购需求。

### 5.4 退款 / 退货

1. 客户或客服发起，选择整单或部分明细。
2. 填写原因，提交审核。
3. 审核通过后：生成退款单、冲销应收或原路退回；退货需生成退货入库流水。
4. 库存回滚（退货入库），财务冲销。

### 5.5 异常订单分析

按维度统计：超时未确认、长时间未发货、拒收、频繁退款、金额异常，输出报表供运营跟进。

## 6. 业务规则与约束

- **价格快照**：订单明细必须保存下单时成交价，禁止关联实时商品价格核算（遵循 `AGENTS.md`）。
- 金额 `DECIMAL(18,2)`、重量 `DECIMAL(18,3)` kg、单价 `DECIMAL(18,4)`；**中间计算保留 4 位、最终金额 `HALF_UP` 四舍五入到分**（G-04 已定，见总览 §13）。
- 改价、取消、退款必须留审计日志；订单操作日志需完整可查。
- 订单、退款记录不允许物理删除（状态作废 / 冲销）。
- 状态流转必须走状态机，禁止直接改 `status`。
- 在线支付与退款需防重复提交（`@RepeatSubmit`）与幂等键。
- 数据范围：业务员只看自己客户的订单。
- 消息提醒复用现有通知机制，不自建第二套。

## 7. 主要接口与页面

- 订单列表：多条件查询、状态筛选、导出
- 订单详情：明细、价格快照、实重、操作日志、物流信息
- 后台快速录单：客户选择 + 商品快速检索 + 批量录入
- 改价 / 取消 / 退款：审批与留痕
- 订单核算：按实重重算金额
- 异常订单报表
