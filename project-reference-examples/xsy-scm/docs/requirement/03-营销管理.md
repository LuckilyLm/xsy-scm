# 03. 营销管理

> 原始需求（摘自 `功能清单模块.docx`）：
> - 定制首页、设置抢购促销活动、新品推荐版块；
> - 满减满赠、优惠券、限时特价；
> - 商品搜索、常用菜品、分类下单、购物车、再来一单、智能语音下单；
> - 四种结算方式：账期支付、货到付款、在线支付、余额充值。

> 说明：本模块偏 C 端商城运营能力，其中「商品搜索 / 常用菜品 / 分类下单 / 购物车 / 再来一单 / 语音下单 / 结算方式」同时属于下单商城交互，字段与流程与 [11-下单商城.md](./11-下单商城.md) 有交叉，本模块聚焦**运营后台配置**，下单商城聚焦**C 端交互**。

## 1. 功能概述

营销模块提供首页装修、促销活动（抢购 / 限时特价 / 满减满赠 / 优惠券）配置能力，并定义下单侧的基础交互与四种结算方式。核心是**促销与价格体系的叠加规则**。

## 2. 业务对象

| 对象 | 说明 |
| --- | --- |
| 首页装修 | 轮播 / 楼层 / 版块配置 |
| 促销活动 | 抢购、限时特价、满减满赠 |
| 优惠券 | 发放、领取、使用、核销 |
| 新品推荐 | 推荐版块商品池 |
| 常用清单 | 客户常用菜品（常购商品） |
| 购物车 | C 端临时选购容器 |
| 结算方式 | 账期支付 / 货到付款 / 在线支付 / 余额充值 |

## 4. 状态机

### 活动状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `DRAFT` 草稿 | 新建未提交 | 待审核、作废 |
| `PENDING` 待审核 | 提交待审 | 进行中、草稿 |
| `RUNNING` 进行中 | 生效中 | 已结束、已作废 |
| `FINISHED` 已结束 | 到期自然结束（终态） | — |
| `INVALID` 已作废 | 人工终止（终态） | — |

### 优惠券状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `NOT_ISSUED` 未发放 | 已创建未发放 | 已领取 |
| `RECEIVED` 已领取 | 客户已领未使用 | 已使用、已过期 |
| `USED` 已使用 | 已核销（终态） | — |
| `EXPIRED` 已过期 | 超过有效期（终态） | — |
| `INVALID` 已作废 | 人工作废（终态） | — |

### 结算方式（订单侧取值）

| 值 | 说明 |
| --- | --- |
| `CREDIT` 账期支付 | 按客户账期记账，后续应收收款 |
| `COD` 货到付款 | 配送签收时收款 |
| `ONLINE` 在线支付 | 下单即支付（对接支付渠道） |
| `BALANCE` 余额充值 | 扣减客户余额账户 |

## 5. 核心流程

### 5.1 促销活动配置

1. 创建活动（类型、时间、规则、适用范围）。
2. 提交审核 → 进行中。
3. C 端下单时命中活动，按规则计算优惠。
4. 活动到期自动转为已结束；异常可人工作废。

### 5.2 C 端下单结算

1. 商品搜索 / 分类浏览 → 加入购物车。
2. 购物车确认 → 选择结算方式。
3. 系统取价（商品价）→ 应用促销与优惠券 → 计算应付金额。
4. 提交订单（价格写入订单快照）。
5. 按结算方式走后续流程：账期记账 / 货到付款 / 在线支付 / 余额扣减。

### 5.3 再来一单

1. 客户选择历史订单。
2. 系统按订单明细重建购物车（校验商品是否上架、是否屏蔽、价格是否变化）。
3. 失效商品提示并剔除。

## 6. 业务规则与约束

- 金额 `DECIMAL(18,2)`，禁止 `double` / `float`。
- **订单价格必须使用快照**：下单时把最终成交价写入订单，后续改价 / 活动变更不影响已生成订单（遵循 `AGENTS.md`）。
- 促销与协议价 / 分级价是否可叠加必须明确（待确认 03-01），系统需在下单时给出唯一取价结果并记录取价依据。
- 优惠券核销需防并发重复使用（唯一约束 / 幂等键）。
- 在线支付需处理重复提交（复用 `@RepeatSubmit`）与支付回调幂等。
- 余额扣减必须生成财务流水，不允许直接改 `balance`。
- 语音下单为增强能力，需降级为手工录入通道（识别失败时可用）。

## 7. 主要接口与页面

- 活动管理：列表、创建、审核、作废、效果查看
- 优惠券管理：创建、发放、核销记录
- 首页装修：版块配置与预览
- 常用清单 / 购物车：C 端接口（详见下单商城）
- 结算：四种结算方式的订单提交接口
