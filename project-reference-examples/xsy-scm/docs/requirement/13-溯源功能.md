# 13. 溯源功能

> 原始需求（摘自 `功能清单模块.docx`）：
> - 一物一码扫码溯源。

## 1. 功能概述

溯源为商品提供「一物一码」的全链路追溯能力：客户扫码可查看商品的来源、批次、流通与检测信息。这是原始清单中**唯一没有现成框架能力可复用**的模块，需要新建。

本模块**溯源颗粒度已定：按批次溯源（一码一批）**（13-01 / G-08，见总览 §13）。数据来源与展示内容中的部分细节仍待确认。

## 2. 业务对象

| 对象 | 说明 |
| --- | --- |
| 溯源码 | 唯一码（二维码），绑定批次或单件 |
| 溯源批次 | 生产 / 采购批次（来源、产地、日期） |
| 溯源节点 | 全链路环节记录（采购、入库、分拣、配送、签收） |
| 检测信息 | 质检 / 检疫报告（可选） |
| 扫码记录 | 扫码查询日志（可选，用于防窜货 / 统计） |

## 4. 状态机

### 溯源码状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `CREATED` 未启用 | 已生成未绑定 / 未启用 | 已启用、已作废 |
| `ENABLED` 已启用 | 可扫码查询（终态） | 已作废 |
| `INVALID` 已作废 | 作废（如错码，终态） | — |

### 批次状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `VALID` 有效 | 在有效期内 | 已过期、已作废 |
| `EXPIRED` 已过期 | 超过保质期（终态） | — |
| `INVALID` 已作废 | 人工作废（终态） | — |

## 5. 核心流程

### 5.1 生成溯源码

1. 采购入库或生产环节创建批次（来源、产地、日期、检测报告）。
2. 按颗粒度生成溯源码：
   - **按批次（已定，采用）**：一个批次一个码，同批次商品共用一个码。
   - ~~按单件~~：不采用（成本高，需产线赋码）。
3. 生成二维码并存储（文件服务），状态置为已启用。

### 5.2 采集溯源节点

1. 关键环节自动写入节点：采购入库、库存出入库、分拣、配送、签收。
2. 节点关联业务单 `biz_id`，记录时间与操作人。
3. 检测报告作为独立节点或挂批次。

### 5.3 扫码查询

1. 客户 / 消费者扫码（微信 / 商城内扫码）。
2. 系统按码查询批次与节点链路。
3. 展示：商品、产地 / 供应商、批次日期、检测报告、全链路时间轴。
4. 记录扫码日志（可选，用于统计与防窜货）。

## 6. 业务规则与约束

- 溯源码必须唯一（唯一索引），生成防重复。
- 二维码走文件服务，禁止硬编码公网 URL。
- 溯源节点数据来自各业务模块，需保证与业务单一致（不单独维护一套来源数据）。
- 扫码查询为公开接口时，必须防刷（限流）且不得泄露内部敏感信息（如成本、供应商联系方式等需脱敏的字段待确认 13-05）。
- 采用按批次溯源，不涉及单件赋码成本与产线改造。
- 批次与库存批次的关联口径需与库存模块一致（待确认 G-03 批次启用与否直接影响本模块）。

## 7. 主要接口与页面

- 批次管理：创建批次、维护产地与检测报告
- 溯源码管理：生成、绑定、作废、导出
- 扫码查询页（C 端公开）：商品、链路时间轴、检测报告
- 扫码统计（后台）：扫码次数、地区分布
