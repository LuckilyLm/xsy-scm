# 12. 订单助手

> 原始需求（摘自 `功能清单模块.docx`）：
> - 支持手机端改价、编辑订单；
> - 支持针对订单进行入库操作。

## 1. 功能概述

订单助手是面向**内部人员（业务员 / 采购 / 仓管）**的移动端轻量操作入口，用于在手机端快速处理订单变更与入库，不追求完整后台功能。载体为 `xsy-app`（UniApp Vue3）内的功能模块或独立入口。

## 2. 业务对象

| 对象 | 说明 |
| --- | --- |
| 订单 | 复用 04 订单管理的订单与明细 |
| 改价记录 | 订单明细价格变更（审计） |
| 入库单 | 针对订单发起的入库（如直送 / 现场收货） |

## 3. 关键字段

主要复用已有表：

| 用途 | 复用来源 |
| --- | --- |
| 订单与明细 | `t_order` / `t_order_item` |
| 改价审计 | `t_order_log`（`operate_type` = 改价），或复用 DataTracer |
| 入库 | `t_receive` / `t_stock_flow`（见 05 采购管理、06 库存管理） |

新增 / 扩展字段建议：

| 字段 | 表 | 说明 |
| --- | --- | --- |
| `mobile_operate_flag` | `t_order_log` | 标记来源为移动端（可选，便于统计） |
| `source` | `t_stock_flow` | 业务来源标记：订单助手入库 |

## 4. 状态机

### 改价

改价不改变订单主状态，但必须满足：

| 前置状态 | 是否允许改价 |
| --- | --- |
| 草稿 / 待确认 / 已确认 | 允许 |
| 采购中及以后 | 需审批（规则待确认 12-03） |
| 已完成 / 已取消 / 已作废 | 禁止 |

### 入库

入库生成库存流水，遵循库存状态约束（见 06 库存管理）：

| 环节 | 说明 |
| --- | --- |
| 登记 | 录入数量与实重 |
| 生成流水 | 生成入库流水（终端态） |
| 更新余额 | 由库存业务层重算加权平均成本 |

## 5. 核心流程

### 5.1 手机端改价

1. 业务员在手机端打开订单，选择要改价的明细。
2. 输入新单价（或新金额），系统校验改价权限与订单状态。
3. 提交后写入订单明细价格，并**记录改价审计日志**（修改前后值、操作人、时间）。
4. 重算订单金额；若已生成应收，需同步调整应收或走差异处理（待确认 12-04）。

### 5.2 手机端编辑订单

1. 修改订单明细（增减商品、改数量）。
2. 修改配送信息（时间、地址）。
3. 提交后同步订单与明细，记录操作日志。
4. 若已触发采购 / 分拣，需提示影响并走变更流程（待确认 12-02）。

### 5.3 针对订单入库

1. 在订单详情发起入库（现场收货 / 直送场景）。
2. 录入实收数量与**实重**。
3. 生成入库流水，由库存业务层更新余额与加权平均成本。
4. 回写订单明细实重，驱动订单核算。

## 6. 业务规则与约束

- **改价必须留审计日志**（`AGENTS.md` 明列的审计项：改价）。
- 入库必须生成库存流水，禁止直接 `UPDATE` 库存余额。
- 重量 `DECIMAL(18,3)` kg，单价 `DECIMAL(18,4)`，金额 `DECIMAL(18,2)`。
- 移动端接口必须做与 PC 端一致的后端权限校验，不能因入口不同而放宽。
- 改价需防重复提交（`@RepeatSubmit`）。
- 数据范围：业务员只能改自己客户的订单。
- 移动端网络不稳定，提交需幂等（幂等键 / 唯一约束）。

## 7. 主要接口与页面

- 订单列表（移动端）：我的订单、待处理
- 订单详情：明细、改价、编辑、入库入口
- 改价页：单价修改、原因、提交
- 入库页：数量 / 实重录入、提交
- 操作记录：本人操作日志
