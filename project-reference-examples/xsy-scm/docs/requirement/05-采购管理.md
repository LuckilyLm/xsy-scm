# 05. 采购管理

> 原始需求（摘自 `功能清单模块.docx`）：
> - 订单实时汇总，按供应商、采购员、品类自动生成采购单；
> - 采购单二维码分享，实时接受任务、传输单价、重量等信息；
> - 多次收货、实重收货。

## 1. 功能概述

采购把客户订单转换为对供应商的采购需求，是「以销定采」的核心环节。核心能力是**订单自动汇总生成采购单**、**二维码协同**与**多次实重收货**。

## 2. 业务对象

| 对象 | 说明 |
| --- | --- |
| 采购需求汇总 | 按维度汇总订单明细产生的待采量 |
| 采购单 | 对某供应商的采购任务 |
| 采购明细 | 商品 / 规格、采购量、单价 |
| 收货单 | 每次收货的实收记录（支持多次） |
| 供应商 | 基础档案（复用 / 新建） |

## 4. 状态机

### 采购单状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `PENDING` 待接单 | 已生成待采购员 / 供应商接单 | 采购中、已取消 |
| `PURCHASING` 采购中 | 已接单，采买中 | 部分收货、已取消 |
| `PARTIAL_RECEIVED` 部分收货 | 已发生收货未收齐 | 部分收货、已完成 |
| `COMPLETED` 已完成 | 收货收齐并入库（终态） | — |
| `CANCELLED` 已取消 | 取消采购（终态） | — |

### 采购明细状态

| 状态 | 说明 |
| --- | --- |
| `PENDING` 待收 | 未收货 |
| `PARTIAL` 部分收 | 已收部分 |
| `DONE` 已收齐 | 收齐 |

### 收货单状态

| 状态 | 说明 | 可流转到 |
| --- | --- | --- |
| `RECEIVED` 已收 | 已登记实收 | 已入库、已作废 |
| `STOCKED` 已入库 | 已生成库存流水（终态） | — |
| `INVALID` 已作废 | 作废（终态） | — |

## 5. 核心流程

### 5.1 订单汇总生成采购单

1. 系统按维度（供应商 / 采购员 / 品类）汇总已确认订单的明细需求。
2. 汇总结果可按商品合并为需求量 `require_quantity`。
3. 按维度自动生成采购单（或人工确认后生成）。
4. 分配采购员；商品预设了默认供应商 / 采购员的直接带出。

### 5.2 二维码协同

1. 采购单生成专属二维码。
2. 分享给供应商 / 采购员扫码查看任务。
3. 供应商扫码回填单价、重量等实时信息。
4. 信息同步回采购明细，作为收货与核算依据。

### 5.3 多次实重收货

1. 到货后登记收货单：实收数量与**实收重量**、单价。
2. 支持同一采购明细多次收货，累计 `received_quantity`。
3. 每次收货确认后生成**库存入库流水**，由库存业务层更新余额并重算加权平均成本。
4. 全部明细收齐后采购单转为已完成。

## 6. 业务规则与约束

- 收货必须走库存业务层生成入库流水，**禁止直接 UPDATE 库存余额**（遵循 `AGENTS.md`）。
- 重量 `DECIMAL(18,3)` kg，单价 `DECIMAL(18,4)`，金额 `DECIMAL(18,2)`。
- 多次收货的累计量不得超过计划采购量（超收规则待确认 05-02）。
- 收货单价与采购单价不一致时需记录差异并可追溯。
- 采购单取消需处理已收货部分（是否已入库、如何冲销）。
- 二维码走文件服务，禁止硬编码永久公网 URL。
- **收货入库后即生成应付**（09-02 / 05-07 已定，见总览 §13）。
- **G-05 已定**：一期实重**手工录入**，需预留称重设备对接接口，不绑定具体硬件型号（见总览 §13）。
- 供应商回填需鉴权，防止越权查看 / 修改他人采购单。

## 7. 主要接口与页面

- 采购需求汇总：按供应商 / 采购员 / 品类查看待采量
- 采购单列表与详情：明细、收货记录、二维码
- 收货登记：多次收货、实重录入、单价回填
- 供应商协同页：扫码查看任务与回填（移动端）
- 采购差异报表
