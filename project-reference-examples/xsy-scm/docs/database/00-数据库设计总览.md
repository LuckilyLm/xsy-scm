# 00. 数据库设计总览

> 本目录存放 XSY-SCM 的数据库设计（DDL、枚举、字典）。
> 设计依据：`docs/requirement/` 下需求文档 + 已确认业务口径（见 [需求总览 §13 已确认口径](../requirement/00-总览与通用约定.md)）。
> 编码与建模铁律见仓库根目录 `AGENTS.md`。
> 当前范围：**P0 主链路**（商品 / 客户 / 订单 / 采购 / 库存）。

## 1. 环境约定

| 项 | 值 |
| --- | --- |
| 数据库 | MySQL 8 |
| 库名 | `supply_chain` |
| 字符集 / 排序 | `utf8mb4` / `utf8mb4_unicode_ci` |
| 引擎 | InnoDB |
| 时区 | 按项目现状（字段统一 `DATETIME`） |

## 2. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 表 | `t_` + 业务名，全小写下划线 | `t_order`、`t_order_item` |
| 主键 | `{模块}_id`，`BIGINT` | `order_id` |
| 业务编号 | `{模块}_no`，`VARCHAR` | `order_no` |
| 字段 | `snake_case` | `actual_weight` |
| 状态字段 | `status`（明细用 `xxx_status`） | `status`、`pay_status` |
| 普通索引 | `idx_{字段}` | `idx_customer_id` |
| 唯一索引 | `uk_{字段}` | `uk_order_no` |
| 联合索引 | `idx_{字段1}_{字段2}` | `idx_product_sku` |

## 3. 公共字段（每张业务表必备）

```sql
`create_user_id`   BIGINT      DEFAULT NULL COMMENT '创建人ID',
`create_user_name` VARCHAR(30) DEFAULT NULL COMMENT '创建人姓名',
`create_time`      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`update_time`      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
`deleted_flag`     TINYINT     NOT NULL DEFAULT 0 COMMENT '删除状态：0 否，1 是'
```

> **与框架对齐说明**：本项目的 `MybatisPlusFillHandler`（`MetaObjectHandler`）会自动填充 `createTime` / `updateTime`；`createUserId` / `createUserName` 由业务层通过 `SmartRequestUtil` 取当前登录人手动设置。Java 侧 `deletedFlag` 类型为 **`Boolean`**（MySQL `TINYINT`）。因此不使用 `create_by` / `update_by` 命名，保持与 SmartAdmin 现有表一致。

说明（遵循 `AGENTS.md`「数据规则」）：

- 不得使用 MySQL 物理外键，实体关系由业务层维护。
- 除日志类表外，业务表默认**逻辑删除**，不做物理删除。
- 订单、采购、库存流水、退款、配送、财务相关记录**不允许物理删除**，走状态作废 / 冲销。
- 日志 / 流水类表（`t_order_log`、`t_stock_flow`）不设 `deleted_flag`。

## 4. 精度口径（G-02 / G-04 已定）

| 类型 | 字段类型 | 说明 |
| --- | --- | --- |
| 金额 | `DECIMAL(18,2)` | **不含税**；最终金额 `HALF_UP` 四舍五入到分 |
| 单价 / 均价 | `DECIMAL(18,4)` | 中间计算精度，含加权平均成本 |
| 重量 | `DECIMAL(18,3)` | **单位统一 kg**，仅展示层换算 |
| 数量 | `DECIMAL(18,3)` | 非标品按重计量，支持小数 |

- Java 侧一律 `BigDecimal`，禁止 `double` / `float`。
- 中间计算保留 4 位，最终金额保留 2 位（见需求总览 §13）。

## 5. 编号口径（G-01 已定）

业务编号 `{module}_no` 由**编号生成器**生成，格式 `前缀 + yyyyMMdd + 4 位流水`（按日重置）；商品 / 客户编码为 `前缀 + 6 位流水`（不重置）。编号字段一律加**唯一索引**。

前缀速查见 [需求总览 §6](../requirement/00-总览与通用约定.md)：订单 `XSD`、采购 `CGD`、收货 `SHD`、分拣 `FJD`、配送 `PSD`、退款 `TKD`、盘点 `PDD`、报损 `BSD`、报溢 `BYD`、转换 `ZHD`、应收 `YSD`、应付 `YFD`、收款 `SKD`、付款 `FKD`、溯源批次 `PCB`、商品 `SP`、客户 `KH`。

## 6. 状态枚举

所有状态字段使用 `TINYINT`，**取值含义必须写进字段 `COMMENT`**，并与后端 Enum、前端常量保持一致。

完整枚举定义见 [06-状态枚举与字典.md](./06-状态枚举与字典.md)。

### 7.6 主要关系

```text
t_customer ──1:N──> t_order ──1:N──> t_order_item ──N:1──> t_product_sku
                       │                                      ↑
                       │                                   t_product
                       └──1:N──> t_refund                      │
                                                          t_product_price
t_supplier ──1:N──> t_purchase_order ──1:N──> t_purchase_item
                                                   │
                                              t_receive ──> t_stock_flow
t_product_sku ──1:1──> t_stock_balance <── 汇总 ── t_stock_flow
```

- 订单 → 采购：逻辑关联（采购明细记录来源订单需求，靠 `t_purchase_item.require_quantity` 与业务单号追溯）。
- 库存：`t_stock_balance` 由 `t_stock_flow` 推导，**任何模块不得直接 UPDATE 余额**。

## 8. 索引规范

- 所有业务编号 `{module}_no` 建唯一索引 `uk_{module}_no`。
- 外键逻辑字段（如 `customer_id`、`order_id`、`product_id`）建普通索引。
- 高频联合查询（如按商品 + 规格查库存）建联合索引。
- 库存流水按 `product_id` + `sku_id` + `create_time` 建索引，便于按时间查流水。
- 唯一性约束用于防重（如同客户同商品可见性唯一、库存余额同 SKU 唯一）。

## 9. 仓库与批次（G-03 已定）

- **单仓库、不启用批次与保质期**。
- `warehouse_id`（默认 `1`）与 `batch_id` 字段**保留但暂不使用**，为后续扩展预留，避免改表结构。

## 10. 变更管理

- DDL 变更走项目现有 migration 机制，不手工改生产库（遵循 `AGENTS.md`）。
- migration 必须可重复部署且版本有序。
- 状态值新增 / 修改时，必须同步更新：数据库字段注释、后端 Enum、前端常量、API 文档、本文档 [06-状态枚举与字典.md](./06-状态枚举与字典.md)。
