0.3.5新增按商品/按客户两级分拣入口，两条路径复用同一任务、每筐记录和完成状态。缺少skuId/customerId时按原任务隔离，不能按名称误合并。0.3.6按用户要求移除原三张统计卡，原可称重商品列表位于各分拣路径下。

0.3.4新增软件去皮、置零：实机测试启动后，在空秤点击“置零”，放空筐后点击“去皮”，等设备稳定零读数再放商品。发送后隔离旧帧，5秒未见零值提示“结果未确认”并阻止新记录；不自动重发、不在软件里减重或造零。状态和最近20次控制可随结果导出。普通演练默认关闭，隔离自动验证可显式加-EnableScaleControl；正式配置仍默认关闭。66/66本地回归、工作台构建、自包含HTTP冒烟及正常/超时/重复/响应丢失的浏览器验证通过；软件T/Z指令尚未实机验收。

沿用0.3.3按用户要求取消50g倍数限制：在现有1–150kg范围内，稳定净重8.55、8.84、8.86kg等均按原始读数保存和打印，不舍入。铭牌分度仍作为设备资料保留，不作为采集门槛；页面和后台规则一致。计划10kg只是任务目标。继续使用KG和60×40完整记录号标签。0.3.2的9.10kg、10.60kg两张实机标签已由用户确认出纸；新版原始小数路径仍按本版验证记录区分本地自动验证和现场验证。

## 本版可操作的流程

1. 打开任务页，使用平台签发的员工授权引用获取本人任务并领取作业。
2. 选择客户/商品，查看实时净重、计划量、本地累计和每筐记录。
3. 点击“记录本筐并打印”：筐记录、待同步命令和本地凭条同事务落盘；打印失败也保留重量。再次称重前明确点击“已换筐，继续称重”。
4. 多筐精确累计，例如5kg＋4kg＝9kg。点击“完成商品”冻结原有两筐，不取第三次重量、不额外打汇总票。
5. 记录页查看原凭条、打印状态，并填写原因补打。补打复用原重量/时间/记录号，不增加筐数。
6. 有效的已缓存员工授权与已领取作业可断网继续保存/打印。刷新和进程重启保留记录；会话或领取租约过期后只能查历史。

本地待同步凭条需显式配置启用，固定标记“待同步 · 非平台正式单据”。通过Windows已安装的打印驱动绘制中文文本，不假定现场打印机支持TSPL。Windows接受只表示已提交打印队列；执行中断记UNKNOWN，不自动重打，先核对实际出纸再人工补打。演练打印器从不调用系统打印队列。

**当前多筐命令仍为WAITING_CONTRACT，尚未接通深圳后台的多筐上传/完成接口；联网后也不会伪装成同步成功。** 原单次v1客户端仍有配对、任务/领取、单事件重传、平台RAW打印回执，但不用于多筐累计。现平台旧accept会覆盖数量，不能将每筐直接发送到那里。正式员工SSO也没有擅自实现，本版使用已签发的授权引用。

## 直接打开本地演练

解压完整win-x64程序包，双击 `Start-LocalTest.cmd`。同时启动独立厂家HTTP/平台替身与秤端，浏览器打开工作台；控制页 `http://127.0.0.1:33611` 可设置稳定重量和模拟平台断网。结束时双击 `Stop-LocalTest.cmd`，记录会保留。

- 工作台 `http://127.0.0.1:33610`；明确显示“本地演练”，不连接正式平台、不读现场秤、不出纸。
- 独立状态目录 `%LOCALAPPDATA%/XSY/ScaleAgent-Exercise`；现场数据目录与演练目录禁止混用。
- 演练员工引用MOCK-OPERATOR；配对码MOCK-PAIR；演练维护码LOCAL-TEST-MAINTENANCE。这些不是正式凭据。
- 演练任务三项，第一项计划10kg。控制页可依次设置5kg和4kg，检查累计9kg，完成选短少并填原因。
- 已存在同目录实例或端口被占用时拒绝重复启动。只停止脚本自己记录并核对身份的进程，不结束其他应用。
- 重启演练后平台替身的领取状态会重置；本地筐与完成状态保留。需要继续未完成商品或补打时，在线重新领取，未改变的作业/明细版本才可继续。

## 后续现场配置

程序包含60×40mm完整标签模板与实机联动测试入口。将新程序包解压到新目录，先关闭串口助手及旧检查进程，再双击`Start-HardwareTest.cmd`；工作台选择测试任务，空秤软件置零、空筐软件去皮，等待稳定零值后放1–150kg物品，稳定后按原始净重保存，不再要求50g倍数；点击保存才向X7打印明确非业务的测试标签。两筐操作及结果带回方法见随包`HardwareTest-README.txt`。结束双击`Stop-HardwareTest.cmd`，导出程序旁`hardware-workflow/<时间编号>`，不复制密钥/数据库。使用真实串口，但任务和记录保持测试标记，不上传正式平台。

硬件测试独立目录`%LOCALAPPDATA%/XSY/ScaleAgent-HardwareWorkflow`、工作台端口33630、回环测试平台33631；不能与普通演练或正式状态共用。普通`Start-LocalTest.cmd`仍不读真实秤、不出纸。测试标签预览与正式业务标签共享版式，但实机保存打印联动仍须现场验证。长客户/商品等无法完整放入时拒绝打印并保留筐记录，不裁切或默默缩小。

2026-10-20 用户已在秤的 Win10 运行 Agent 0.3.0，只读 COM1/9600/8N1 连续 RS232。三轮检查分别覆盖毛重零→稳定0.40kg→零、实体去皮后NET零→稳定0.08kg→移走筐后-0.28kg、保留空筐NET零→稳定0.10kg→零；原始帧与解析字段一致，无读取错误。用户确认第二轮最后筐也拿走了，负值符合保留皮重，独立皮重字段仍未知。上述小重量只用于读数和状态检查，不能据此宣称计量准确度或正式业务采集合格。

独立实秤检查包将 `Start-ScaleCheck.ps1/cmd`、`Stop-ScaleCheck.ps1/cmd` 放到已有程序目录后，可双击 `Start-ScaleCheck.cmd` 观察60秒；先关闭串口助手释放COM1，按Q可提前结束。结果保存在程序旁 `hardware-check`，不读取正式业务数据，不创建筐或打印。意外关窗后用 `Stop-ScaleCheck.cmd` 回收本检查启动的进程。原0.3.0主程序压缩包保持原校验值，检查包单独交付。

第三轮归档缺少result.json，检查进程结束状态未知，可用Stop-ScaleCheck释放检查进程，无需为此重复称重。称重基础读数、实体去皮与净重回零检查已结束。

用户随后确认标签为60×40mm。独立标签检查包提供 `Print-TestLabel60x40.cmd`，解压到现场程序目录后双击，向X7请求打印一张明确标注测试的中文标签，输出记录在 `printer-check`。Windows接受仅代表提交队列，需以实际纸张确认边框、中文、示例重量及间隙停纸；找不到X7时停止。脚本 `Test-Label60x40.ps1` 不加-Print只生成预览。该检查不读秤、不写业务库，也没有将现有长凭条模板宣称为已适配短标签。

历史现场记录报告单张60×40测试标签已出纸，但原始现场材料未随源码交付。当前源码的连续走纸、正式业务标签、真实称重保存打印联动和平台同步仍需按交付版本重新验收。

计量准确度与正式业务接入仍需验证，参考[交付说明](FIRST-GENERATION-HANDOFF.md)。

复制 `appsettings.Local.example.json` 为程序目录中的 `appsettings.Local.json`，设置真实设备/工作台编码、平台测试地址、协议/端口/厂家本机地址、单位和打印队列；维护码由现场设置非空值。首次启用本地凭条须核对纸宽/高并设置LocalTicketsEnabled=true。配置优先级为appsettings.json → appsettings.Local.json → XSY_环境变量 → 命令行。

双击 `Open-Workstation.cmd` 启动并打开现场模式的本机工作台，默认 `http://127.0.0.1:33600`。设备设置页允许查看串口/打印队列；修改需维护码，落盘后重启统一生效，不热切换作业中的设备。

- SOHE_RS232_V101：13字节连续帧，默认9600/8N1；需确认设备实际协议。
- SOHE_AD：文档未证明净重模式，当前输出UNKNOWN，正式采集会拒绝，不能默认视为净重。
- SOHE_HTTP：仅访问本机厂家服务 `/api/Weight`。HttpUnit必须明确，可信布尔稳定字段需经厂家/实机核实；Code=1不等于稳定。无稳定来源时只显示、不允许采集。
- 默认可记录范围1–150kg，铭牌分度0.05kg只作设备资料，取消分度倍数校验。保留原始小数、未知皮重和原始单位，不舍入或隐式转换销售单位。失联、过期、不稳定、非净重、单位不符或超出范围仍禁用采集。
- 正式配置去皮/置零默认关闭，实机联动测试明确启用，无标定入口。现场系统位数、Win10补丁、浏览器与打印驱动尚需实机核实；当前Windows11验证不代替Win10硬件验收。
- 自包含win-x64包不要求.NET SDK；浏览器、打印驱动需可用。没有自动提权安装、开机自启或生产部署。Install-Autostart.ps1只在现场明确执行时安装当前用户登录任务。

本机API密钥在DataDirectory/local-api-key.txt，由受控集成使用。网页采用同源HttpOnly/SameSite会话和请求头，密钥不写URL/前端。员工授权引用DPAPI加密存储；不存密码/Cookie，不新建本地正式账户。

## 源码构建和验证

Windows开发环境：.NET10 SDK，Node20+；Vue3/TypeScript/Vue Router/Vite/Ant Design Vue、.NET10/SQLite/System.IO.Ports/System.Drawing.Common。界面规范随源码保存在[DESIGN.md](DESIGN.md)，与西安项目根规范同步。

```powershell
# 模块目录；第一次安装依赖，后续可加-SkipInstall
./scripts/Build-Workstation.ps1
./verify.ps1 -DotnetPath 'C:/path/to/dotnet.exe'
# 打包前自动构建工作台；已有刚验证的资源可加-SkipWorkstationBuild
./scripts/Publish-Agent.ps1 -Runtime win-x64 -DotnetPath 'C:/path/to/dotnet.exe'
# 开发模式隔离演练，不自动打开浏览器
./scripts/Start-LocalTest.ps1 -Development -NoBrowser -DotnetPath 'C:/path/to/dotnet.exe' -StateDirectory (Join-Path $env:TEMP 'xsy-scale-agent-demo')
```

工作台浏览器测试在workstation目录执行；需先启动全新的隔离演练，已有记录的演练不适合重跑整条初始流程：

```powershell
$env:XSY_UI_TEST_URL='http://127.0.0.1:33610'
$env:XSY_UI_CONTROL_URL='http://127.0.0.1:33611'
$env:XSY_UI_ARTIFACTS = Join-Path $env:TEMP 'xsy-scale-agent-ui'
npm.cmd test
```

测试使用本地Chrome/Playwright，浏览器全屏窗口，检查1366×768与1024×768布局、离线多筐、响应丢失、补打、权限和外部请求；无Chrome DevTools MCP时的降级已记日志。npm dev是布局开发入口，正式操作及鉴权验证应使用Agent承载的构建产物。

本机接口见[秤端本地接口文档](docs/秤端本地接口文档.md)，SQLite增量说明位于 `docs/db/`。数据、密钥、个人配置和构建输出不入Git；隔离验证与正式平台联调分别记录。

## 升级和数据约束

保持同一Windows用户运行，DPAPI、打印机和缓存属于该用户。升级前停止旧实例，保留DataDirectory和appsettings.Local.json；不删除未同步记录，不同时启动新旧进程。发布脚本按其输出目录规则保留旧构建与版本包。

累计按员工会话＋作业＋任务＋明细隔离，不含平台缓存已分拣量。当前无接班、零筐缺货、作废、更正、重开、价格或库存功能；新增时应由平台定义正式业务规则。补传必须对接真实多筐受理/集合完成契约，不能向旧accept塞累计总量冒充秤读数。

[厂家及平台交接](../docs/sohe-scale-integration-handoff.md)，[第一代秤端交付及深圳接入清单](FIRST-GENERATION-HANDOFF.md)。正式平台接口仍须由双方确认后联调；本模块不依赖个人工作区中的工具目录。
