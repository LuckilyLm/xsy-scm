# 鲜蔬园秤端工作台设计规范

日期：2026-10-16；维护者：Codex。

状态：用户已回复“继续”确认多筐方案，随后明确第一代秤端程序由西安研发、测试后移交深圳，包含秤端操作界面。本文件为该界面的唯一设计约束，不修改深圳平台主题文件。Agent0.2.0仅为已完成的本地基础，并非最终第一代成品。

## 目标与范围

- 服务仓库称重员，在 Win10 触屏上连续完成选任务、称筐、打印、完成商品和异常处理。
- 复用鲜蔬园 Vue 3 / TypeScript / Ant Design Vue 的组件与语义；Windows Agent 提供设备与本地持久化能力。
- 西安在独立秤端模块研发触屏工作台和本地承载，复用平台字段与组件语义，测试后随Agent移交深圳；深圳平台源码只读，不复制平台其他业务模块。
- 参考蔬东坡的操作效率与 design-md-skill 的 airtable 信息组织，不使用其品牌资产或业务代码。

## 视觉与主题

- 默认浅色：白色内容区、浅灰背景、清晰分区；主按钮沿用平台主题蓝色。
- 运行时优先使用已有 `--scm-primary`、`--scm-success`、`--scm-warning`、`--scm-error`、`--scm-text`、`--scm-border`、`--scm-bg-container`。
- 独立离线构建不能缺失主题初始化；没有平台主题快照时采用 Ant Design Vue 默认主题，蓝色 `#1677ff`，成功 `#52c41a`，警告 `#faad14`，错误 `#ff4d4f`，正文 `#1f1f1f`，边框 `#d9d9d9`，背景 `#f5f5f5`。
- 状态必须同时使用文字和色彩，不能只靠红绿区分。
- 字体优先 Microsoft YaHei UI / Microsoft YaHei / Segoe UI / system-ui；不加载在线字体。
- 间距以 8px 为基础；按钮和输入框圆角默认 6px，业务卡片 8px；弱阴影或边框分区。
- 主题 token、通用控件和触屏尺寸 variant 集中维护，不在页面覆盖 `.ant-*` 基础类或重复硬编码基础样式。

## 页面和布局

2026-10-20用户确认的新任务导航（0.3.6修订）：任务首页仅保留按商品分拣、按客户分拣两张可点击入口，移除待称商品/本次可见客户/任务来源三张统计卡。商品入口先选SKU再看该SKU各客户任务；客户入口先选客户再看客户商品，终层复用原可称重商品列表、搜索和领取按钮。均回到相同作业/明细称重，不生成第二套记录。沿用现有蓝白面板、字号与48px触屏目标；入口/分组卡使用明确命名sorting-card样式，搜索/空态/离线提示统一。每个下级（商品选择、客户选择、可称重商品列表、称重作业）均提供明确的“返回上级”按钮，失效页面也可返回；返回固定父级，不依赖浏览器历史。分组页面按钮与刷新并列在页头，称重页位于标题左侧；保留面包屑，刷新保留当前模式与分组。

标签追溯预留：60×40新票保留主要冻结字段，独立二维码位置；无正式URL时只显示待配置文字，不绘制假二维码。旧票按原模板重现，补打不改原关联号/链接。配置后二维码使用HTTPS平台页面，公开内容与正式包装码由平台负责。

1. **任务选择**：只展示已授权任务，提供客户、订单、商品及状态筛选，离线仅展示有效缓存任务。
2. **称重工作台**：顶部为员工、当前客户/商品及设备/网络状态；左侧为任务明细，中间为当前重量与累计，右侧为本商品筐记录；主操作位于重量卡片底部，目标分辨率首屏可触达。
3. **记录与异常**：查看原始筐记录、待同步、冲突、打印失败或未知状态，提供经授权的补打与作废入口。
4. **设备设置/诊断**：串口或厂家 HTTP 配置、打印机、连接状态、软件版本、脱敏诊断；与日常称重主界面分开，仅授权人员可改。

称重页优先适配1024×768和1366×768，不把参考程序尺寸当成实机分辨率。使用workstation-compact布局：1190px以下侧栏收为图标文字窄栏，1024px仍保留三列；980px以下记录区移到第二行，最小视口760px。较窄尺寸允许滚动查看记录，当前重量与主操作优先。

## 触屏规格

- 正文建议 16–18px；客户/商品标题 22–26px；实时重量 56–72px，单位紧邻数值；辅助状态至少 14px。
- 常用触摸目标至少 48px 高，主操作 60–64px 高，按钮间隔至少 12px。
- 当前净重、本商品累计、平台已受理量、本地待同步量分开显示；禁止把当前秤读数当作累计。
- 重量显示使用等宽数字；展示精度服从设备分度与业务单位，不用浮点误差或随意四舍五入掩盖异常。
- 展示目标量、已记录筐数、累计净重和剩余/超出量；剩余为负时明确显示“超出”，不隐藏差额。

## 称重与完成动作

- **记录上传并打印**：冻结当前有效样本，先本地保存；按在线或离线授权流程打印。保存成功后即使打印失败也保持记录，允许处理打印问题。
- **完成商品**：结束当前商品的多筐作业，提交本次筐记录集合与累计；不重新读取当前重量，不重复生成筐记录，默认不额外打印汇总票。
- 样本过期、不稳定、非净重、单位不符、授权失效或正在保存时，禁用对应采集动作并显示具体原因。
- 完成前有未记录读数、未决作废或同步冲突时提示处理；离线完成只能显示“本地已完成、待平台确认”。
- 不根据相同重量自动丢弃不同筐；按钮连点重用同一操作号，保存后明确提示换筐再称。

## 状态、表格与弹窗

- 业务：本地已保存、待同步、平台已受理、被拒绝/冲突、作废申请中、已作废；以最终契约枚举为准。
- 打印：待执行、已提交打印队列、失败、结果未知；只有具备可信硬件回执才显示已物理完成。
- 记录表：筐序号、净重/单位、皮重、时间、业务状态、打印状态、操作；状态未知时显示“未知状态”并禁止不受控动作。
- 有效记录不会因刷新、切换商品或打印失败消失；累计只统计同一商品未作废记录，并区分本地与平台口径。
- 加载、空数据和离线分别有明确文案；网络恢复补传不抢焦点、不清空当前作业。
- 作废、更正、补打及完成弹窗统一标题、字段、校验位置和底部按钮顺序；错误显示在相关动作附近。

## 离线与小票

- 本地工作台资源、必要图标及字体不依赖 CDN；断网刷新或重启后仍可进入已有授权作业。
- 小票冻结客户、商品、任务关联、筐序号、净重/单位、记录号和时间；是否显示价格由平台权限决定。
- 离线打印明确“待同步”，使用已授权模板和可追溯记录号；不把本地记录号冒充平台已确认业务编号。
- 补打保持原重量和记录标识，可标注补打；不新增称重、不触发重复累计。

## 后续验收

- 实现后由本地 AI 检查布局、按钮可触达性、主题一致性、禁用态及错误恢复；浏览器检查按项目规定使用 chrome-devtools。
- 2026-10-16，0.3.0四页工作台已实现；本地Chrome/Playwright验证1366×768与1024×768主操作首屏可达，页面无外部资源/统计请求。Chrome DevTools MCP未提供，按工具降级留痕。平台/实机联调仍暂停。
- 多筐命令WAITING_CONTRACT；未启用本地凭条时WAITING_AUTHORIZATION，显式启用后执行独立LOCAL_PENDING_V1待同步凭条。演练TEST_ONLY明确未出纸，不显示真实平台同步成功或物理打印完成。


## 2026-10-29 确认的市斤与人工录入模式

全部新业务按市斤，实时读数的sj显示斤，历史公斤不换标签。取消软件固定上下限，保留正数及设备可信状态校验。称重卡增加weight-entry-actions区域的“手工录入净重”触屏按钮，独立弹窗显示当前客户、商品、订单、净重（斤）、可选来源说明及确认动作。沿用Ant组件与现有蓝白token，不改主导航或两种分拣路径。

manual-entry命名样式集中在workstation/src/styles.css；数字键盘3列、按钮48px，主输入60px、等宽数字，确认与取消48px。弹窗最多460px宽，1024×768和1366×768确认可触达。输入为已扣皮净重，正数且最多4位小数，不自动舍入。保存后清空草稿；未知结果锁定原请求并允许原号重试，禁用另一次设备/手输记录和完成。人工录入不依赖本机秤连接。

每次录入独立记录，来源在记录页/侧栏/新标签中冻结为电子秤或手工录入；旧来源缺失显示历史记录，不补造。实称与手输共用累计和完成集合；补打不新增重量。设备命令继续有独立的稳定零值确认，不用于人工输入。
