# 需求描述

2026-10-20更新，Codex。Agent 0.3.6 的本机接口供随包工作台及受控集成使用；与集团设备 API v1 草案分开，设备端不提供人工 accept 或库存/订单写入。本次仅调整任务入口与返回导航，接口入出参、鉴权及数据结构沿用0.3.5。

0.3.0保留多筐WAITING_CONTRACT，不经旧单次上报器上传；新增同源工作台会话、受维护码保护的配置、独立本地待同步凭条及补打。未启用本地凭条时仍WAITING_AUTHORIZATION；启用后本地凭条执行状态不代表平台正式票授权。真实多筐受理/完成及正式出票仍待深圳适配。

# 鉴权与通用约定

- `/api/agent/*` 支持X-Agent-Key；首次启动在DataDirectory/local-api-key.txt生成。随包网页不接触密钥：访问根页面时获进程内随机HttpOnly/SameSite=Strict的XSY-Workstation Cookie，并携带X-Workstation-Request: 1。Origin如存在须等于当前http://回环Host，重启后刷新页面重新获得Cookie。无Cookie/请求头且无密钥返回401 LOCAL_UNAUTHORIZED，非法非回环Host返回400。页面不允许iframe嵌入，API不缓存。
- UI会话访问activate还需X-Maintenance-Code；配置保存无论采用哪种本机认证都必须维护码。未设置维护码时维护动作禁用。维护码、本机密钥及设备Bearer不返回页面/日志/URL。
- tasks、events、scale 控制需 `X-Operator-Session`；capture 的 operatorSessionId 在请求中携带，都是集团签发的会话引用，不是员工 Cookie 或密码。
- 多筐全部接口需 `X-Operator-Session`；两个 POST 的头值还必须与请求体 operatorSessionId 相同。会话缺失返回 OPERATOR_SESSION_REQUIRED，不一致返回 OPERATOR_SESSION_MISMATCH。
- 当前任务响应必须带 operatorSessionExpiresAt；缓存按员工会话分开，过期或已知设备被撤销则不得采集。该设计为平台适配草案，实际员工 SSO 仍由集团落实，最终业务授权由服务端重验。
- 跨源默认不开放；若使用平台 HTTPS 页面，需配置明确 LocalAllowedOrigins，前端仍需处理浏览器本机网络策略。SSE 使用带头的 fetch 流，不能把密钥拼入 EventSource URL。
- 筐记录等幂等POST无法确定响应时保留原operationId和整个请求核对。去皮/置零非幂等，只查询status/SSE，不自动重发。
- 采集/任务 ID 使用字符串，不把大整数转换成 JS Number；重量用十进制字符串，禁止靠显示小数位推断实机精度。
- 多筐范围为 operatorSessionId＋jobId＋taskId＋taskItemId；不跨员工会话合并，也不把平台 sortedQuantity 与本地累计相加。当前没有跨会话接班、作废或重开接口。
- 文档示例为 JSONC，实际请求移除注释；任务、采样、会话和 manifestHash 必须替换为当前接口返回值，示例不能作为授权或设备事实。

# 数据模型（请求/响应）

## 采样

| 字段 | 类型 | 含义与空值 |
| --- | --- | --- |
| sampleId | string | 当前设备采样唯一引用；每帧可变化 |
| readingSequence | string | 本进程采样序号；重启可重置，不作业务幂等键 |
| rawWeight | JSON decimal number | 本机实时显示用值，正式上传另以十进制字符串冻结；不得把页面输入当真实采样 |
| rawUnit | string | kg / g / sj；未知单位拒绝 |
| stableFlag | boolean / null | null 表示稳定性未知，不等同 false 或 true |
| stabilitySource | string | 本机 DEVICE_FRAME / DEVICE_HTTP / UNKNOWN；可信设备来源上报映射为草案 DEVICE |
| netGrossFlag | string | NET / GROSS / UNKNOWN；只允许稳定 NET 采集 |
| tareWeight | decimal / null | 设备未提供时为 null，不补 0 |
| capturedAt | 带时区时间 | 采样时间，当前以 UTC 返回 |
| rawFrameHex | string | 串口原始帧十六进制；HTTP 无帧为空字符串 |

## 任务缓存

TaskBatch 包含 operatorSessionExpiresAt 和 tasks。每个任务有 taskId/taskNo/taskVersion/items、jobId/jobVersion/expiresAt/claimedByDeviceCode。expiresAt 为平台作业租约期限，claimedByDeviceCode 为领取设备（未领为 null）。每个明细有 taskItemId/taskItemVersion/productName/specName/saleUnit/plannedQuantity/sortedQuantity/productType/active；0.3.0新增可空customerName/orderNo，平台缺少时显示未提供。0.3.5新增可空字符串skuId/customerId，必须来自平台稳定身份，缺失或空白时按jobId＋taskItemId独立分组，不能凭名称合并；两条导航路径始终使用原业务范围，不合计不同单位。数量和 ID 为字符串，taskItemVersion 为非负整数；这些只读投影不代表可直接完成正式分拣。

## 本机事件状态

`CAPTURED_LOCAL` 已落盘；`UPLOADING` 上传中；`RETRY_WAIT` 等重试；`SERVER_PENDING` 平台已接收（本机不据此推断接受/驳回）；`NEEDS_REVIEW` 不可自动重试。events 返回的数据为本机最近 200 条中当前员工的记录，正式历史应查询集团平台。

## 打印状态

本机执行状态与 ACK 的 status 分开。`ACK_PENDING` 待上传回执；`ACKED_SERVER` 回执获确认；`NEEDS_REVIEW` 平台拒绝回执。ACK status 为 SUBMITTED_TO_SPOOLER / FAILED / UNKNOWN，不由本机自行报告物理 CONFIRMED_PRINTED。每个 printAttemptId 最多执行一次；同 printJobId 的明确授权重印必须产生新 printAttemptId。

## 多筐模型

`BasketRecord`：eventKey、operationId、sampleId 为非空字符串；basketNumber 为当前范围从1开始的整数；measurement为下文完整冻结模型；printIntentId为本地意图ID，**不是**平台printAttemptId。queueState表示本机派发进度：初始WAITING_CONTRACT，平台受理后SENT，可重试失败SYNC_RETRY，平台明确拒绝NEEDS_REVIEW；它不代表平台已确认分拣量。printState在未启用本地票时WAITING_AUTHORIZATION，启用后为QUEUED/SUBMITTING/SUBMITTED_TO_SPOOLER/FAILED/UNKNOWN/TEST_ONLY。未知枚举显示未知状态，不推断成功。不向网页返回串口原始帧、设备凭证或打印租约。

`ItemCompletion` 字段如下，成功完成响应和累计中的 completion 共用该模型：

| 字段 | 类型 | 含义及空值 |
| --- | --- | --- |
| operationId | string | 本次完成操作号，与采集操作号不能重用 |
| jobId / jobVersion | string | 冻结作业标识和版本 |
| taskId / taskItemId | string | 任务及明细 ID |
| taskItemVersion | integer | 非负明细版本 |
| operatorSessionId | string | 平台员工会话引用 |
| eventKeys | string[] | 按筐号排序的完整事件集合，不限当前查询页 |
| totalQuantity / unit | string | 本机计算的精确净重总和及业务单位，不是平台受理量 |
| result | string | NORMAL / SHORT / OUT_OF_STOCK / OVER，需员工选择，不由差额自动推断 |
| reason | string / null | 去除两端空白后的原因，最长 500 字符；非 NORMAL 必填 |
| completedAt | 带时区时间 | 首次本地完成时间，重试/重启不更新 |

`BasketCommand`：sequence 是 SQLite 命令序号（整数，可能不连续）；operationId 是操作幂等号；kind 为 CAPTURE_BASKET / COMPLETE_ITEM；state 表示本机派发进度，取 WAITING_CONTRACT（待发送）/ SYNC_RETRY（可重试失败）/ SENT（平台已受理）/ NEEDS_REVIEW（需人工处理）；eventKey 在采集命令为事件键，完成命令为 null；dependsOnEventKeys 在采集命令为 []，完成命令为全部本筐事件键；createdAt 是本地命令落盘时间。未知枚举按未知状态显示，不自动执行。发送按 sequence 升序，全部采集命令受理后才提交完成命令。

# 接口清单

## 1. GET /health、GET /api/agent/status、GET /api/agent/weight/stream

均无请求体。health 成功 200：`{"status":"running","version":"0.3.4"}`。

status 成功 200：

```jsonc
{
  "deviceCode": "SOHE-STATION-001", // 本机配置的设备编码，尚未配置时为空
  "version": "0.3.4", // Agent 版本
  "deviceAuthorized": false, // 设备凭证是否当前有效，不代表员工有全部权限
  "scaleConnected": false, // 当前是否存在未过期的有效采样
  "error": "SCALE_NOT_CONFIGURED", // 错误码，无错误时为 null
  "reading": null, // 没有有效重量时为 null，绝不能把缺失显示成 0kg
  "control": null, // 本进程未操作过时null，否则为第6节控制模型
  "controlHistory": [] // 本进程最近20次控制的当前状态，初始为空；不包含凭据
}
```

SSE成功200，Content-Type为text/event-stream，每条格式`data: {"reading":...,"error":...,"control":...}\n\n`，新增control与status中同模型，未操作时null，不带controlHistory。断开后前端重新连接，不能把丢帧或缺失读数补为零。不会生成业务事件。status可按需只读轮询（控制等待期250ms一次，通常每秒），无业务幂等副作用；认证失败401，其他异常503，错误体见通用约定。

## 2. POST /api/agent/activate

无业务幂等承诺；一次性配对码已消耗而响应丢失时先查询 status，避免盲目循环配对。

```jsonc
{
  "pairingCode": "由管理员签发的短效配对码" // 必填，非空且不超过 200 字符，不是员工密码
}
```

成功 200：`{"activated":true}`，不返回凭证。设备编码未配置/配对码为空返回 409 INVALID_PAIRING；远程拒绝/网络错误返回 503，已存在队列不删除。

## 3. GET /api/agent/tasks

必填头 `X-Operator-Session`：非空、不超过 160 字符。成功 200：

```jsonc
{
  "cached": false, // true 表示弱网时的本地缓存，信息可能已过期
  "data": {
    "operatorSessionExpiresAt": "2026-10-15T18:00:00+08:00", // 平台授权到期时间；不是本机自行授时
    "tasks": [{
      "taskId": "9007199254740993", // 平台任务 ID，字符串防精度丢失
      "taskNo": "SORT-001", // 平台任务编号
      "taskVersion": "0", // 平台版本引用，不能由本机覆盖
      "jobId": "job-001", // 与分拣任务不同的设备作业标识
      "jobVersion": "3", // 领取后由平台返回的作业版本
      "expiresAt": "2026-10-15T18:00:00+08:00", // 作业租约期限，采集时必须有效
      "claimedByDeviceCode": "SOHE-STATION-001", // 未领取为 null，不能由前端自己填写
      "items": [{
        "taskItemId": "9007199254740994", // 平台明细 ID
        "taskItemVersion": 0, // 明细版本，采集时必须与选择时一致
        "productName": "生菜", // 商品名称
        "specName": "散装", // 商品规格
        "saleUnit": "kg", // 冻结销售单位，必须与设备单位相同
        "plannedQuantity": "5.000", // 计划量
        "sortedQuantity": "0.000", // 平台已分拣量，本机不自行累加成正式量
        "productType": "NON_STANDARD", // 非标品类型
        "active": true, // 当前明细是否活动
        "skuId": "9007199254741001", // 可空字符串；同SKU跨客户共用，不能使用商品名替代
        "customerId": "9007199254741002", // 可空字符串；同名不同客户须不同ID
        "customerName": "测试客户", // 可空客户快照
        "orderNo": "ORDER001" // 可空订单快照

```

空任务返回 tasks=[]。无缓存且断网返回 409 TASK_CACHE_EMPTY；未传会话返回 409 OPERATOR_SESSION_REQUIRED。平台 401/403 等拒绝不降级成缓存成功，以免绕过撤销权限。

## 4. POST /api/agent/captures

此接口只生成本地待上传事件。每个参数必填；taskItemVersion 为非负整数，其余为非空、不超过 160 字符的字符串。不接收手填重量。

```jsonc
{
  "operationId": "e73c6d225d7843d59bb4041614c98e94", // 一次人工采集的幂等编号，超时重试保持不变
  "sampleId": "326f10b92b054e1f858e8b699f13295b", // 从实时读数取得的采样引用
  "taskId": "9007199254740993", // 已缓存且有权限的任务
  "taskItemId": "9007199254740994", // 当前任务非标品明细
  "jobId": "job-001", // 当前已领取的作业
  "jobVersion": "3", // 选择时取得的作业版本，不默默替换为新版本
  "taskItemVersion": 0, // 选择时取得的非负明细版本
  "operatorSessionId": "平台签发的员工会话引用" // 与任务缓存对应，不是员工凭证
}
```

成功 200：

```jsonc
{
  "eventKey": "SOHE-STATION-001:ab278596321a4ace940b139d07f39560", // 本机持久保存的事件键，补传不换键
  "state": "CAPTURED_LOCAL", // 已本地保存，尚不代表正式分拣
  "eventId": null, // 上传获回执后才有平台事件 ID
  "rawWeight": "4.850", // 本次冻结的真实重量字符串
  "rawUnit": "kg", // 真实设备单位
  "capturedAt": "2026-10-15T08:00:00+00:00" // 冻结采样时间
}
```

同 operationId 同请求返回既有记录；同编号更改采样或任务返回 409 OPERATION_CONFLICT。新的一次真实称重即使重量相同也应有新编号。

采集及其重复请求均需当前仍有效的员工缓存、该设备已领取的作业及匹配版本；会话或租约到期后可查 events 核对原记录，不能以幂等重试绕过权限。未领取、租约到期或 jobVersion 不匹配返回 JOB_CONTEXT_STALE；明细版本变化返回 TASK_ITEM_STALE。

采样已过期、最新重量变化/不稳定/毛重/掉线、单位不匹配、低于配置的最小称量/超过量程，均拒绝且不落事件。0.3.3起取消分度倍数校验：默认1–150kg范围内的8.55、8.84、8.86kg等原始稳定净重均可采集，不舍入、不凑成50g倍数。rawValue、netWeight、每筐累计与标签沿用原始十进制重量；divisionKg仅保留为铭牌资料，不改变JSON结构或旧记录。

## 5. GET /api/agent/events、GET /api/agent/prints

events 必传员工会话头，返回数组，每项包含 eventKey/state/eventId/lastError/taskId/taskItemId/rawWeight/rawUnit/capturedAt；eventId 是远程 measurementId 的本地投影名称，没有记录时为 []。prints 返回 printJobId/printAttemptId/printRecordId/state/status/errorCode 数组；不返回 leaseToken 或内容下载地址。

两者不改业务状态、不触发补打。events 的 eventId 缺失为 null，lastError 无错误为 null，不能把 null 显示为成功。prints 的 UNKNOWN 提示人工核查，不自动重试物理输出。

## 6. POST /api/agent/scale/tare、POST /api/agent/scale/zero

人工去皮/置零；无请求体（随包页面可发送空对象{}，无业务参数）。需本机认证和X-Operator-Session有效缓存，设备未暂停，并显式AllowScaleControl=true。需新鲜稳定读数，控制允许毛重或零值，不受商品最小称量限制。请求非幂等，操作员明确点击才发送一次；响应丢失仅查status/SSE，不重试POST。无普通操作员标定或任意串口写入入口。

RS232按厂家单字节T(54)/Z(5A)，不附加CR/LF；串口读、组帧、控制写入共用锁，控制前清缓冲和半帧，写入后flush。HTTP沿用厂家/api/setTare、/api/zero，与采样互斥；HTTP Code=1也不代表执行结果。发送后隔离500ms旧采样，然后观察稳定零值；5秒未观察到则未确认。去皮要求NET零值，置零允许NET/GROSS零值。ZERO_OBSERVED只说明收到随后真实零读数，不是硬件ACK，更不是计量标定结果。

成功200示例（字段在status和SSE中复用）：

```jsonc
{
  "status": "REQUEST_SENT", // 保留既有发送状态，不表示设备执行成功
  "message": "等待设备后续稳定零读数", // 操作员提示
  "control": { // 本次操作观测模型，不是称重业务事件
    "controlId": "a9f4f8db5cee4a10abfe12a0d8e909ea", // 进程内唯一操作ID，查询时需匹配
    "command": "tare", // tare或zero，由请求路径决定
    "state": "WAITING", // SENDING/WAITING/ZERO_OBSERVED/UNCONFIRMED
    "requestedAt": "2026-10-20T07:30:00+00:00", // 开始处理时间，带时区ISO
    "sentAt": "2026-10-20T07:30:00.050+00:00", // 完成发送时间；未完成时null
    "observedAt": null, // 观察到合格零值时间；尚无时null
    "observedSampleId": null, // 合格真实样本ID；尚无时null
    "observedWeight": null, // 合格零值的十进制字符串（观察后通常"0"）；尚无时null
    "observedUnit": null, // 观察后kg/g/sj，尚无时null，不改变设备单位
    "observedMode": null, // 观察后NET/GROSS，尚无时null
    "errorCode": null // 正常等待或零值观测时null；未确认时说明原因
  }
}
```

SENDING为发送中；WAITING为发送完成但等待稳定零值；UNCONFIRMED表示超时、连接异常或发送结果不明，禁止新采集、不自动重发。WAITING和UNCONFIRMED都不能直接使用非零重量记录；已发送操作后续收到合格零帧可转ZERO_OBSERVED。发送是否完成都不确定（sentAt=null）时，偶然零值不解锁，须核对后明确再次操作。ZERO_OBSERVED后仍按原有稳定NET、范围、单位、时效、任务约束采集，不补写未知皮重。

controlHistory按请求先后返回最近20次操作的最新状态（含当前），不是永久审计或状态迁移流水；进程重启清空，已有筐/票不变。没有历史为[]，没有当前操作为null；未知状态客户端保守禁止新采集，重新查询。全部时间UTC ISO，界面按北京时间显示。

失败409示例：

```jsonc
{
  "code": "CONTROL_IN_PROGRESS", // 已有发送中或等待中的操作，未再次写设备
  "message": "正在等待上次操作的设备读数，请勿重复点击" // 核对status，不重放POST
}
```

其他409：CONTROL_DISABLED（开关关闭）、OPERATOR_SESSION_REQUIRED/OPERATOR_SESSION_EXPIRED（员工未授权）、SCALE_DISCONNECTED/SCALE_UNAVAILABLE（失联/陈旧）、WEIGHT_UNACCEPTABLE（不稳定）、INVALID_COMMAND/PROTOCOL_UNSUPPORTED/INVALID_ADDRESS（命令/协议参数非法）、CONTROL_RESULT_UNKNOWN（发送中异常，不可断言未执行）。控制等待时新采集409 CONTROL_IN_PROGRESS；未确认时新采集409 CONTROL_UNCONFIRMED。现有保存操作的幂等核对不生成新采样，仍按原身份权限校验。没有本机认证401，其他不可确定异常503；通用错误体为code/message。

并发操作在SENDING/WAITING拒绝；UNCONFIRMED后只有新鲜稳定帧才可明确再次操作，仍不自动重发。每次人工操作生成新controlId，不用该ID作平台事件键，不新增数据库结构。实机测试启动显式开启，普通演练默认关闭，可加-EnableScaleControl仅在隔离厂家替身验证。正式模式保持配置默认false，现场软件指令仍需在秤Win10上验证。

## 7. 作业详情、领取和释放

`GET /api/agent/jobs/{jobId}`、`POST /api/agent/jobs/{jobId}/claim`、`POST /api/agent/jobs/{jobId}/release` 都需要本机密钥及 X-Operator-Session，无请求体，jobId 是平台发出的非空作业字符串。成功 200 的响应为上面 tasks 数组中的单个 TaskSnapshot（没有额外 data 包装）。领取/释放只根据平台回执更新当前员工缓存，不能本机伪造领取状态。

## 9. GET /api/agent/baskets

用途：分页查询当前员工本商品的筐记录。需两个鉴权头，无请求体；只读且可重复调用。GET 示例：`/api/agent/baskets?jobId=job-001&taskId=9007199254740993&taskItemId=9007199254740994&after=0&limit=50`。

| 查询参数 | 类型 / 必填 | 范围及含义 |
| --- | --- | --- |
| jobId | string / 是 | 非空，不超过 160 字符，当前缓存作业 |
| taskId | string / 是 | 非空，不超过 160 字符，作业对应任务 |
| taskItemId | string / 是 | 非空，不超过 160 字符，该任务的明细 |
| after | integer / 否 | 排他筐号，默认 0，不可负数 |
| limit | integer / 否 | 每页 1～100，默认 50 |

200 返回 `{items: BasketRecord[], nextAfter: integer|null}`；items 每项完整字段同第 8 节，按 basketNumber 升序。nextAfter 非空时原样作为下次 after；末页为 null。空结果：

```jsonc
{
  "items": [], // 当前范围无记录或游标之后无记录
  "nextAfter": null // 已无下一页
}
```

分页没有快照锁定整个浏览过程，新增筐可在后续页出现；**不能用某一页求商品总量**。授权过期仍可读取原会话缓存可见的历史，但不恢复写权限；缓存无此明细返回 409 TASK_ITEM_NOT_VISIBLE。缺少/非法范围返回框架 400 或 409 INVALID_BASKET_SCOPE；分页越界返回 409 INVALID_PAGINATION；其他错误按通用体及状态处理。

## 10. GET /api/agent/basket-summary

用途：查询完整筐累计、平台缓存量、集合摘要及本地完成状态。鉴权和必填查询参数 jobId/taskId/taskItemId 同第 9 节，无分页参数、无请求体；保存后/完成前读取，只读可重复。

成功 200，两筐 5kg＋4kg 示例：

```jsonc
{
  "basketCount": 2, // 当前范围全部已存筐数，不受分页和旧200条诊断限制
  "totalQuantity": "9.000", // decimal精确累计字符串，尾随零不表示额外精度
  "unit": "kg", // 已存筐业务单位；空集合使用当前任务销售单位
  "plannedQuantity": "10.000", // 当前缓存计划量，可能过期
  "platformSnapshotQuantity": "0.000", // 当前平台缓存量，不能与本地9相加
  "manifestHash": "DDA94D109E86590BAC18211555B8CAA555337D1B42EB026BBF97292F7C5874F2", // 示例两条事件键有序集合的摘要；实际使用响应原值
  "authorizationExpired": false, // 授权/租约到期、设备不再持有作业、明细停用或设备暂停时为true
  "locallyCompleted": false, // 只表示本机是否已冻结完成意图
  "completion": null, // 未完成为null，已完成时为完整ItemCompletion
  "queueState": "WAITING_CONTRACT" // 等正式接口，不代表平台受理
}
```

无筐时返回 basketCount=0、totalQuantity="0"、completion=null、locallyCompleted=false；仍有 64 位空集合摘要。摘要由有序事件键数组的本机 WireJson/SHA256 产生，**前端直接引用返回值，不自行拼装**。摘要与累计及完成来自同一数据库读取快照；它防止完成期间漏掉新筐，不是授权令牌。

过期缓存可查且 authorizationExpired=true；范围不可见/格式不合格及内部异常的 HTTP 状态、错误体同第 9 节。已完成后的重新查询不会新增记录或打印。

## 11. GET /api/agent/basket-queue

用途：查询当前范围已落盘命令及完成依赖；需要本机密钥和员工会话，jobId/taskId/taskItemId 同第 9 节。after 是非负 64 位整数命令序号（默认 0）；limit 为 1～100（默认 50）。只读，诊断时调用，不触发上传、完成或打印。

200 为 BasketCommand 数组，按 sequence 升序；以下为完成命令示例，实际另有每筐 CAPTURE_BASKET 命令：

```jsonc
[
  {
    "sequence": 3, // 本机全局命令序号，其他范围的命令可造成跳号
    "operationId": "complete-operation-001", // 完成请求幂等号
    "kind": "COMPLETE_ITEM", // 商品完成意图，不是已执行回执
    "state": "WAITING_CONTRACT", // 本轮没有多筐发送器，保持待对接

      "SOHE-STATION-001:basket-001", // 第1筐，正式契约须先受理
      "SOHE-STATION-001:basket-002" // 第2筐，完整集合不限查询页

    "createdAt": "2026-10-16T04:02:00+00:00" // 原命令落盘时间
  }

```

无记录或页末返回 []；有数据时把最后一项 sequence 作为下一次 after，直至空页，不依赖页长推断完成。序号是本机分页游标，不是平台 ID。采集命令的 eventKey 非空、dependsOnEventKeys=[]。失效授权可查询原会话可见范围；范围、分页、内部错误同第 9 节。

{

# 错误码与错误语义

统一失败体：

```jsonc
{
  "code": "STALE_READING", // 机器可识别错误码
  "message": "重量数据已过期" // 可显示提示，不含凭证或远程原始异常
}
```

- 401 LOCAL_UNAUTHORIZED：本机密钥不正确；不重试业务写入。
- 409：INVALID_CAPTURE、OPERATION_CONFLICT、SCALE_UNAVAILABLE、SAMPLE_CHANGED、STALE_READING、WEIGHT_UNACCEPTABLE、METROLOGY_LIMIT、UNIT_MISMATCH、JOB_CONTEXT_STALE、TASK_ITEM_STALE、OPERATOR_SESSION_EXPIRED 等，提示并刷新或等待人工操作。
- 503：平台失败、超时、设备 I/O 或内部持久化异常，不能当作“肯定没有保存”；采集重试保持原 operationId，先查本机事件。
- 平台返回 DEVICE_UNAUTHORIZED 会暂停同步及新采集，记录保留，需重新授权。
- 请求体格式错误可能由 ASP.NET 返回 400，超过 32KiB 返回 413，前端按 HTTP 状态处理，不假设每个框架拒绝都有统一 JSON。

多筐接口的 409 错误补充如下；统一体例如：

```jsonc
{
  "code": "BASKET_MANIFEST_CHANGED", // 完成前筐集合发生变化
  "message": "称重集合已变化，请刷新累计后重新确认" // 保留原记录，刷新后由员工重新确认
}
```

| 错误码 | 触发及处理 |
| --- | --- |
| OPERATOR_SESSION_REQUIRED / OPERATOR_SESSION_MISMATCH | 缺少员工头或头/体不一致；恢复正确身份后再操作 |
| INVALID_BASKET_SCOPE / TASK_ITEM_NOT_VISIBLE | 范围缺失或不属于当前员工任务缓存；不能通过改参数读取其他员工记录 |
| INVALID_PAGINATION | after负数或limit不在1～100；修正参数 |
| SAMPLE_ALREADY_RECORDED | 同范围同采样另起操作；查询已有筐，不再累计 |
| ITEM_LOCALLY_COMPLETED | 已有完成意图；查询原完成快照，不擅自重开 |
| BASKET_CONTEXT_CHANGED | 新操作与原筐版本/设备/单位上下文冲突；保留历史交平台处理 |
| BASKET_MANIFEST_CHANGED / INVALID_MANIFEST | 集合已变化或摘要格式错误；重新读取累计，不伪造摘要 |
| NO_BASKETS | 无筐不得完成；零筐缺货使用平台业务流程 |
| INVALID_SORTING_RESULT / SORTING_REASON_REQUIRED | 结果枚举不支持或原因缺失/超长；修正后再请求 |
| LEGACY_CAPTURE_EXISTS / BASKET_WORKFLOW_REQUIRED | 旧单次与多筐流程混用被阻止；核对既有事实，不自动搬移 |
| OPERATION_CONFLICT | 操作号已用于不同请求或不同命令；先核对原结果，不能默默改号造成重复 |
| MAINTENANCE_REQUIRED / INVALID_DEVICE_SETUP | 维护码缺失/错误或有限配置字段非法，HTTP409，不重启设备 |
| INVALID_TRACE_TEMPLATE / TRACE_URL_TOO_LONG | 维护保存或采集冻结链接失败，HTTP409；配置合法短HTTPS模板，不生成半条筐记录。若已冻结票异常由打印尝试记FAILED，不自动重打 |
| LOCAL_TICKET_DISABLED / LOCAL_TICKET_NOT_FOUND / INVALID_REPRINT | 未启用本地票、当前范围无原票或补打参数非法，HTTP409，不新增打印尝试 |
| PRINT_IN_PROGRESS / PRINTER_NOT_CONFIGURED | 正在处理已有尝试或现场未设队列；先核对并处理，不能自动连点补打 |
| PRINT_RESULT_UNKNOWN / AGENT_RESTARTED | 打印尝试errorCode，说明执行结果未知；不自动发纸，人工核查后新编号补打 |

- 0.2.0有意限制混用：同会话/作业/任务/明细已有旧单次记录不能改走多筐，反向也拒绝；既有单次流程其余语义保留。工作台需显式接新接口，不能仅升级Agent就获得完整多筐业务。
- 远程前缀：`/scm/device/scale/v1`。当前实现 activate、heartbeat、jobs 分页/详情/claim/release、measurements、print-jobs/pull/claim/ack 与同源内容下载；没有员工 accept、设备解绑管理、Token 刷新和租约续期。人工补打由平台生成新尝试，Agent 不调用 retry。
- 全部发送 X-Request-Id、X-Agent-Version、X-Protocol-Version（下载仅附追踪和设备凭证），非激活请求使用设备 Bearer。成功包装为 code="OK"/"DUPLICATED" + data。HTTP 失败与业务失败分别处理，401 或 DEVICE_UNAUTHORIZED 暂停设备同步。
- measurements 按交接字段 rawValue/businessUnit/weightKind/measurementId 适配；打印按 printJobId/printAttemptId/snapshotChecksum/SUBMITTED_TO_SPOOLER 适配，不采用另造的字段名称。
- 下列响应包装、员工会话和租约字段是基于草案的明确最小投影，**不是已获深圳确认的 OpenAPI**；正式接口冻结后需更新适配和契约测试。

## 远程设备接口适配明细

| 方法与相对路径 | 请求 | 成功 data | 幂等及失败处理 |
| --- | --- | --- | --- |
| POST `/agents/activate` | deviceCode、installationId、pairingCode、protocolVersion、agentVersion 字符串 | accessToken 非空字符串、expiresAt 带时区时间 | 不盲目重试一次性配对；凭证过期需重新授权 |
| POST `/agents/heartbeat` | deviceCode、agentVersion、protocolType、scaleConnected、lastWeightAt、printerConnected、printerQueueAvailable、queueDepth、sentAt | JSON 对象 | 默认约 15 秒；lastWeightAt 可空，printerConnected 固定 null，仅 queueAvailable 表示 Windows 队列可打开 |
| GET `/jobs?limit=100&cursor=...` | X-Operator-Session；cursor 首次省略 | operatorSessionExpiresAt、items:TaskSnapshot[]、nextCursor:string/null | 最多聚合 20 页；游标重复/超限报错，不静默保存截断任务 |
| GET `/jobs/{jobId}` | X-Operator-Session | 单个 TaskSnapshot | 只读，不修改本机缓存授权 |
| POST `/jobs/{jobId}/claim`、`/release` | 员工头；deviceCode、jobVersion 字符串 | 单个完整 TaskSnapshot | 响应作业必须匹配；成功后原子替换缓存中的当前作业 |
| POST `/measurements` | 下例 Measurement | measurementId 字符串、status:PENDING/ACCEPTED/REJECTED，其他接收字段由平台保存 | 同 eventKey 同内容补传；5xx/429/网络退避至约 5 分钟；业务拒绝转 NEEDS_REVIEW |
| GET `/print-jobs/pull?limit=5` | 设备凭证 | items:PrintJob[]、nextCursor:string/null | 当前每轮最多取第一页 5 项；服务端应仅返回可领取待执行项，下一轮再拉 |
| POST `/print-jobs/{printJobId}/claim` | deviceCode、printAttemptId 字符串 | 含租约的完整 PrintJob | 任务和尝试必须与候选匹配；持久化后才进行物理调用 |
| GET `contentUrl` | 同源设备凭证 | 原始二进制，限制 MaxPrintBytes 及整个下载时长 | 禁止跳转/跨源；sha256 摘要不符则不打印 |
| POST `/print-jobs/{printJobId}/ack` | 下例 PrintAck | JSON 对象 | 失败保留原回执；重试不改观察时间/尝试/租约，不再发纸；业务拒绝转 NEEDS_REVIEW |

# 注意事项

- 断网可缓存采集、保存本筐/完成意图，并执行显式启用的本地待同步凭条；不能自动接受或生成平台正式标签。正式分拣结果以员工/平台接受为准。
- 多筐可在有效缓存授权期间断网记录/本地完成并跨重启保留；当前WAITING_CONTRACT不会在联网后自动变成已上传。真实多筐补传及正式票依赖深圳扩展，不能用旧accept覆盖接口代替。本地凭条状态与平台授权完全分开。
- 本机没有作废/更正接口，当前累计包含该范围全部已保存筐。未来加入作废须同步修订有效集合、摘要、总量及完成依赖，不直接删除原始记录。
- 本机时间用于原始采样，服务端还需记录接收时间并校验偏差；UTC 响应在页面按北京时间展示。
- Windows 打印队列可打开不等于物理打印机在线，所以心跳不伪报物理 connected=true。
- 实际设备协议、HTTP 稳定字段、最小称量和标签机语言尚待实机验证；本地测试通过不能代替现场验收。
