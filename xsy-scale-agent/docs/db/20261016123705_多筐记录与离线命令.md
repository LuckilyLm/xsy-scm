# 多筐记录与离线命令增量结构

日期：2026-10-16；执行者：Codex；版本：Agent 0.2.0。

范围：秤端本地 SQLite `DataDirectory/agent.db`，不涉及深圳 PostgreSQL 或平台迁移。来源：`src/Xsy.Scale.Agent/BasketStore.cs` 的 `InitializeBaskets`，在旧表初始化后自动执行。

## 执行顺序及 SQL

```sql
-- 1. 每筐保存不可变事实、原始帧和独立打印意图。
CREATE TABLE IF NOT EXISTS basket_records (
  event_key TEXT PRIMARY KEY,
  operation_id TEXT NOT NULL UNIQUE,
  request_hash TEXT NOT NULL,
  scope_key TEXT NOT NULL,
  basket_number INTEGER NOT NULL,
  sample_id TEXT NOT NULL,
  payload TEXT NOT NULL,
  raw_frame TEXT NOT NULL,
  print_intent_id TEXT NOT NULL UNIQUE,
  print_state TEXT NOT NULL,
  UNIQUE(scope_key,basket_number),
  UNIQUE(scope_key,sample_id)
);

-- 2. 同一会话/作业/明细按筐号读取。
CREATE INDEX IF NOT EXISTS ix_basket_scope
  ON basket_records(scope_key,basket_number);

-- 3. 上传及完成意图独立于旧 events；未冻结正式契约时禁止旧上传器发送。
CREATE TABLE IF NOT EXISTS basket_commands (
  sequence INTEGER PRIMARY KEY AUTOINCREMENT,
  operation_id TEXT NOT NULL UNIQUE,
  scope_key TEXT NOT NULL,
  kind TEXT NOT NULL,
  event_key TEXT,
  request_hash TEXT NOT NULL,
  payload TEXT NOT NULL,
  state TEXT NOT NULL,
  created_at TEXT NOT NULL
);

-- 4. 范围内按命令序号翻页。
CREATE INDEX IF NOT EXISTS ix_basket_command_scope
  ON basket_commands(scope_key,sequence);

-- 5. 一个范围最多只有一个本地完成意图，不允许静默覆盖或重开。
CREATE UNIQUE INDEX IF NOT EXISTS ux_basket_completion
  ON basket_commands(scope_key) WHERE kind='COMPLETE_ITEM';
```

## 字段与事务约束

- scope_key 为 `BasketScope(operatorSessionId,jobId,taskId,taskItemId)` 确定性 JSON 的 SHA256 大写十六进制；不使用会随进程重启变化的 sessionId。
- basket_records.payload 是完整 Measurement；重量字段是十进制字符串，SQLite 不以浮点 SUM 重新计算重量。服务层从所有记录用 C# decimal 精确累计。
- request_hash 校验同一操作的完整请求；operation_id 不允许被不同命令重用。跨旧 events 和新命令表的互斥由单进程门锁和同一存储层检查保护。
- `CAPTURE_BASKET` 命令 payload 保存 BasketRecord；`COMPLETE_ITEM` 保存 ItemCompletion，含完整有序事件集合、总量、版本、结果/原因及原始完成时间。
- 保存一筐时，记录（含打印意图）和 CAPTURE_BASKET 命令在同一 SQLite 事务内提交；命令插入失败会回滚记录，不留下半条成功。
- 完成时在同一门锁/事务内重新读取全量集合、对比 manifestHash 并保存快照；完成操作不新增筐或打印意图。
- basket_commands.state 当前为 `WAITING_CONTRACT`，basket_records.print_state 为 `WAITING_AUTHORIZATION`。本轮没有新队列的远程发送器或打印调度，不把这些状态当成平台正式回执。
- 原始帧本地保留用于诊断，本机多筐 API 不返回该字段；打印意图不是打印授权或实际出纸证据。

## 升级与数据保留

以上均为幂等增量建表/建索引，不删除/改写旧 events、task_cache、settings 或 print_jobs；无需人工执行平台 SQL。已有旧采集记录的同一范围不自动转成多筐，避免混用覆盖与累计语义。

SQLite 沿用 WAL 和 synchronous=FULL。升级前停止 Agent，保留完整数据目录；如在运行时复制数据库，必须使用 SQLite 一致性备份方式，不能只取主 db 丢弃未合并的 WAL。不要通过清空记录解决同步或版本冲突。

无破坏性迁移、回滚删除或自动清理 SQL。将来正式接口/作废规则落地时按增量变更另行记录，未确认前不修改本批历史事实。
