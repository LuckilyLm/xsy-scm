# 第一代秤端交付说明

版本0.3.6。本文描述秤端源码、待接入的正式平台契约及历史验证范围；实际交付版本以仓库提交为准。正式平台代码和秤端接口须由双方按当前版本核对。

## 深圳接入快速开始

交付内容是Windows秤端程序及触屏工作台。源码从本目录 `README.md` 开始阅读；本机接口见 [`docs/秤端本地接口文档.md`](docs/秤端本地接口文档.md)，界面规范见 [`DESIGN.md`](DESIGN.md)。独立模拟平台在 `mock-platform/`，仅用于隔离演练，不代表正式平台接口已接通。

Windows开发机安装.NET10 SDK、Node20+后，在本目录运行：

```powershell
./scripts/Build-Workstation.ps1
./verify.ps1
./scripts/Publish-Agent.ps1 -Runtime win-x64 -SkipWorkstationBuild
# 在publish/win-x64中运行；仅本机模拟，不读真实串口或发纸
Set-Location ./publish/win-x64
./Start-LocalTest.cmd
```

不提交node_modules、bin/obj、dist/wwwroot、发布包、业务SQLite、密钥、个人配置或已取消方案的delete目录。60×40实机测试程序包另行交付；本地环境使用示例配置，正式地址/员工与设备授权由平台提供，不收集员工Cookie。

建议先评审“深圳接手时需要对齐的适配点”表，再共同冻结真实任务/领取/租约、员工与设备鉴权、每筐幂等受理、商品集合完成及依赖顺序补传的请求和响应。西安按确认的测试接口适配秤端并配合实机；深圳负责服务端业务受理/权限/状态。二维码公开查询页和返回字段由深圳设计，目前仅保留链接配置和标签位置。

正式联调的最低验收：真实授权领取任务；两筐分别上传且累计正确；重复请求/响应丢失不重复记账；断网保存打印、恢复后先筐后完成；过期/冲突有明确处理；补打不新增称重记录；平台确认状态可查询。本地待同步记录和演练票不能作为平台已受理证据。

0.3.6任务首页仅两个分拣入口，移除待称商品/本次可见客户/任务来源统计卡。两条分拣路径每层和称重页均提供明确“返回上级”，使用固定父级或原列表returnTo，刷新、直接进入、空态和失效路径均可返回；业务/API/数据库无变更。

本次构建、发布EXE的HTTP冒烟、分拣浏览器完整路径通过；1024×768/1366×768布局已检查，返回按钮唯一且至少48px，8.84＋8.86两筐仍累计17.70kg、完成状态跨入口共享。全部为本地隔离验证，不含实机或正式平台联调；未重跑无变化的C#及软件控制专项。

## 深圳接手时需要对齐的适配点

| 项目 | 当前实现与接入位置 | 需要平台提供的真实能力 |
| --- | --- | --- |
| 员工身份 | WorkstationService与工作台授权弹窗，仅保存平台签发引用 | 员工SSO/权限、设备绑定、会话过期与续期；不收员工Cookie |
| 任务与领取 | PlatformClient、TaskBatch/TaskSnapshot/TaskItem | jobs列表/详情/claim/release正式响应及版本/租约；客户订单字段 |
| 每筐受理 | BasketStore的CAPTURE_BASKET命令，eventKey/operationId去重 | 独立每筐事件事实、幂等受理与查询，不能覆盖前筐 |
| 商品完成 | COMPLETE_ITEM保存有序eventKeys、manifestHash、累计及结果 | 校验依赖集合后正式完成、重复请求查询、冲突处理 |
| 离线补传 | 本机筐/完成依赖已持久保存，未派发 | 按原键重传、先每筐后完成、拒绝/过期冲突的服务端契约 |
| 实时重量 | 本机SSE约250ms更新，不逐帧记账 | 若后台要实时跳动数值，另设只读通道和限频；不能假作每筐记录 |
| 纸票 | 本地LOCAL_PENDING_V1待同步凭条，明确非平台正式单据 | 业务正式票据编号/模板/离线授权及与本地票的关联；当前不擅自发正式票 |

平台缺失接口作为清晰的适配差异移交，不阻止本地程序开发；也不在西安改写平台后端或绕过员工正式接受。正式同步实现后应追加幂等、乱序、响应丢失、断网和业务冲突回归。

## 恢复现场联调后的顺序

1. 保留现场数据，先只读检查Win10位数/补丁、触屏分辨率、COM口、厂家辅助程序、打印机驱动与纸张。
2. 确定RS232、AD或HTTP中哪一个才是该设备实际通路。核对真实砝码/秤显示、单位、净毛重、皮重及稳定来源；不操作标定。
3. 接集团测试环境真实员工与任务；对齐上述接口后验证每筐与完成的真实同步，不使用正式业务数据库试造数据。
4. 单独核实物理出纸、纸张/中文长文本、断电中断及人工补打，再安排Win10完整验收。

用户已恢复实机检查，下一步按HardwareTest-README完成两筐联动并带回结果。正式平台联调仍未完成；测试模式不能冒充正式员工授权或业务确认。
