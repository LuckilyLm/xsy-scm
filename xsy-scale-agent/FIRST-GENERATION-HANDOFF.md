## 当前实现与接入重点

| 对象 | 当前源码 | 接入核对点 |
| --- | --- | --- |
| 员工与设备 | 平台签发授权引用、设备配对、领取/释放与缓存租约 | 真实权限、设备仓库、指派人、过期与续期，不收集员工 Cookie |
| 每筐上传 | `PlatformClient.UploadBasket` → `/measurements`，固定 eventKey、operationId、筐号与任务版本 | 重复请求、响应丢失、多商品、版本和单位；不覆盖前筐，不上传累计冒充单次读数 |
| 商品完成 | `/items/{taskItemId}/complete`，摘要取有序 eventKeys | 全部依赖先受理；平台重算总量、结果/原因及旧上下文冲突 |
| 队列恢复 | `SyncWorker` 处理初始 WAITING_CONTRACT，可转 SENT、SYNC_RETRY、NEEDS_REVIEW | 断网、恢复顺序、明确拒绝人工处理；本地保存不冒充平台受理 |
| 市斤与人工净重 | 同单位别名原数值；手输本地保存 MANUAL、说明和非设备采样语义 | 当前平台上传载荷未见 entrySource/entryNote，须核对持久化与接受策略；不能假作稳定设备读数 |
| 打印选择 | 每条 true/false/null，false 不建票；未知结果原号原选择重试 | 只上传不出纸、无票不能补打，打印异常不丢重量 |
| 正式包装标签 | 平台发码，返回包装码/批次/公开链接；本地凭条另行保留 | 本地 eventKey 不冒充 unitCode；冻结来源字段与批次字段各自独立，补打不改原快照 |

## 现场验收顺序

1. 保留现场数据，只读核对 Windows 位数/补丁、运行用户、COM/波特率、厂家辅助程序、连续输出、市斤、NET/稳定状态、打印机与纸型。不操作设备标定。
2. 用明确的硬件测试模式检查真实连续读重、空秤置零、空筐去皮、稳定零值、正净重原值保存。控制未知不自动重试，不以缓存旧重量放行。
3. 对齐测试环境的员工、设备、仓库、班次和领取租约；验证两筐、跨商品、实称与手输混合、重复点击/响应丢失不重复计重。
4. 验证断网本地保存、重启、恢复后先每筐再完成，明确区分待同步、受理、重试与人工复核；完成的 eventKeys/摘要与平台一致。
5. 单独验证 60×40 标签长文本、二维码、连续走纸、打印中断 UNKNOWN、人工补打不新增重量，以及只上传不出纸。
6. 联合后台核对实发量、分拣完成、送货单、发车库存与签收应收。平台正式包装标签还须查平台码及公开白名单，不能由本地凭条倒推出完整追溯闭环。

记录所用源码/安装包版本、设备/打印机、数据范围、步骤、平台回执和实际纸张结果。旧版单张样张、模拟平台或驱动受理都不替代当前组合验收。测试结果保存在对应验证记录中。

## 升级与数据保护

先停止旧包并导出，再将完整新包解压到新目录；同一 Windows 用户运行，保留本地配置、SQLite、未同步命令和旧公斤票快照。FIELD、LOCAL_TEST、HARDWARE_TEST 数据隔离，不清空队列或为测试重置现场记录，不自动安装自启或更改打印机全局配置。

真实多筐接口已有源码；实际环境是否部署兼容版本、手工来源是否完整传递、真实 Win10/电子秤/打印机是否通过，仍须按上表逐项确认。源码实现不能替代目标环境受理与现场验收。
