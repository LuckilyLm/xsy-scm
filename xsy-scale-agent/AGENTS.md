# Windows 秤端 Agent 协作规则

本目录是独立的 Windows 秤端服务与触屏工作台。正式 SCM 业务、身份和权限以仓库根目录的 `AGENTS.md`、`docs/decisions.md` 及平台接口为准；本地程序不建立第二套订单、库存、分拣或财务状态机。

## 当前能力边界

- 工作台首页只有“按商品分拣”和“按客户分拣”两个入口。任务列表、空态、失效页和称重页都提供确定的上级返回路径；返回按钮至少 48px，不依赖浏览器历史。
- 每筐重量、员工/作业/明细身份、事件键、打印快照与待同步命令由本机持久化。重复操作按原键核对，不重复计重；商品完成只确认已记录的筐集合。
- 正式平台的多筐受理、集合完成和公开追溯接口仍待对接。`WAITING_CONTRACT` 表示未同步成功；不能把旧单次 `accept` 接口当作多筐协议。
- 正式采集要求稳定净重、有效授权与租约、正确单位和默认 1–150kg 范围。保留设备原始小数，不按铭牌分度自动舍入，也不凭本地重量推断库存或结算。
- 软件去皮/置零使用厂家 T/Z 单字节命令，不自动重发。发送后等待设备稳定零值；结果未确认时阻止新采集，不能本地伪造零值或皮重。
- 本地凭条与平台正式单据分开。打印执行前保留冻结内容；驱动结果为 `SUBMITTED_TO_SPOOLER` 只表示已提交队列，执行状态未知时不自动补打。二维码仅使用明确配置的公开 HTTPS 模板，默认不生成公开链接。

## 模式、配置与交付

- 普通本地演练使用隔离状态目录、模拟任务和 `TEST_ONLY` 打印器，不读取现场秤或发送真实打印任务。硬件测试须显式开启并与正式状态目录分离。
- `appsettings.Local.json`、密钥、SQLite、员工授权引用、测试导出、构建产物和发布包不进入 Git。示例配置保持空密钥与占位平台地址。
- 正式程序升级前停止旧实例，保留数据目录与个人配置；未同步记录不能因更新程序被删除。
- 可共享的接口说明在 `docs/秤端本地接口文档.md`；部署与待接入范围见 `README.md`、`FIRST-GENERATION-HANDOFF.md`。不要引用仅个人电脑可访问的日志作为团队验收结论。
- 测试、构建、服务启动和实机操作遵循仓库根规则及用户授权。源码交付、隔离演练、设备出纸和正式平台验收应分别报告。
